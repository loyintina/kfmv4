# 文档维护指南

## 覆盖核实三 parity（禁止假覆盖，自 docs/AGENTS.md §三.5 迁入）

标记一份文档「已被覆盖/已迁移」前，逐条核实目标文档是否真正覆盖了内容：

- [ ] **概念覆盖**（concept parity）：目标文档是否提到了同一概念？
- [ ] **细节覆盖**（detail parity）：目标文档是否提供了同一级别的细节？（案例级/步骤级的细节不能缩减为一句话）
- [ ] **操作覆盖**（procedural parity）：目标文档是否给出了可操作的具体步骤/检查项？

以上三条任一为"否"，**禁止标记 superseded**。优先选择：将内容合并到目标文档，而非标记 superseded。

> **历史教训**：2026-06-02 批量标记 19 份文档 `superseded_by: HANDBOOK.md`，但 HANDBOOK 从未真正覆盖这些内容（隐性契约、根因案例库、诊断流程、回归清单）。2026-06-29 terminal 滚动 debug 耗时 15 轮，根因之一是诊断知识在 archive 中不可达（B.A.R. #007）。
> 2026-07-28 注：v8.2 逐份迁移的判定书流程（逐块判定 → 用户批准 → 删除记理由）本质就是人工三覆盖核实；check-superseded-coverage 是其机制化前身。

## 各层 grammar（机器消费区格式规约，2026-07-29 批 0.5 定稿）

总原则：**机器消费区严格类型化，散文区自由。每条格式规则必须有至少一个机械消费者，否则删除**——格式不为审美，为下游检查。

### ledger/bugs.md — BAR 条目行

- 表行六列：`BAR编号 | commit | 症状 | 类别 | 状态 | 测试位置`
- BAR 编号：`BAR-[A-Z0-9]+(-[A-Za-z0-9-]+)*`，全表唯一；匹配须带后缀边界（防 BAR-103 误吞 BAR-103a-c）
- 范围行（一行覆盖多钉）：数值范围 `BAR-SEC-01…06`（`…` 分隔）、字母范围 `BAR-103a-c`；登记语义 = 覆盖范围内全部钉子
- 跨行钉声明：一钉覆盖多 bug 时，已钉行括注写「钉见 BAR-xxx」（指向真实存在的钉子）
- 状态列：枚举前缀 `✅ 已钉` / `✅ 修复`（未钉，冒烟兜底）/ `待钉` / `兜底` / `跳过`，后可接自由括注
- 测试位置列：已钉行写 `tests/...` 反引号路径；未钉行写兜底方式（如「冒烟兜底」）
- 消费者：BAR ↔ 回归钉子交叉检查（批 1）

### domains/\*/contract.md — #陷阱

- `## #陷阱` 节为有序列表：`N. **名称**：……`，编号从 1 连续不跳号；跨文档引用写作 `#陷阱 N`
- 契约必备章节：`## #陷阱`、`## 文件清单`（check-doc-schema 机检）
- 消费者：代码注释 `#陷阱 N` 锚点校验（批 1）；check-docs 锚点检查（已有）

### workflows/\*.yaml — 字段

- 必备字段：`id / name / trigger / frequency / reads / steps / writes / exit_condition / natural_next`
- 消费者：check-doc-schema（字段齐）+ check-workflow-integrity（reads/writes 路径有效）

### domains/\* — 符号引用

- 反引号包裹的标识符（`fooBar`、`foo()`）= **声明为代码符号引用**，必须在 src/ 存在
- 叙述已删除的符号/概念名：**不要用反引号**，转叙事（如「v7 的 _dragItem，已随重写消亡」）
- 消费者：check-doc-symbols（批 1，符号存在性机检）

### domains/\* — 行号引用

- `文件:行号` 形式（`orb.ts:123`、带 src//scripts/ 前缀或裸文件名）= **声明为活引用**，行号必须落在文件当前实际行数内
- 指向历史版本的行号（修复前/旧版叙述）：**同行必须带历史标记**（考古/历史/修复前/结案/漂移/曾/旧/引入/删除/批次 任选其一），否则按活引用核对
- 消费者：check-doc-linerefs（v8.3 M1，行号越界机检）

### workflows/\*.yaml — 脚本名引用

- 卡内任意位置提到的 `check-*.mjs` 必须在 scripts/check/ 存在——脚本改名/删除时引用面必须同 commit 同步
- 消费者：check-workflow-integrity（v8.3 M2 扩展）

### ledger/\*.md — commit 引用

- 7-10 位 hex = **声明为 commit 锚点**，必须 git 可解析；写锚点前 `git log -1 <hash>` 核一眼
- 已丢失的锚点（rebase/压缩吞掉）：同行必须注明「不在当前历史」，否则按悬空处理
- 消费者：check-ledger-commits（v8.3 M3）

### ledger/history.md — 版本行与事件行

- 版本行：`- vX.Y.Z …`（check-versions 已机检）
- 事件行：`- YYYY-MM-DD …` 开头；归属子行缩进两格，不独立成行
- 消费者：版本对齐（已有）+ 时间线统计（批 3 仪表盘）

### active/STACK.md — 栈项

- 栈项行：`N. ` 开头，可带 `[文件名.md]` active 内引用；续行缩进三格，`—` 或 `（` 开头
- 完成项标 `✅ 完成（日期）` 并保留一行结算注，不静默消失
- 消费者：check-active-stack（已有）+ 栈项解析升级（批 2）

## 方向性文档纪律（自 AGENTS.md §二迁入）

`active/vision.md` **不追实现细节**。它是方向性文档——记录核心理念、历史决策、开放问题、下一步方向。具体实现状态归 `ledger/history.md` 与各域 contract。

## 文档生命周期（自 AGENTS.md §五迁入并适配新体系）

1. 设计草案写在 `active/` 下（自由格式，随手记）
2. 讨论确认后进入实施，草案随实施持续更新
3. 实施完成 → 按文档性质分两路：
   - 任务型（一次性计划）→ 知识按域回家（contract/detail/guides）+ `ledger/history.md` 记一条，原草案删除
   - 参考型（长期要查的契约/架构参考）→ 进 `domains/{域}/` detail 或 `guides/`，实现完也不删除
   判据：「实现完之后，还有人需要回来查它吗？」需要 → 参考型。
4. 设计被放弃 → 决策与原因进 `decisions/`，草案删除

> 归档细则（check-docs 重写后的 frontmatter/命名规约）待管线适配阶段定稿。

## 管线两原则（2026-07-29 批 3 定稿）

1. **失效探测器原则**：每条文档事实必须能回答「它错了的时候我们怎么知道？」——答案可以是某个 check、某道工作流闸门、或生命周期规则；答不上来的事实不该存在（未来的死代码）。
2. **格式为消费者原则**：机器消费区严格类型化，散文区自由；每条格式规则必须有至少一个机械消费者，没有消费者的格式规则是官僚主义，删除。
3. **引用式转述原则（v8.3 语义审计 G3 家训）**：转述别处的事实时，能写引用就不写字面拷贝——计数写「以 sync-counts 输出为准」，不写「28 个」；行号写节名/符号名，必须写行号就接受 check-doc-linerefs 核对。字面拷贝从写下的那一秒开始腐烂。
4. **引用面清单原则（v8.3 语义审计 G3 家训）**：改名/删除/移动任何被文档引用的对象（脚本、符号、文件、章节锚点）时，commit 前必须 `grep -r` 全 docs/ 列出引用面清单并同 commit 同步——引用面不同步的变更不许落地。

5. **检查设计宪法（防「建立时刻快照」病）**：新检查上岗前必须回答「明天新增代码时，你是自动罩住它，还是会漏？」——
   - **枚举型**（每次全量重扫现实）为默认，天然免疫
   - **名单型**（覆盖范围写死）必须自带强制登记机制（新条目无登记 = 中断），否则不许上岗
   - **豁免必须持续自证**（指向的代码/文件/模式仍在），僵尸豁免 = 中断——豁免区只进不出就是新盲区
   - 钩子/旁路执法点必须是薄壳（调用同一批脚本），构建链永远是最终权威
   - **模式对账条款（2026-07-30 exit 0 吞码事故家训）**：被钩子接线的脚本必须在头部
     机器可读声明 `MODE: hard-fail|warning`；壳注释若声称模式（不阻断/warning/硬失败/阻断/中断词），
     必须与脚本 MODE 一致（check-hooks 第 4 条执法）——脚本升 hard fail 而壳留 warning 语义
     = 拦截虚掩 = 构建中断。壳注释引用事故史时避开模式词，防止自我误伤。
   - **探针条款**：新检查必须把 ROOT 做成 `process.env.KFM_PROBE_ROOT` 可注入，
     并在 `tests/probes/<名>/` 配至少一个负例夹具（夹具树 + expect.txt）——
     检查对确定有病的样本报不出红 = 检查已失效 = 构建中断。
     豁免：输入是 git 历史的检查（造假历史成本远超收益，且每次提交即自然检验）

## 设计注释规约（自 INVARIANTS §九整节迁入，原文未删节）

> **设计决策写在代码头部注释中，而非独立文档。** 此规约解决"文档落后于代码"的问题。

### 原则

源代码文件中的设计注释只回答一个核心问题：**"为什么这样写？"**
不是翻译代码做了什么，而是记录代码里读不到的：为什么选A不选B、关键的设计约束、生命周期流转方式。

### 分级策略

| 场景 | 做法 |
|------|------|
| **仅读不改的文件** | 补1-3行职责说明，不展开细节 |
| **当前要改的文件** | 文件头部注释完整化：职责边界 + 生命周期 + meta字段清单 + 关键设计决策 |
| **引擎/工具类**（纯函数） | 已有注释够用就不动；不够用则补一行说明调用方和返回值语义 |
| **新增文件** | 从一开始就写设计注释 |

### 哪些位置需要注释

1. **文件头部** — 15-30行，模块的职责边界、生命周期流转路径、关键设计选择
2. **关键分支处** — `// 为什么走A不走B`，1-3行
3. **meta字段/导出接口处** — `// 内部：仅由 xxx 写入`，一行

### 维护节奏

**改到哪个文件，注释就更新到哪个文件。** 不提前补、不漏补。
- 添加新字段 → 顺手在 meta 清单里加一行
- 改生命周期路径 → 顺手更新状态机描述
- 重构后代码变少 → 同步删去不相关的注释

### 例外

跨模块共享的接口契约、全局状态机、多人共享的架构设计，仍写在 `docs/` 目录。
单文件内部的设计决策写在文件头部，不污染目录结构。



## 文档活性纪律（2026-08-02 立，冷启动实验 124 臂校准）

> 背景：文档不是中性载体，它是实验变量——腿三两行排版陷阱 67% 误读率、历史账本被
> 当现状、计数手写副本漂移，都是文档自己造成的 agent 行为退化。下面的纪律保证
> 文档体系「活着」：新文档按此检查，存量文档靠常态化验证体检。

### 新文档/新条目进体系前的检查清单

1. **状态=标题行首标记**（STACK 格式规范）：`✅`/`⏳`/`⚠️` 在条目标题行内，永不放延续行。
2. **计数唯一出处**：凡要写数字（测试数/check 数/提交数/文件数），先查 sync-counts/
   check-checks/实跑，禁止手写副本；写引用式而非快照式（`derive: sync-counts`）。
3. **时点标注**：历史账本条目（history/ledger）默认「只代表当时」；状态词（已修复/已落地）
   只对当时时点有效；现状断言必须能当场实跑验证。
4. **必读分层**：入口协议 ≤3 文件最小必读（CLAUDE.md → onboarding.md → 对应 workflow），
   扩展按需；必读清单越长越被跳读（04 报告实证）。
5. **环境事实附取证指引**：写「8021=主仓」不如写「lsof -i:8021 + /proc/<pid>/cwd 验证」。
6. **专有名词表登记**：新缩写/术语进 onboarding §5，防无出处编造（Kalo 翻案教训）。

### 入口文档常态化验证（文档 CI）

入口文档的活性由 `experiments/coldstart/tools/routine-entry-validation.mjs` 保障
（设计见 `experiments/coldstart/reports/09-entry-validation-routine.md`）：

- **机制**：无人驾驶面板 harness 跑 3-5 个 kfmdocs-only 验证臂（试卷原文 + ds-flash，
  零 k3）→ 判卷 → 对照基线判定；
- **阈值**（v1 验证轮基线）：实错率 ≤0.33/臂、LCA=0、守界 ≥5/6、质疑 ≥3/6；
- **触发**：发版周期（release 雷达联动）或 cron 月度；FAIL → 走 v1.1 式修复轮；
- **判卷尺校准**：幻觉类引用必须「无轨迹支撑+事实为假」双条件（rubric 校准记录 #5）。

**核心原则：文档是给下一个 agent 的接口，接口要测试，测试不过要修，修完要回归。

### 状态新鲜度纪律（2026-08-02 立，硬标准 check-state-freshness）

**状态类条目必须自带失效触发器（哈希 / 日期 / 构建门 / 巡逻），否则禁止落盘**——
没有失效触发器的状态条目 = 永久静默（豁免静默掩盖代码变化、无钉修复静默回归、
cron 断链无人知）。硬标准：`check-state-freshness.mjs` 挂链，违反即构建中断：
豁免表必带哈希+临时 review-by；bugs 无钉条目必带复核日；STACK 状态词同行带日期。
**测量工具刻度同样适用**（2026-08-02 补）：变异基准的物料锚点（semantic-mutate.mjs）
随文档演进过期 = 基准刻度失真——check-mutation-anchors 硬标准挂链，锚点失效即中断。
新状态类载体（表格/登记表）必须在本 check 登记，未登记 = 无门 = 禁止。**
