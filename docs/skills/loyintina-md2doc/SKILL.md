# Loyintina 公文格式转换（MD → DOCX）

## 工具与路径

- **转换工具**：`/root/.local/bin/md2doc`
- **默认输出目录**：`/root/箱子/落灰的termux/md2doc公文格式转换/成品/`
- **源码与历史归档**：`/root/00-Loyintina/40-库/06-技术与工程/50-办公自动化/md转公文格式docx/`
- **中转站说明**：`/root/箱子/落灰的termux/md2doc公文格式转换/README.md`

## 公文层级符号规则

md2doc 只认 `###` / `####` / `#####` 三级符号，其余按正文处理：

| Markdown | 对应排版 | 字体/字号 | 段落格式 |
|---|---|---|---|
| `### 标题` | 主标题 | 方正小标宋简体 22pt | 居中，段后 10pt |
| `#### 一级标题` | 一级小标题 | 黑体 16pt | 首行缩进 32pt |
| `##### 二级标题` | 二级小标题 | 楷体_GB2312 16pt | 首行缩进 32pt |
| 无符号行 | 正文 | 仿宋_GB2312 16pt | 首行缩进 32pt，行距 28.95pt |

页脚自动加页码：底端居右 `- 1 -`。

## 标准流程

### 1. 接收原始内容

用户可能给：

- 一段纯文本（无层级符号）；
- 一段已有 `#` / `##` / `###` 等 Markdown 标题的文本；
- 一个 `.md` 文件路径。

### 2. 审计并补全层级符号

**核心原则**：确保最终喂给 md2doc 的内容只有 `###` / `####` / `#####` 这三级符号，且与内容层级匹配。

具体做法：

1. **读取原始内容**，识别内容结构（主标题、大段、小节、段落）；
2. **清洗现有符号**：
   - `# 标题` → `### 标题`
   - `## 标题` → `#### 标题`
   - `### 标题` 保持不变
   - `#### 标题` → `##### 标题`
   - `##### 标题` 保持不变
   - 更深的 `######+` 视为正文或按上下文降一级；
3. **无符号时自动补**：
   - 全文最顶层的标题 → `###`
   - 其下第一大段主题 → `####`
   - 再细分的小主题 → `#####`
4. **符号冲突时以内容语义为准**，不要硬套固定深度。

### 3. 调用 md2doc

#### 方式 A：文件输入（推荐）

先把审计后的内容写到临时 `.md`：

```bash
md2doc /tmp/审计后.md
```

如未指定输出，自动落到 `/root/箱子/落灰的termux/md2doc公文格式转换/成品/<标题>.docx`。

#### 方式 B：管道输入

```bash
cat <<'EOF' | md2doc -c
### 关于某某工作的通知

#### 一、总体要求

各级单位要高度重视，切实加强组织领导。

##### （一）提高站位

深入贯彻落实上级决策部署。

##### （二）压实责任

明确责任分工，确保任务落地。

#### 二、工作安排

按照时间节点有序推进。
EOF
```

#### 方式 C：显式指定输出

```bash
md2doc /tmp/审计后.md /root/00-Loyintina/40-库/40-语言与传播/10-写作/99-归档项目/50-docx原稿库/某文件.docx
```

### 4. 验证输出

- 检查 `✅ 转换成功:` 后面的路径；
- `ls -lh /root/箱子/落灰的termux/md2doc公文格式转换/成品/` 确认文件存在；
- 如可用，用 `file` 或 `unzip -l` 简单验证 DOCX 结构。

## 典型调用示例

```bash
# 用户说：把下面这段话转成公文
# agent 先做审计补符号，写入 /tmp/待转.md，再：
md2doc /tmp/待转.md

# 预期输出：
# ✅ 转换成功: /root/箱子/落灰的termux/md2doc公文格式转换/成品/关于某某工作的通知.docx
```

## 与 vault 同步的关系

`/root/箱子/` **不在 vault / git 同步范围内**。默认落点的 DOCX 不会自动回到手机或 Git。

如果需要回手机/Git，转换完成后**主动移动**到 `/root/00-Loyintina/` 下的合适位置，例如：

```bash
mv /root/箱子/落灰的termux/md2doc公文格式转换/成品/某文件.docx \
   /root/00-Loyintina/40-库/40-语言与传播/10-写作/99-归档项目/50-docx原稿库/
```

## 常见错误

- **报错 `ModuleNotFoundError: No module named 'docx'`**：说明环境没有 `python-docx`，需 `pip install python-docx`；
- **输出字体显示异常**：服务器端没有安装「方正小标宋简体」「楷体_GB2312」「仿宋_GB2312」等 Windows 字体，这是已知限制；
- **标题提取失败**：如果内容里没有 `###`，默认用输入文件名作为 DOCX 文件名。

## 验收

- 输出单一 DOCX 文件；
- 内容层级符号与原文语义一致；
- 文件落到默认中转站或用户指定的 vault 路径；
- 转换命令返回 0 并打印成功信息。
