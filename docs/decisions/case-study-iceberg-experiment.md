# 案例研究：冰山工作量验证实验（2026-07-30）

## 假设（心法 34 庙算优先）

质量工作量守恒：feat 前不付讨论/设计成本，feat 后加倍付 fix 链。
可检验形式：**feat 落地前有设计文档沉淀的，后续 fix 链更短。**

## 尺子（口径，先修尺再量物）

| 概念 | 操作定义 |
|---|---|
| feat / fix | 提交 subject 匹配 `^feat(\(|:)` / `^fix(\(|:)` |
| fix 链 | 某 feat 之后、到下一个 feat 或 tag 之间的 fix 提交数 |
| 前置讨论 | 该 feat 之前 30 个提交窗口内有「设计类 docs 提交」（`^docs` 且 subject 含 设计/方案/SPEC/立项/锁定/设计稿） |

复现：`node scripts/agent/exp-iceberg.mjs`（`--json` 出明细）。

### 已知测量边界（诚实记录）

- **fix 归属是近邻代理**——窗口内的 fix 可能修的是更早的 feat，归因有噪声。该噪声对两组对称，不制造方向性偏差，但压低效应量。
- **「无前置讨论」=「无 docs 沉淀」**——对话里的讨论只有沉淀成 docs 提交才进仓库，探测不到的部分会被错分到「无讨论」组（使两组差异被低估）。
- **相关性非因果**——feat 规模、讨论质量未控制。

## 数据

样本：1787 提交，feat 339、fix 800（全局比 2.36 fix/feat）、设计类 docs 43、tag 51。

| 组 | n | 平均 fix 链 | 中位 | 厚尾（链≥5） |
|---|---|---|---|---|
| 有前置设计沉淀 | 158 | **1.58** | 0 | 20（12.7%） |
| 无前置设计沉淀 | 181 | **2.58** | 1 | 38（21.0%） |

置换检验（mean 差，10000 次洗牌，双侧）：**p = 0.0043**。

时代混杂控制（以 v7.0.0 为界，各自重算，方向一致）：

| 时代 | 有讨论 | 无讨论 |
|---|---|---|
| pre-v7 | n=94，avg 1.94 | n=114，avg 2.68 |
| post-v7 | n=64，avg 1.06 | n=67，avg 2.40 |

厚尾明细（链≥5 的 58 条 feat）见 `--json` 输出；典型长链：
fc1745f 调试面板（链 21，无沉淀）、7c35ba8 输入参数流式（链 17，无沉淀）、
dd39ed4 设置卡（链 14，**有沉淀**——讨论不是免死金牌）。

## 结论

- 假设方向被数据支持：有设计沉淀的 feat 平均 fix 链缩短 **39%**（2.58→1.58），厚尾率近腰斩（21%→12.7%），p≈0.004，且两个时代内方向一致（排除「早期项目混乱」混杂）。
- 效应是**降均值、斩厚尾**，不是归零——有沉淀仍有 20 条链≥5（讨论质量维度未被本实验测量）。
- 与心法 34 的边界条款互证：沉淀必须落成文档才算数（「无 docs 沉淀」组的对话讨论救不了它）。

## 衍生用途

- 厚尾明细表 = 天然的「下一个溯源考古候选清单」（链≥10 且当时无沉淀的 feat，是机制缺口的富矿）。
- 本实验是三条新心法的首次联合实战：庙算（选题）→ 测量（口径先行+边界诚实）→ 实验（置换检验+时代控制，不空谈）。
