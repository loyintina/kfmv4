## 心法原则（18 条）

来源：`docs/KFM_V4_INVARIANTS.md` §一

> 每条原则标注了适用范围层级：
> - **[LEVEL 1]** — **不可违反**。违反就是 bug。没有权衡余地。
> - **[LEVEL 2]** — **需要权衡**。可能在特定场景下与同层级其他原则冲突。
> - **[LEVEL 3]** — **流程建议**。推荐遵循，可在注释中说明后跳过。

### 组1：理解偏差

| # | 原则 | 一句话摘要 | LEVEL |
|---|------|-----------|-------|
| 1 | 先问"为什么"，再问"改哪里" | 找到根因，不修症状 | 1 |
| 2 | 从源头上简化，不是在输出端增加 | 数据模型只存不可简化的原始信息 | 2 |

## 关键约定速查

- `_` 前缀 = 模块内私有
- `L.renderer` 等通过 `renderer-lifecycle.ts` 单例访问
- `(as any)` **零逃逸**（白名单已清空，`check-as-any.mjs` 扫描）
- `Box.data` 必须通过 `getFileRowData()` 守卫访问
- 所有 GSAP 调用通过 `animation-registry.ts`，禁止直接 `import gsap`
- overlay 元数据用 `(as Box & OverlayMeta)` 类型访问
- 向 `ts` 加 tween 的函数，必须在 `ts.call` 回调里 `ts.clear()`
- 动画中 `_stateSub` 不会触发 `rebuildTree`（`L.isAnimating` 守卫）
- `crypto.randomUUID()` → 用 `_uuid()` 替代（兼容旧浏览器）
- 所有卡片内容通过 `buildCardLayout()` 统一骨架

## 设计注释规约（v2026-07-03）

> **设计决策写在代码头部注释中，而非独立文档。** 此规约解决"文档落后于代码"的问题。

### 原则

源代码文件中的设计注释只回答一个核心问题：**"为什么这样写？"**\
不是翻译代码做了什么，而是记录代码里读不到的：为什么选A不选B、关键的设计约束、生命周期流转方式。

### 分级策略

| 场景 | 做法 |
|------|------|
| **仅读不改的文件** | 补1-3行职责说明，不展开细节 |
| **当前要改的文件** | 文件头部注释完整化：职责边界 + 生命周期 + meta字段清单 + 关键设计决策 |
| **引擎/工具类**（纯函数） | 已有注释够用就不动；不够用则补一行说明调用方和返回值语义 |
| **新增文件** | 从一开始就写设计注释 |

### 哪些位置需要注释

1. **文件头部** — 15-30行，模块的职责边界、生命周期流转路径、关键设计选择
2. **关键分支处** — `// 为什么走A不走B`，1-3行
3. **meta字段/导出接口处** — `// 内部：仅由 xxx 写入`，一行

### 维护节奏

**改到哪个文件，注释就更新到哪个文件。** 不提前补、不漏补。
- 添加新字段 → 顺手在 meta 清单里加一行
- 改生命周期路径 → 顺手更新状态机描述
- 重构后代码变少 → 同步删去不相关的注释

### 例外

跨模块共享的接口契约、全局状态机、多人共享的架构设计，仍写在 `docs/` 目录。
单文件内部的设计决策写在文件头部，不污染目录结构。
