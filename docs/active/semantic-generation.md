# 语义生成（semantic generation）——语义单源 + 生成呈现

> 2026-08-02 立（用户动议：固定用自己的话描述、自己定语义，生成可读文档——
> 看起来像手写，完全是机器生成，跟动态眼睛系统同构）。
> 归属：8.5 度量衡（统一度量衡的语义版）设计方向。

## 0. 一句话

**任何能从单一活源头推导出的文档内容，都由生成器产出，而不是手写——**
包括自然语言散文段落。读者看不出是生成的，但内容永远不可能旧。

## 1. 与既有机制的同构

| 机制 | 模式 | 尺度 |
|------|------|------|
| 动态眼睛（page-state） | 实时状态 → 注入提示词 | 会话级（每轮动态） |
| 语义生成（本文） | 实时事实 → 生成文档段落 | 文档级（构建时/按需） |
| sync-counts / gen-code-inventory | 计数/清单 → 回写文档 | 字段级（已落地） |

同一个哲学的两个尺度：**呈现永远从源头现场生成，不存副本。**

## 2. 可生成 vs 不可生成的边界（升档判定法）

写任何文档内容前问一句：**「这句话能从一个活源头推导出来吗？」**

| 可生成（单一出处、可枚举） | 不可生成（需要判断、叙事） |
|---|---|
| 计数（测试数/check 数/提交数） | 决策理由（为什么选 A） |
| 清单（文件清单/路由表/工具表/域归属） | 判例（bug 根因/豁免理由） |
| 状态（版本/HEAD/服务状态/构建时间） | STACK 条目（工作栈判断） |
| 契约的清单节/计数节 | ADR 叙事 |
| 交叉引用（路由表 ↔ 工作流文件） | 设计讨论 |

**能 → 生成器；不能 → 手写。** 这就是三档阶梯（消灭 > 编译 > 检查）的句级版本。

## 3. 生成器规范

1. **生成区标记**：生成内容包在 `<!-- gen:xxx 自动生成，禁止手改 -->` ... `<!-- /gen:xxx -->` 内
   （沿用 contract 的 chain:auto 约定，泛化）；
2. **单一出处**：生成器只读活源头（代码/配置/文件系统/账本），不读其他生成区；
3. **幂等可重跑**：同源头生成同结果（`--check-only` 验证漂移，未同步 = 构建中断，
   同 sync-counts 模式）；
4. **人写区与生成区不重叠**：同一文件里生成区与人写区并存，人只维护判断部分。

## 4. 制度化（8.5 度量衡方向）

1. **可生成事实登记表**：盘点全系统可生成事实 → 登记（新增可生成事实必须登记，
   同状态新鲜度载体套路）；
2. **生成器群**：每个登记项一个生成器，统一规范（标记/出处/幂等/check-only）；
3. **纪律**（doc-maintenance §文档活性纪律增补）：**写文档前先问「这是可生成的事实吗？」**
   是 → 生成器；否 → 手写；边界含糊 → 讨论（不可生成默认）；
4. **未来：按需生成（动态文档）**——像眼睛一样，读时现场生成状态段落（真·动态文档）。

## 5. 与现有生成器的关系

- sync-counts（计数）、gen-code-inventory（清单）、chain:auto（链节）是**字段级生成**的落地；
- 本文把生成从「字段」扩展到「段落/散文」——模板 + 实时值拼装自然语言；
- 最终形态：文档 = 「人写判断 + 机器写事实」的混合体，人只管需要判断的部分。

## 6. 风险与边界

- 生成区样式雷同（模板腔）——可接受：一致性优于文风，且生成区占比低；
- 模板维护成本——每个生成器是一份模板，登记表管着，不失控；
- 不可生成的误判——边界含糊时按「不可生成」默认（保守，判断留人）；
- 与 STACK 格式规范（状态=标题行首）的交互——生成区同样遵守文档格式规范。
