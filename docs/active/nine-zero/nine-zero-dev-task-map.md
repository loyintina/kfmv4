## 读法

- **层间箭头只向下**：上层依赖下层，开发自底向上；文档世界线（工坊）与代码
  世界线（运行时）**并行**，互不阻塞；
- 迁移法（绞杀者两步走）贯穿全图：数据管道换心 → 搬进新容器；每步带
  功能一致对照表 + 保留性考题；**576 测试基线不许降**；
- 全景图与本文档的分工：图看结构，本文档派活。图的内容 = 本文档 L0–L3 +
  文档世界机制层；
- **实现来源列**（2026-08-17 卡萝增补）：自研 / dsh拿来 / dsh参考 / 接口对齐——
  逐项对照见 `nine-zero-dsh-sourcing.md`；dsh 资产按契约优先 + 移动端指标两关取材。
- **验收口径**：L0–L3 与文档世界线不单列验收列，以对应契约『考题』（A/B/C
  三档）为准；步 0 与迁移验证线单列验收。
- **版本策略**（2026-08-17 用户拍板）：`8.x.y` 小版本串行——`8.x` 是主题、
  `8.x.y` 是主题内小步；每版完整可运行，全部做完发 9.0 收口；逐版受
  「迁移验证线」五道闸保护（见下）。

## 版本策略（v4：8.x.y 小版本进度标记 + 9.0 一次性收口）

> 不走 release 流程；全部小步完成并实拍通过后一次性发 `v9.0.0`。
> 触发背景：小步串行下逐版发版（tag/部署/注记）成本高且价值低，9.0 是
> 唯一有意义的发布单元。v3 的 2026-08-17 拍板历史保留于下（只追加不删改）。

> 不在 kfmv4 内绞杀——**另立外置纯代码项目 `kfm-nz`**（kfmv4 不动、不冻结、
> 不并行维护，老房子照住；nz 内只放代码，不建新文档系统——kfmv4 的
> `docs/active/nine-zero/` 设计文档即 nz 规格书，工坊线在 kfmv4 文档世界
> 照旧）；nz 开独立端口，从 Cordis 根总线起步，一个插件一个插件做/移植，

> 替换即删旧等"kfmv4 内部收编"类设计作废登记。工坊线 D1–D6 整体推迟
> （见下节），29 步小步预排改写为 nz 插件实现/移植顺序。

**版本号语义**：

- `8.x` = 一类主题（例如 8.8 = 终端/tmux 主题）；
- `8.x.y` = 该主题内的一个可运行、可验收、可回滚的小步（**进度标记，
  v4 起不发版**——编号只出现在文档/任务图，不升 package.json）；
- 每个小步都是完整可用的咖啡猫；一个主题的全部小步完成并通过实拍后，该主题闭环；
- `9.0` = 收口：v8 退役、旧代码删除、宪法全面接管，**一次性发版 v9.0.0**。

## dsh 插件兼容面（远期立项，2026-08-17 用户拍板登记）

**定位**：kfmv4 作为 Cordis 宿主，具备承接 dsh 插件的能力——三层递进：

1. **Cordis 层（天然兼容，已白送）**：只依赖 `ctx`/事件/注册表的 Cordis 插件，
   9.0 直接可装——采用裁决的隐藏红利；
2. **服务层（服务名映射）**：依赖 dsh 服务（`systemPrompt`/`webServer`/`session`
   等）的插件需同名服务或适配器——**依赖取材清单的接口对齐做实**（agent-service/
   session-store 对齐 dsh 服务面 = 兼容面的地基）；
3. **转化器（轻量工具，非运行时）**：读 dsh 插件 cordis.yml 组成 + inject 声明
   → 生成 kfmv4 组成 + 服务映射表（dsh 服务名 → kfmv4 服务名/适配器状态）。

**第一个实验对象**：`dsh-routing-suite`（已装于 dsh 环境，2026-08-17；只依赖
systemPrompt + webServer，小且干净、已审计）——agent-service 落地后验证
"一行 patch 搬进 kfmv4"，成了就写转化器规范。

**边界**：依赖 dsh 深层服务（agent-loop 内部/session schema）的插件转化成本高，
v1 只承诺轻服务插件；双向兼容不是目标——kfmv4 是 Cordis 的另一个宿主，
转化器搬能力，不跑 dsh。

**触发条件**：agent-service 落地（8.11）后验证实验 → 状态：🌙 远期（9.x）。

## NA 协同路径与 Rust 共享内核（2026-08-18 用户拍板）

**关系式**：9.0 契约出规格（接口/语义/考题）→ Rust crate 出内核实现（host 中立，
不属于任何一端）→ **kfmv4 编 WASM / NA 编原生，两端各自包壳**（kfmv4 壳=TS 插件
注册进 Cordis；NA 壳=cordis-na 插件）。cordis-rs 归 NA 线（已有 crates/cordis-na
基座）。NA 的主机层（渲染/UI/APK 打包/手势）主题对齐我们、粒度节奏自定——共享
crate 覆盖的部分直接白拿，不重走 8.7→9.0。

**分层判据**（2026-08-18 修订：用户指出"两端都需要"对 TS 侧不成立——NA 全 Rust，
计算内核天然 Rust，"要不要 Rust 化"只是 TS 侧的问题）：

- **共享 crate（两端同源）**：边界薄（buffer 进/状态出）· 计算重 · 两端都需要——
  三条全要；
- **kfmv4 专有 WASM 内核（不问 NA）**：边界薄 · 计算重 · 浏览器有性能痛点——NA
  是终端 APK，天然没有编辑器/预览类场景，这类内核 TS 侧单边成立；
- **管线方向**：TS 工坊先行试错定语义 → 稳定后沉淀 Rust crate → NA 收编稳定版
  （NA 下游定位，Rust 化判断天然滞后于功能落地，不作前置）。

**终端芯定案**：alacritty_terminal（NA 已生产实证：首个终端提交即用，APK 真机在跑；
调查证伪了"终端库只能自研"的说法——NA 自研的是渲染壳，闪退根因在 GPU 驱动与
dex/.so 打包层，与终端解析无关）。kfmv4 WASM 侧同 crate 优先，rio-vt 备选（官方
wasm32 支持），评估动作挂在 8.8.1 前。

**Rust 共享内核清单**（资源均已核真）：

| 共享内核 | 对应 9.0 任务（版本） | 现成 Rust 资源 | 取材方式 |
|---------|---------------------|---------------|---------|
| 终端解析核 | №1 终端卡（8.8） | **alacritty_terminal**（定案）；rio-vt 备选 | 直接拿来 |
| PTY 管理 | 终端连接家族（8.8，仅 NA 侧；kfmv4 的 PTY 在 Node 服务端不共享） | portable-pty（wezterm 抽出） | NA 拿来 |
| token 计量 | agent-service / 压缩挂点（8.11） | tiktoken-rs（Zed 在用） | 拿来 |
| 压缩修剪核 | 压缩挂点（8.11） | 薄自研（规则逻辑简单）+ tiktoken-rs 计量 | 自研薄核 |
| diff | 文件编辑卡跟随同步（8.10） | similar（候选） | 拿来改 |
| 文件树过滤 | tree-data 千级过滤（8.10） | ignore / globset（ripgrep 系，候选） | 拿来改 |
| 权限策略裁决核 | 安全包（影子 8.7，转正后评估） | cedar-policy（AWS 官方，可形式化分析；可能过重，影子期先薄自研） | 远期评估 |
| session 存储格式 | session-store（8.11） | 共享 JSONL schema 即可；NA 侧 rusqlite，浏览器侧续用 dsh TS 件（WASM sqlite 复杂度不划算） | 只共享格式 |
| 账本 hash 链 | ledger-service（8.11） | sha2 + serde 薄自研 | 共享格式 |

**共享 crate 接口冻结点**：每个共享 crate 定一个接口冻结版本；任何一侧要改接口，
必须走评审/通报；两端各留一个兼容性冒烟测试，确保同一 crate 在 WASM 与原生侧行为一致。

**kfmv4 专有 WASM 内核候选**（NA 无此场景，单边成立；均为"先 TS 稳定、后 WASM 沉淀"）：

| 内核 | 对应 9.0 任务（版本） | 现成 Rust 资源 | 触发条件 |
|------|---------------------|---------------|---------|
| Markdown 渲染核 | 文件编辑卡预览 / 对话卡消息（8.10/8.11） | pulldown-cmark / comrak（候选） | 手机端大 md 渲染实测掉帧才立项 |
| 语法高亮核 | 文件编辑卡代码态（8.10） | syntect（候选） | 同上，实测痛点驱动 |
| 大文件 diff | 编辑卡外部改动跟随（8.10） | similar（与共享清单同行，可先单边落地） | 跟随同步实测卡顿才立项 |

判据纪律：专有内核一律**实测痛点驱动**——TS 实现先跑，手机上测出性能问题才
WASM 化；不许预防性 Rust 化（边界税 + 调试成本是确定支出，收益必须实测在先）。

**dsh 拿来件的 Rust 化评估**（2026-08-18 用户提议：先 TS 搬 → 功能考题过 →
按分层判据评估 Rust 化——顺序入档）：

| dsh 拿来件 | Rust 化结论 | 理由 |
|-----------|------------|------|
| compaction 家族（pruner/spill/摘要） | **够格**（8.11.2/8.11.3 已入小步备注） | 边界薄（字符串进出）+ 大上下文计算重；计量=tiktoken-rs，修剪规则薄自研 |
| session-persistence/projection | 不 Rust 化，只共享 JSONL 格式 | IO 密集、计算量≈0，WASM 化纯付边界税 |
| todo | 不 Rust 化 | 增删改查状态件，无计算 |
| context 注入族（time/session-reference/tmux） | 不 Rust 化 | 字符串拼接胶水 |

**明确不 Rust 化**（DOM/编排类，WASM 边界税纯亏）：全部卡片渲染壳 · 渲染宿主 ·
手势分发 · broker · 布局 · 启动器 · 皮肤 · 动画 · 眼睛/手 · 命令系统 UI。

## kfm-plugtest 热插拔自测工具（初稿，2026-08-18）

> 目标：让 kfmv4 自己（或 AI agent）验证插件可插拔、可降级、无残留，把“可插拔”
> 从设计原则变成可机检机制。

### 形态

- **8.7.6 最小版**：headless 自测服务/脚本，直接操作 Cordis 注册表与 broker；
- **8.11.2 转正**：注册为 tool-host 工具，AI 可调用；
- 同时支持 CI 模式（构建/测试跑）与 headless 模式。

### 输入

| 参数 | 类型 | 说明 |
|------|------|------|
| action | string | `list` / `test` / `test-one` / `disable-simulate` |
| plugin? | string | 目标插件/卡/服务 id；`test-one` 必填 |
| scope? | string | `all` / `core` / `card` / `service`；默认 `card+service`，不含内核 |
| reload? | boolean | 默认 true；卸载后是否重新加载验证恢复 |
| danger? | boolean | 允许测试内核件；默认 false |

### 输出

统一 JSON：

```json
{
  "ok": true,
  "summary": { "total": 0, "passed": 0, "failed": 0 },
  "results": [
    {
      "id": "card-terminal",
      "load": true,
      "unload": true,
      "reload": true,
      "domLeak": false,
      "eventLeak": false,
      "serviceLeak": false,
      "errors": []
    }
  ],
  "missingSimulation": {
    "plugin": "eyes",
    "degraded": true,
    "recovered": true,
    "errors": []
  }
}
```

### 错误码

| 码 | 含义 |
|----|------|
| PLUGTEST_OK | 全部通过 |
| PLUGTEST_UNLOAD_FAIL | 卸载失败（disposer 抛错/未完全回滚） |
| PLUGTEST_LEAK_DOM | 卸载后 DOM 容器/节点残留 |
| PLUGTEST_LEAK_EVENT | 卸载后事件订阅/监听未清 |
| PLUGTEST_LEAK_SERVICE | 卸载后服务/注册表仍可解析 |
| PLUGTEST_DEGRADE_CRASH | 模拟缺失时系统崩溃而非降级 |
| PLUGTEST_RECOVER_FAIL | 放回/重载后未恢复 |
| PLUGTEST_UNKNOWN_PLUGIN | 目标插件不存在 |

### 权限

- riskClass：`exec`（会变更运行时插件状态，不是只读）；
- 默认禁止测试内核件（ctx/渲染宿主/手势/broker）；`danger=true` 才允许；
- 生产会话默认 ask/deny；CI/headless 可按配置自动放行；
- 每次 unload/reload 写 ledger-service `ns=plugtest` 审计。

### 纪律

- 串行执行，禁止并发卸载；
- 发射类效果只验证“停止”，不验证“撤销”；
- 每个 8.x.y 小步闭环时，对涉及的新插件跑一次 `test-one`，把结果写进发布注记。
