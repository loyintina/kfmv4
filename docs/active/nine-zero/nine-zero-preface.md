## 已拍板结论

### 议题 1：渲染底座是内核还是插件？（2026-08-15 拍板）

**结论：不整体插件化，分层——「能画东西」在内核，「怎么布局」是插件。**

| 层 | 归属 | 内容 | 理由 |
|----|------|------|------|
| 渲染宿主 | **内核** | DOM 容器、事件总线、最薄生命周期（"有一块画布"） | 性能热路径不被间接化；启动不需等布局插件 |
| 布局引擎 | **插件** | 浮卡工作台、tmux 窗口管理器、标签页、手机单列、headless | 收益最大点：换布局=换插件；headless=AI 无头自测 |
| 动画/手势 | **半插件** | 动画引擎可替换（GSAP 是一种实现）；手势分发在内核 | 手势决定"输入如何进组件"，是基座；动画是策略 |

> 修订注（2026-08-16 用户拍板）：动画从「半插件」升级为**整体插件化**方向——
> 整个项目的交互动画将收编为一个动画插件；组件 v1 核心**零动画**（交互瞬时
> 生效），动画由动画插件后挂。首个兑现：契约 №7 文件树卡（v8 的双树
> overlay 动画/字符雨不迁移，归动画插件）。手势分发在内核不变。

**依据**（讨论要点存档）：
- 收益：布局可替换（tmux 管理器=布局插件）；无头运行（AI 自更新可自测）；
  动画/手势策略可换；与论文彻底对齐（渲染=效果、渲染依赖=coeffect）。
- 代价：接口稳定性压力陡增（渲染接口是所有组件地基）；热路径性能（kfmv4
  热路径是 UI 渲染，与 dsh 的工具调用不同）；性能契约履约难度（60fps 保证
  要从代码内聚改为接口契约）；启动链路变长。
- 对齐：论文 §6.2 服务多路复用（渲染底座=broker，布局插件=提供者）；
  dsh 结构（基座只留 ctx，渲染形态由 bundle 决定）。

### 议题 3：状态与持久化放哪（2026-08-15 拍板）

**结论：三状态归属表——登记类逆序摘、发射类不撤、数据归数据管理器（服务）。**

| 类型 | 例子 | 归谁 | 卸载时 |
|------|------|------|--------|
| 登记类（=获取类） | 订阅、手势、服务注册 | 插件挂到基座 | **逆序摘干净**（契约考题） |
| 发射类 | 像素、网络请求、终端字节 | 扔出去收不回 | 不承诺撤销，摘容器即完 |
| 数据 | 会话、配置、池条目 | 数据管理器（服务） | 与插件无关，毫发无损 |

- **插件只持私有草稿**（滚动位置、在途动画——别的插件不关心、卸载没人
  心疼的），草稿随卸载蒸发；共享的、活得比插件久的、要落盘的状态全归
  服务层（= NA 规格书 §4.1 状态存活规则的 web 表述）；
- **发射类边界**（用户拍板）：像素 = 发射类，卸载 = 摘 DOM 容器，不承诺
  "恢复屏幕原样"；回滚承诺只覆盖登记/获取类；
- **哲学对应**（茉莉指出）：本表是宪法第四条「真相源/投影分离」在插件层
  的展开——数据是真相源归服务，投影（像素/订阅）随插件生灭。每个插件
  契约须显式标注自己属于哪一类。

### 原则：服务即插件（2026-08-15 拍板）

系统里只有内核 ctx 不可插拔；**服务与卡片同为插件，仅 provide 内容不同**
（卡 provide 界面能力，服务 provide 数据能力）。服务插件卸载须满足：
relied 守卫（有依赖者禁卸）+ serialize 交班（热替换，复用契约 №1 渲染器
serialize/restore 模式）或账本在盘（真卸载）。内存里重建不起来的状态
不许存在。

### 契约模板：对齐 NA 规格书 §8（2026-08-15 拍板；评审高 1/高 2 + 茉莉增补）

每份插件/组件契约九字段：身份 / 提供（标注注册表式 vs 有序链）/ 依赖 /
生命周期语义 / 配置 schema / 事件（**逐事件标注派发模式**）/ 状态存活 /
契约测试清单 / 实拍判卷点。

kfmv4 本地增补与定调：

- **apply/unload 两栏不得缺栏**（茉莉）：apply 注册清单 + unload 逆序
  回滚清单；「无效果注册」是合法答案，缺栏非法——从结构上堵「忘回滚」；
- **卸载三相**（对齐 §4.3）：停供 → 依赖者排空 → LIFO disposers；
  dispose take-once（二次调用报错，契约测试强制）；
- **卸载判据 = 观察等价**（对齐 §5）：卸载后经由 ctx 可观察行为与加载前
  不可区分；断言范围只含登记/获取类；
- **事件派发集 v1**（与 NA v1.1 同步基座同构）：emit（同步观察）/
  serial+bail 合一（同步顺序短路）/ waterfall（委托链）；parallel 缓建。
- **插件包（bundle）是正式形态**（2026-08-16，契约 №5 首立）：插件两种
  形态——单插件（自包含，如手）与插件包（总插件 + 供稿段，如眼睛/池卡）；
  四规矩见契约 №5。

### 9.0 验收哲学（2026-08-15，茉莉原话，用户确认）

> 验收标准不是"多少东西可插拔"，而是**"不用的东西能不能干净地消失，
> 需要的东西能不能随时召唤"**。

**抽文件测试**（2026-08-16 用户拍板，判据化）：随机抽掉/禁用任何一个**插件**
文件——系统启动正常、其余功能正常、依赖者降级挂起（PENDING）不崩溃、
放回后自动恢复。成立三要件：依赖未齐=合法挂起（非错误）/ 数据不在插件里
（零数据损失）/ 单插件隔离（失败不传染）。边界：内核 ctx 不在此列（目标
是压到最小，不是可换）；「正常」= 降级运转（缺眼睛 AI 失明但工具循环照跑）。
平时由互操作测试的变异抽检覆盖。这也是 AI 运行时自更新的安全地基：
换坏任何文件，放回去即自动降级恢复。

> 修订注（2026-08-16，评审进度评审 §二）：**执行形态两式**——
> ① 变异抽检形态（删文件 → 重构建 → 跑互操作测试 → 断言降级挂起不崩溃），
> 自动化测试操作，对应 NA 规格书 §5 互操作变异抽检；② 配置禁用形态
> （disabled 位 → 不装载），配置级启停。**恢复时态 = 重构建/重启后恢复**
> （kfmv4 插件为构建期扫描注册，v1 不承诺运行中热恢复——与 NA 规格书
> v1.1 热插拔承诺边界一致）；末句「AI 运行时自更新的安全地基」是**远期
> 愿景**（动态 import / HMR 时代），非 v1 承诺，防误读为运行中热插拔。

#### 二、第二阶段开篇命题定稿：沙漏模型与文档世界 ctx

`kfmv4-9.0-phase2-hourglass-submission.md` 讨论区）**全部采纳**，整合定稿：

**模型（沙漏）**：上世界=文档世界（插件=agent+机制），下世界=代码世界
（插件=卡/服务，16 契约），agent=唯一被允许跨界的实体（沙漏中点特权），
组合（prompt×model×工作区）=跨界数据不是实体，**用户=沙漏外的验证者/
裁决者**（"用户当路由器"是模型缺位的降级形态，不是设计）。补充态：
**会话=未沉淀 Σ 流**，/compact=流→沉淀的机械仪式；降生（新 agent 拿到
什么）与压缩（老 agent 留下什么）是同一枚硬币的两面。

**文档世界 ctx = Σ + 事件 + 累积器（三元组，对齐 Cordis）**：
Σ=文档系统本体（已沉淀知识）；事件=信箱（事件面而非全部 ctx——收窄成立，
判据是中介性非连接度）；**累积器=git**（恢复面——没有它文档世界只有登记
没有卸载；心法 14"未提交改动没有安全网"即其文档表述）。入口仪式=降生协议。

**插件单位 = 机制**（规约+机械执行+失效信号三件套；卡萝互证：dsh 平行
演化出同构结构，是 agent harness 的普遍形态）：

- 生命周期（登记→巡逻→失效显形→退役）=**外层状态机管"何时死"**；
  运行时卸载三相=**"退役"这一步的内部实现管"怎么死"**——嵌套不平行
  （评审表述，采纳）；
- 退役判据两种红（茉莉）：守护代码已删/重构而红=正常退役（删钉），
  回归红=事故；**不存在薛定谔的机制**（死时要么绿=守护等价物，要么红且
  删钉=确认消亡）；
- **死后访问判红**（NA 自 G2 活性闸映射）：机制退役后任何文档/检查仍
  引用它=死后访问，痛觉器官立即显形，不许静默存活；
- broker 纪律（NA 自单一来源映射）：**同名二次登记=报错，绝不覆盖**。
