# 思维模式记录（thinking patterns）

> 洛主（用户）在范式级设计讨论中反复出现的思维模式——**可研究的对象**。
> 每个模式 = 名称 + 定义 + 出处（哪次讨论用了它）。原始数据在
> `.kfmv4/discussion-log.jsonl`（每次讨论一条）；本文档是提炼层（模式+出处）。
> 模式识别靠讨论中的意识 + 用户确认，**不自动化**——agent 不单方面定义用户。
> 愿景（远景）：样本积累后统计模式频率 → 用户验证 → 提炼启发式 → 部分注入 agent。
> 记录流程：见 workflows/discussion-study.yaml。

## 模式特征（用户确认，2026-08-03）

洛主的模式**会自然涌现但不会主动想起**——面对对应场景时自然出现，但事后
不会自觉识别「我用了什么模式」。因此分工：agent 在讨论中识别（用户涌现时
提醒「这条值得记录」），用户确认标签。这正是 discussion-study 双触发路径
（agent 主动提议 / 用户发起复盘）的设计依据。

## 模式清单

### 1. 类比驱动
**定义**：用日常/具象的类比提出新视角，让抽象机制变得可感、可验证。
**出处**：
- 2026-08-03 文档体系讨论：「游乐场入口指引牌」→ 引出了可达性审计（check-doc-orphans）
- 2026-08-03 文档体系讨论：「书架 vs 档案馆」→ 读/存价值分区（doc-architecture）
- 2026-08-03 文档体系讨论：「温水煮青蛙」→ 稀释腐烂的渐进性诊断

### 2. 追问本质
**定义**：不满足于表面定义，反复问「这到底是什么」直到挖到可操作的判据。
**出处**：
- 2026-08-03 可达性讨论：「可达本质上是什么」→ 从「有引用」推进到「有用/多大用」
- 2026-08-03 错误码讨论：「自我修正 vs 自我检查」→ 负反馈回路框架

### 3. 主动找反例（反驳修正）
**定义**：对每个方案主动找漏洞/反例/边界，不让方案带病通过。
**出处**：
- 2026-08-03 价值观测讨论：「数据不具代表性」「年龄偏倚」→ 统计口径修正
- 2026-08-03 价值观测讨论：「读得少≠没用」→ 价值模式分层（常态/应急/裁决）
- 2026-08-03 结晶回路讨论：「边界数字要数据说话」→ 采集层先行，阈值留数据

### 4. 概念统一
**定义**：把分散的机制统一到一个底层框架，用同一个原理解释。
**出处**：
- 2026-08-03 工作流讨论：「意图+行为=工作流」——check 链（机器执行者）/
  索引（人执行者）/工作流卡（agent 执行者）统一为「意图驱动的读取-行动-产出」
- 2026-08-03 自我修正讨论：错误码/账本/观测同构于一个负反馈回路

### 5. 分层治理
**定义**：面对复杂系统，先分层（按性质/执行者/时间尺度），再逐层给策略。
**出处**：
- 2026-08-03 错误码盘点：「流程门/质量门/自解释门」三分 check
- 2026-08-03 结晶回路：「现在（采集）/长跑（积累）/未来（定阈）」三时相

### 6. 反预设原则
**定义**：反对给未撞过的需求先画路线图——模式/机制从撞墙中演化，
刻意留白不预设。预设的路线图再合理，也是"没撞过墙的人画的墙"。
**出处**：
- 2026-08-08 NOOA 能力路线讨论：五层路线图（转录/提炼/练习/校准/放手）
  被用户当场反驳——与 experiments 通用契约 v0.1「模式从撞墙中演化原则，
  刻意留白不预设未撞过的需求」同源，首次在讨论中被显式识别为模式。

### 7. 基建涌现
**定义**：工具/机制靠真实需要长出，不靠设计堆——「实验需要 → 工具诞生 →
沉淀成常态」的循环。需要的墙被撞到，工具自然出现，形态比设计出来的合适。
**出处**：
- 2026-08-08 NOOA 能力路线讨论：证据链——单 api 工具（实验需要）→
  教官-考生双 api 脚本（实验需要）→ 集群并发（实验需要）→ 判卷+落成门
  （实验需要）——「agent 自主设计实验」大概率也由需要长出，不需预建。
- 推论：唯一不可延后的动作是记录（讨论/裁决样本会消失，工具不会）。

### 6. 数据先行
**定义**：涉及边界/阈值/判断的决策，不拍脑袋，先测量后定标。
**出处**：
- 2026-08-03 结晶回路：「≥3 次的边界数字必须真实数据统计后科学制定」
- 2026-08-03 文档重构：「要不要重构由观测台数据回答，不凭感觉拍板」

### 7. 元层思考
**定义**：把机制本身当研究对象——讨论的讨论、观测的观测、模式的模式。
**出处**：
- 2026-08-03 本文档的诞生：「讨论本身的思维路径是原始数据，agent 做不到」
- 2026-08-03 文档体系：「文档系统会不会有自己看不出、很难看出的腐烂」

### 8. 推演正确 ≠ 结论正确（前提校验）
**定义**：推演链路全对但前提错，结论就成了症状不是解药。当推演结论要引入
复杂机制（新分类/分层/新系统）时，回头检查前提——复杂化是「前提错」的信号。
**出处**：
- 2026-08-03「每文档一个工作流」推演：「会爆炸 → 要二级分类」链路对，但
  前提（每文档都要独立 yaml）错——解药是消费模式聚类，不是二级分类

### 9. 函数化统一
**定义**：把分散概念抽象成函数/接口（输入→输出），分散的实例立刻变成同一
框架下的不同实现，关系一目了然。
**出处**：
- 2026-08-03「意图解释器」：输入意图→输出行为的函数框架统一了
  API/脚本/人/agent 四类执行者（差异 = 意图来源/状态性/行为域/适应性）

### 10. 拆轴
**定义**：看似二选一的争论，往往是混了两个轴——拆开各谈，两边的合理部分
都能保留。
**出处**：
- 2026-08-03「更像人 vs 更好的工具」：拆成「界面像人」（交互偏好，有用）+
  「能力不像人」（超越机械化短板）两轴，争论消失
- 2026-08-03「显式 vs 涌现」：拆成「执行/发现/审查」三职责分工——杂交而非选边

### 11. 类型学追问
**定义**：从一个单点缺口追全类普查——「这属于哪一类产物？同类还有谁没有
主人？」点的问题是症状，类的问题才是病灶；给类立机制，点就不会再犯。
**出处**：
- 2026-08-06「发现性保障」：守视（browser-relay）上线当日同机另一 agent
  不知其存在 → 追到「重要产物脱离第一手作者后无发现路径」整个类 →
  发现门统一模式「文件名必须出现在发现面」（code-map 门管部件、
  agent-runner 门管脚本）+ 元规则（新产物类型必问机械主人，DOC-FLOW-10）

### 12. 三重检验（元认知行为边界）
**定义**：任何元认知行为（补充信息/错误清单/自动化/定价/检查清单/展示权衡/
守主线/复盘/制度化）都是工具——价值在「服务判断」，宿命在「取代判断」。
三重检验：① 它服务判断吗（有用）② 它还有产出吗（活着，产出被消费而非
归档）③ 它是否已在取代思考本身（退化：仪式/打卡/教条）。任何行为一旦从
「服务判断」滑向「取代判断」，就该收起——收起不是失败，是把注意力还给
真正需要它的地方。
**出处**：
- 2026-08-07 反例边界篇系列收尾（B9-S12 九节）：九节各自的停止信号高度
  同构，收尾提炼为总纲「三重检验」，用户确认后入档。配套信号：「产出趋零
  / 行为未变 / 动作取代思考 / 手段取代目的 / 情绪从方向变安全 / 在等停止
  的许可」——任一持续出现即收起

## 记录规程

1. 范式级讨论收尾（discussion-study 工作流）→ 账本一条（含模式标签）
2. 新模式 → 本文档加一条（名 + 定义 + 出处）；旧模式新样本 → 出处追加
3. 模式标签由用户确认后才入档
4. 本文档本身是「元层思考」的产物——模式清单会随样本增长
