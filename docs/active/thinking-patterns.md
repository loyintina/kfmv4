# 思维模式记录（thinking patterns）

> 洛主（用户）在范式级设计讨论中反复出现的思维模式——**可研究的对象**。
> 每个模式 = 名称 + 定义 + 出处（哪次讨论用了它）。原始数据在
> `.kfmv4/discussion-log.jsonl`（每次讨论一条）；本文档是提炼层（模式+出处）。
> 模式识别靠讨论中的意识 + 用户确认，**不自动化**——agent 不单方面定义用户。
> 愿景（远景）：样本积累后统计模式频率 → 用户验证 → 提炼启发式 → 部分注入 agent。
> 记录流程：见 workflows/discussion-study.yaml。

## 模式清单

### 1. 类比驱动
**定义**：用日常/具象的类比提出新视角，让抽象机制变得可感、可验证。
**出处**：
- 2026-08-03 文档体系讨论：「游乐场入口指引牌」→ 引出了可达性审计（check-doc-orphans）
- 2026-08-03 文档体系讨论：「书架 vs 档案馆」→ 读/存价值分区（doc-architecture）
- 2026-08-03 文档体系讨论：「温水煮青蛙」→ 稀释腐烂的渐进性诊断

### 2. 追问本质
**定义**：不满足于表面定义，反复问「这到底是什么」直到挖到可操作的判据。
**出处**：
- 2026-08-03 可达性讨论：「可达本质上是什么」→ 从「有引用」推进到「有用/多大用」
- 2026-08-03 错误码讨论：「自我修正 vs 自我检查」→ 负反馈回路框架

### 3. 主动找反例（反驳修正）
**定义**：对每个方案主动找漏洞/反例/边界，不让方案带病通过。
**出处**：
- 2026-08-03 价值观测讨论：「数据不具代表性」「年龄偏倚」→ 统计口径修正
- 2026-08-03 价值观测讨论：「读得少≠没用」→ 价值模式分层（常态/应急/裁决）
- 2026-08-03 结晶回路讨论：「边界数字要数据说话」→ 采集层先行，阈值留数据

### 4. 概念统一
**定义**：把分散的机制统一到一个底层框架，用同一个原理解释。
**出处**：
- 2026-08-03 工作流讨论：「意图+行为=工作流」——check 链（机器执行者）/
  索引（人执行者）/工作流卡（agent 执行者）统一为「意图驱动的读取-行动-产出」
- 2026-08-03 自我修正讨论：错误码/账本/观测同构于一个负反馈回路

### 5. 分层治理
**定义**：面对复杂系统，先分层（按性质/执行者/时间尺度），再逐层给策略。
**出处**：
- 2026-08-03 错误码盘点：「流程门/质量门/自解释门」三分 check
- 2026-08-03 结晶回路：「现在（采集）/长跑（积累）/未来（定阈）」三时相

### 6. 数据先行
**定义**：涉及边界/阈值/判断的决策，不拍脑袋，先测量后定标。
**出处**：
- 2026-08-03 结晶回路：「≥3 次的边界数字必须真实数据统计后科学制定」
- 2026-08-03 文档重构：「要不要重构由观测台数据回答，不凭感觉拍板」

### 7. 元层思考
**定义**：把机制本身当研究对象——讨论的讨论、观测的观测、模式的模式。
**出处**：
- 2026-08-03 本文档的诞生：「讨论本身的思维路径是原始数据，agent 做不到」
- 2026-08-03 文档体系：「文档系统会不会有自己看不出、很难看出的腐烂」

## 记录规程

1. 范式级讨论收尾（discussion-study 工作流）→ 账本一条（含模式标签）
2. 新模式 → 本文档加一条（名 + 定义 + 出处）；旧模式新样本 → 出处追加
3. 模式标签由用户确认后才入档
4. 本文档本身是「元层思考」的产物——模式清单会随样本增长
