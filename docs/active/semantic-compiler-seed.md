## 定位：双区管线，不硬拼

v8.2 建立的是**语法层 doc-as-code**（引用、结构、计数——机械可判）。本体系是**语义层 doc-as-code**——文档断言与代码现实、文档与文档之间的真值一致性。两者是双星系统，互相喂食但不同轨：

- **确定区**（已有/在建）：`npm run check` 阻断链。要求确定性、秒级、零边际成本。
- **概率区**（本体系）：subagent 驱动的语义审查，**非阻断**。LLM 输出概率性、分钟级、烧 token——进阻断链会杀死管线信任（alarm fatigue）。位置在**工作流**，以工作流卡为载体（semantic-audit.yaml，未建），触发条件 = 流程闭环计数（距上次 N 个 feat/fix 闭环）或事件（发版 / 大迁移后）——分布式系统的 anti-entropy 对账协议。

## 语义病灶分类（SEM 错误码草案）

编译器的本质是错误码分类学——没有错误码，模糊发现就无法计数、无法进「同一错误 ≥3 次 → 机械化」的结晶回路。

- **SEM001 stale-claim**：文档断言的行为被实现直接反驳
- **SEM002 cross-doc conflict**：两份文档对同一事实断言不兼容
- **SEM003 orphaned-concept**：文档围绕的概念在代码/远景中已消亡（悬垂指针的概念版）
- **SEM004 authority-conflict**：两份文档争夺同一主题权威权，真相悬空
- **SEM005 direction-drift**：远景/路线图与累积决策记录方向相悖（合并冲突从未 resolve）

**已确认首个实例**：远景类表达仍称「kfmv4 不做自己的 agent、不自己调用工具，只做其他 ai-coding 工具的转接」，与 kfm_ 系列内置工具的实现现实相悖 → SEM001/005。语义 bug 会顺提示词传播成行为 bug：每个冷启动 agent 都会执行到这条错误指令。试点时优先修复。

## 分布式视角（本体论）

文档系统 = 真相的分布式副本系统：代码是真相源，文档是副本，contract → CLAUDE.md 路由 → agent 提示词是二级副本。

- **分层一致性模型**：contract 强一致（机械检查，每次构建）；vision/guides 最终一致（定期语义对账）。
- **血缘（provenance）支撑增量对账**：迁移注/素材考古即血缘标记；上游变更 → 只复检依赖链上的下游，语义编译才可负担（make 式增量）。
- **拜占庭对策**：`LLM proposes, mechanics disposes`——每个发现必须附 file:line 证据，机械复核后才立案。幻觉发现拿不出真证据，死在复核环节。

## 结晶回路

模糊层是确定层的研发部：发现 → 核实 → 修复 → **同类发现反复出现 → 提炼机械规则进确定区**（discipline-mechanize 的文档管线版）。模糊层的终极职责是让自己一条规则一条规则地失业。试点产出率不达标 → 记录证伪，方向封存。

## 冷启动 e2e 测试

推到底：**文档就是程序，agent 是解释器，文档系统的功能正确性 = agent 读完后的行为正确性。**

测试法：给全新 subagent 只喂文档，提问后对照真相。例：「kfmv4 做自己的 agent 工具吗？」——若按过时远景回答则测试红。不看文档对不对，看文档装出来的 agent 对不对。

## 集群统计方向（2026-07-29 追加）

冷启动 e2e 的进化：单发提问是测试用例，**集群提问是统计显著性检验**。

- 利用生成式 AI 每次回答不同的特点：同一问题问 N 个新 agent。
- 假说：规模小/文档清晰 → 回答趋同；规模超量/文档模糊 → 回答发散。
- **回答方差 = 文档语义质量的统计信号**（一致率、置信区间）。
- 待研究：问题集设计（覆盖各域关键事实）、N 的确定、发散阈值、成本约束。

## 试点方案（批 1.5，前置：批 1 完成）

4. 达标 → 制度化（定时触发，release.yaml 已埋审计节奏铺路字段）；不达标 → 证伪封存。
