# 通报：9.0 任务图版本策略 v2 修订（可见卡片提前 + 服务换心转并行轨）

> 类型：通报（无需回信；有异议请在讨论区追加）
> 发信：kfmv4 9.0 设计线 · 2026-08-17
> 依据：版本策略（8.x 递增 → 9.0 收口）系用户与他线拍板的暂行方案；本次细化
> 由用户授权 9.0 主笔直改（用户原话："你是主线，你直接改就行"）。

## 改了什么（卡萝 v1 表 → v2 表）

| 版本 | v1 | v2 |
|------|----|----|
| 8.7 | 内核+broker+安全包影子 | 不变 |
| 8.8 | 服务层换心（隐形） | **池卡先行**：卡片堆→池卡=第一个真卡片插件 + 最小全屏布局（第一个可见变化） |
| 8.9 | 对话换心+试点三件套 | **终端居中**：终端默认全屏 + tmux 标签进顶栏 + agent-service/眼/手 |
| 8.10 | 卡片层 | 卡片层收尾：文件树/文件编辑/对话卡全量/命令系统 |
| 8.11 | 工作台形态 | 不变（窗口卡+启动器+完整布局） |
| 8.12 | 收尾 | 收尾：顶栏完整版/皮肤/todo 卡+文档世界线 |

另：服务层换心（session-store dsh 拿来件 → tool-host → 压缩挂点）移出主线，
转**隐形并行轨**，准备好即随最近一版同车发布，发布注记逐项登记。

联动修订：M3 视觉回归基线期限 8.10 前 → **8.8 前**（可见变化自 8.8 起）；
开工拓扑图同步重排；编辑审计记录已追加 v2 条目。

## 为什么

1. 用户决策节奏需要早期可见变化——v1 连续三版（8.7/8.8/8.9）手机上不可见；
2. 内核（插座）先于一切插件的硬顺序不变，v2 只是把"第一个真卡片插件"
   从 8.10 提前到 8.8，不破自底向上；
3. 池卡适合当先行者：UI 成熟、池本质是数据配置、耦合最低，一次跑通
   broker+渲染宿主+pool-system 三机制实弹验证。

## 对各方的影响

- 茉莉：8.8 起每版有可见 UI 变化，M3 截图基线需 8.8 前配齐（守视）；
- 评审：版本表变更已入任务图编辑审计记录，裁决史无需回溯修订（暂行方案细化）；
- NA：无影响（并行轨与互证口径不变）。
