## 二、真根因（修正之前判断）

**Via 在「有栏 + 键盘」态，`visualViewport.height`（和 innerHeight）都不可靠——`vv.height` 多报 ~40px**（≈一整排高）。所以**任何按 vv 定位的底部 UI（keybar 下排 / 输入栏）都会偏低 ~40px → 落进键盘被盖**。全屏时 vv 可靠（多报=0）→ 正常。

- 不是 9.0 单个实现错（公式对、钉 vv 对，但 **vv 本身在 Via 有栏就是错的**）；
- 是**浏览器视口测量问题**，8.x/nz 各被它咬着不同元素——**两个版本都没真正解决**。

## 三、修法方向（换了基准，不再是猜）

**拿「真实可视高 / 真实键盘顶」作基准，别信 vv**，让 keybar + 输入栏**所有底部 UI**都钉到真可视底。候选：
1. **探测真实键盘顶**：vv 变化前后差值 / 浏览器特定 API / `visualViewport` 的 offsetTop+scroll 复合（Via 有栏时 offsetTop 可能非 0，实测数据里 ot 恒 0 可疑——需在真机再确认 vv.offsetTop 的真实值）；
2. **终端容器按『真实可视内容区』裁剪**：壳知道自身可见多少行/内容底，keybar 钉在**内容真裁边界**（不依赖 vv 数值）；
3. 若 8.x 的 keybar 定位用了某种可靠基准，可对照其实现（但 8.x 输入栏仍盖，说明它也没全解决）。

## 四、验收

修后请用户真机**两状态（全屏/有栏）**各弹键盘，**keybar 两排 + 输入栏都不得被盖**（截图/实测判据），`kbc`/输入栏 overlap 稳定 0。评审按截图+数字收口。

## 备注

本案与 IME 滚焦/上浮同为「浏览器视口(visualViewport/innerHeight) + 键盘交互」真机专属类。**教训**:这类问题 headless 不可复现、vv 在特定状态不可信——正确打法是**先真机截图+数据实测**（case-002 / 本 4 图），再定位到"基准信号不可靠"，换可靠信号，而非继续在 vv 公式上打转。
