## 一、问 1：与既有机制无冲突，附三处咬合修订

六步与判卷链/打脸结晶/词汇表强制/§7 **无重复建设**——它是 §7 四步纪律的操作化，⑥即结晶制、④即词汇真源。三处咬合修订：

1. **⑤应显式含变异抽检**：§7 四步的第四步（变异抽检）在六步里被并进⑤但未点名。判卷链的教训（考题与实现同流合污）靠的就是这一步，⑤改为「考卷自动红绿 + 变异抽检点名，不经过用户」。
2. **③生钉应含时序钉**：§7 五要素的时序预算（转换时限超限=红）在六步里没有位置。③改为「每行转换一颗钉 + 每条禁令一颗钉 + 时序预算」（§7 裁决①同款）。
3. **①②受豁免线约束**：§7 裁决②已立「≤2 状态 × ≤4 转换免签收事后报备」——六步①②对琐碎组件应直接跳过，豁免线优先，否则流水线瓶颈在用户端复现。

## 二、问 2：入口判别——agent 判，清单词汇判，六步自校验兜底

- **由执行线 agent 判，用户不判**。用户只描述现象；分类是元工作，判别器（用户）只做具体实例判断——让用户分类等于把元工作塞回最贵的资源。
- **判别规则形式化**：现象能否用清单词汇描述？能用清单状态描述（「点 X 后按钮停在 Y」）→ 规格缺口，直接补清单；完全无法描述（闪退/黑屏/无响应）→ 故障，走观测环。
- **误判兜底不需要新机制——六步自校验**：规格缺口判别后补清单→生钉→跑卷，卷红且修后用户满意 = 判对；清单补了卷却绿而用户仍不满意 = 误判（实为故障），升级观测环。**连续 2 次同向误判 → 该类现象默认改走另一条道**（判别器自适应校准）。

## 三、问 3：可立即机检清单 + ①盘点枚举的机械生成形态标准

**立即可机检**：③→⑤ 清单-考卷映射（每转换/禁令一钉，缺钉=红）；词汇表一致性（清单外状态名=告警，nz 考卷⑦先例）；清单文件路径进契约签名（§7 裁决③）。

**①盘点枚举标准（评审定）**：

- **源 = 实现扫描**：状态候选从「状态赋值点」提取（DOM class 写入 / data-* 属性 / 枚举变量赋值）；转换候选从「事件源」提取（addEventListener / inject 入口）。
- **形态**：`scan-state-machine <组件>` 输出草案三节（states/transitions/sources），**每条带证据位置（文件:行号）**——用户认领时必须能跳到代码，不可溯源的草案条目直接弃。
- **分工判据**：扫描器对**事件源覆盖率**负责（所有监听入口被枚举，漏一个=扫描器 bug），对**状态语义正确性**不负责（那是②认领的事）——机器管完备苦工、人管语义对错，正是①②分工的形式化。
- na 侧形态：从 enum 定义 + match 臂提取（比 web 侧更结构化）；bar-inject 指令集即事件源清单。

## 四、问 4：composer 首跑验收标准（三层判据 + 否定判据）

「8 天循环被终结」的判定 = 以下**全部**成立：

1. **清单收敛**：composer 状态×转换表定稿（样板 v1 十一行 + 首跑结晶合并）并完成用户签收；且签收中**「没想到」类回答 ≤30%**——超过三分之一靠「没想到」长出来的清单，说明①盘点不成熟，不配宣判终结。
2. **行为判据（核心）**：清单定稿后**连续 5 个交互需求全部一轮签收**——认领一次通过（「对」，或「不对应是 X」且 X 一轮并入），无第二次语义仲裁。tmux-tabs 式三轮不复现。
3. **时间判据**：定稿后 **7 天零「跟我预期不一样」报告**。出过 bug 的转换按结晶制回炉不算失败；**同一转换第二次出 bug 算失败**。
4. **观测记录（非判据）**：⑥→③结晶频率随时间递减——这条曲线就是「循环被终结」的定量形态，首跑期间照常记录。

**否定判据（何时宣告假设不成立）**：5 个需求中 ≥2 个触发完整三轮仲裁 → 「清单终结循环」在 composer 上不成立，回炉研究清单形态本身。**失败也是数据点**——8 天循环本身就能证伪一次方法论假设，这买卖不亏。
