## 一、必须有（没有它开发流就断/就疼）

1. **断链自愈 + 状态可见**——真实场景：今天服务器崩溃重启后四个 tmux
   窗口是用户手动 `tmux new-session -A -s dsh` 逐个重建的；8022 隧道断
   时我（agent）侧的远程命令/热更链直接断在半路。要的：断层可见（ssh
   断？隧道断？tmux 死？各自状态+恢复时刻），恢复后 tmux 上下文与窗口
   注册自动回来，不靠人肉逐个敲。
2. **长任务通知**——真实场景：chain 闸一轮 3~5 分钟、手机编译 1 分钟、
   过夜实验按小时计，我现在靠轮询 field-reports.log 和人眼盯屏。agent
   任务完成/失败/需要拍板时手机推送，等待环立刻缩短。
3. **多会话活动指示**——真实场景：dsh/kfm-na/omp/psh 四窗并行，kimi
   在后台窗等我拍板、chain 红了、实验跑完，我全都不知道，得挨个翻窗。
   非焦点窗有输出 = 标签上可感提示。
4. **重载下不冻结**——真实场景：IO 挤兑事故两轮（mutants + 多 kimi 并
   行），服务器 PSI 满、终端整个卡死连字都打不进。要的：重载时降级显示
   状态（哪怕一行「服务器 IO 满」），正在敲字的终端不能死。

## 二、最好有（显著提效不致命）

1. 会话生命周期快捷操作：新建/改名/杀/清屏，从标签栏直达，不手打 tmux 命令。
2. scrollback 内搜索：万行日志里找报错，现在只能翻页肉眼扫。
3. 复制粘贴体验对齐 na 输入栏水准（长按选中/拖柄/菜单那套，na 侧已打磨
   过一轮，nz 终端侧还是粗糙版）。
4. scrollback 容量按 term-contract 契约值（SCROLLBACK_LINES=10000）显式
   对齐——容量考题已立项，nz 侧顺手钉住。

## 三、明确不做（防自作多情）

1. 内置 AI/眼/手——那是 na 的线（见 §〇 边界）。
2. 文件树/便签本——na 主线。
3. 多服务器编排/云同步/团队协作——单人单服务器+手机场景，稳定优先。
4. 视觉主题系统——先稳定后好看。

## 四、na 侧承诺

验收判卷人随叫随到：na-push-so 热更链、chain 闸、8022/8024 通道都是日常
高用路径，nz 的稳定化以这些路径的连续无事故为标尺，我们实时反馈。
