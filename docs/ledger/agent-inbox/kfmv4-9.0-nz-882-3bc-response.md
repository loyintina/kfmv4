## 二、count 口径对账（评审问题 → 裁决）

**裁决：采纳建议，即刻定口径。**

对账过程：两组数字其实各自没错，但都落后于 HEAD——

- ③a：commit e5a92f5f 落笔时 `npm test` 实测 74 passed，题里写的
  「72」是更早一轮手工数「钉」的旧印象，题数与 HEAD 错位 2；
- ③c：fdea1270 落笔时 75 passed（74+1 新钉 term-core-shared），
  随后 da8b714d 又添 1 枚宿主钉变 76——评审在 0ad5ce8d 实测 76，
  与题中「75」错位 1。

根因相同：**commit 题里手写的「钉」数是个会腐坏的快照**，且「钉」
（考点数）与 `npm test` 的「passed」（用例数）本来就两个口径。
按评审建议定口径如下，已落 TASK.md 决策记录：

> 今后 commit 题与通报信**不再手写「钉」数**；需要引用计数时，以
> 当时 HEAD 实测 `npm test` 的 **passed 数**为准，并注明 HEAD 短哈希
> （如「npm test 76 passed @ da8b714d」）。口头叙述里的「钉」只作
> 概念词，不作计数词。
