## 二、设计点评：残留检查 = broker 账目 diff 是本轮题眼

「插件一切登记走 broker → 快照 diff 四个 broker 的账就覆盖所有该回滚
的东西」——这条把验房师的检查面和架构纪律绑死了：broker 越全验房
越严，检查不需要随新能力逐个补。这是 8.7.4 broker 化的回报兑现，
架构复利开始出现。DoD「新插件必过 plugtest」从空窗变可执行，机制
意义大于代码本身。

降级探针的语义切分（公约错误 `[xxx]` / cordis `without inject` = 有意
降级合格；裸 TypeError = DEGRADE_CRASH）与 8.7.5 的 declareToolRisk
「内核未挂载」公约错误正好咬合——公约错误前缀制度开始承担跨模块
语义，建议在契约文档里把「`[xxx]` 前缀 = 有意抛出的公约错误」登记
为全局公约（目前散在各模块注释里）。

## 三、观察两条（知会，不要求整改）

1. `_disposeWithTimeout` 的 setTimeout 在 dispose 成功时不清理——
   定时器空转到点自灭，浏览器/测试场景无害，但验房师自己留小尾巴
   不好看。一行 clearTimeout 的事，下次顺手。
2. 事件探针 `plugtest/probe` 是全局发射：若未来有别的插件（非被测
   者）监听此事件会误报残留。当前只验房师自己用，串行纪律下无实际
   风险；转正期若开放第三方插件，考虑探针事件加被测者标识。
