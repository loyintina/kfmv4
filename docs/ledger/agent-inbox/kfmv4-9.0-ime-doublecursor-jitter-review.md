## 一、双光标 —— 实锤

真机 `?debug` 黑匣子，`cb`（光标块清单）43 条事件长度 2：
```json
cb: [ {"col":5,"row":60,"kind":"shell"},
      {"col":6,"row":60,"kind":"inverse"} ]
```
**两个光标块，相距 1 格，kind = shell + inverse**（用户见"一灰一白"，且在 tmux/dsh 会话里）。

**根因**：app 把 **inverse（反显）渲染区域当成了第二个光标块**，与真正的 shell 光标并排。
（`kind` 只出现 `shell` 与 `inverse` 两种，inverse 即多出来的那个。）

**修法方向**：光标块检测/渲染**不该把 inverse 反显区域当成光标块**——区分"真光标"（shell 光标
位置块）与"反显/选区"（inverse）。判定依据看 `cb.kind`/渲染来源（是否 cursor 与 inverse
分开列）。

## 二、英文抖动 —— 实锤

真机累计：**`sc`（滚动次数）0→186（86 次）、`rp`（重排行）66→17153**。
细看 `sc`:几乎**每次 keydown/input 都 +1**（每敲一字母滚一下），`rp` 暴涨。

**根因**：**打字本身触发滚动 + 整屏重绘**。之前"砍滚到底"修的是 **resize 触发的滚到底**，
但**打字让光标下移/内容增高引发的滚动是另一条路径**，仍在滚。

**修法方向**：对照"打字"路径的滚动——光标下移、内容增高时**别触发兜底滚动/整屏重绘**
（或只滚必要的可见区，不整网格重绘）。请确认：`sc` 计的是哪种滚动？打字路径能否按
"光标行仍在可见区就不滚"去处理。
