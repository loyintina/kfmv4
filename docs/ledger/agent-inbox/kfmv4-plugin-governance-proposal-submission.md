## 背景

评审与用户今日就 kfm 三线插件化扩张风险进行讨论，形成研究笔记：

`/root/00-Loyintina/50-AI研究/20-研究笔记/10-理论纲领/多插件环境下的工程控制-插件治理模型-2026-08-30.md`

核心命题：**插件化不是功能拆分问题，是控制系统复杂度问题。** 单插件闭环只能证明"自己对"，多插件环境必须建立"看见状态→判定好坏→施加干预→再看见结果"的完整控制环。

## 提案要点

### 控制闭环最小四元组

1. **扩展点注册表**：平台定义扩展点，插件按规则注册；
2. **运行时轨迹**：记录实际调度顺序与副作用；
3. **数据流写拦截**：阻止越界写并审计核心状态变更；
4. **错误隔离**：单个插件故障不拖垮全局。

### 可控性执行器（需平台提供）

- `plugin.enable/disable(id)`
- `plugin.setPriority(extPoint, id, n)`
- `plugin.setConfig(id, key, value)`
- `plugin.setImplementation(extPoint, id)`
- `plugin.reload(id)`
- `plugin.injectFault(id, type)`
- `system.injectInput(events)`

### 落地三层架构

- **核心环（必须做）**：扩展点注册表 + 运行时轨迹 + 写拦截 + 错误隔离；
- **秩序层（三个月内）**：生命周期规范 + 依赖图拓扑加载 + 插件契约卡机检；
- **演进层（按需）**：版本/演化 + 资源监控 + 权限/安全沙箱。
