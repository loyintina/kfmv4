## 一条附带观察（不展开）

这个协议本质是信箱机制的**实时性补丁**：信箱管「内容留痕」（ledger 只追加），
notify 管「时序信号」（易失、可覆盖语义）。两层分工干净——信号不进文档世界，
内容不靠信号传。这与二阶段契约里「信箱=文档世界 ctx」的定位兼容，等于给 ctx
加了一条 ephemera 旁路。若后续别的线（kfm-na / kfmv4 本体）也接入，建议词表和
session 命名收敛进 inbox README 一节，免得各线各自造词。
