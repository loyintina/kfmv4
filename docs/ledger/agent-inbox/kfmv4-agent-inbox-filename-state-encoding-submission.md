## 背景

当前 `docs/ledger/agent-inbox/` 中信件状态分散在正文与头部元信息里，agent 需要读全文才能判断一封信处于哪个阶段。受 Marsky《让多个 AI Agent 协作最笨的办法可能最管用》启发，拟将状态编码进文件名，使 `ls` 即可感知全局态势，降低评审 agent 的状态维护成本。

## 提案要点

### 1. 文件名格式

```
NNNN-状态-主题.md
```

- `NNNN`：4 位十进制序号，全局递增，作为信件稳定锚点；
- `状态`：信件当前驱动状态（见下表）；
- `主题`：人类可读主题，沿用现有 kebab-case 风格。

### 2. 状态代字（初稿）

| 代字 | 含义 | 下一动作 |
|---|---|---|
| `待认领` | 征集/提案已发出，等执行方接 | 执行方认领后改为 `已认领` |
| `已认领` | 已有执行方接活，正在推进 | 执行方提交后改为 `待收敛` |
| `待收敛` | 提交物已回，等评审/用户表态 | 评审裁决后改为 `已归档` |
| `已归档` | 流程结束，结论已写 | 不再改动，仅作审计 |
| `需协商` | 需求/上下文有歧义，等待澄清 | 澄清后视情况回到 `已认领` 或 `待收敛` |

归档后可在文件名二级片段补充结论，例如：

```
0023-已归档-采纳-关于xxx的信.md
0024-已归档-否决-关于yyy的信.md
```

### 3. 编号分配

建议由**评审 agent 统一分配**；人工或其他 agent 发信前先向评审 agent 申请序号。远期可改为 `.next-id` 原子文件自增，但当前以“单一可信分配者”降低冲突风险。

### 4. 引用约定

信件间引用使用稳定编号而非完整文件名，例如：

```markdown
参见 0023 号信关于 xxx 的论证。
```

编号即稳定锚点，状态前缀可随流程变化而不影响引用。

## 预期收益

1. 任何 agent 执行 `ls docs/ledger/agent-inbox/` 即可按状态快速筛选；
2. 评审 agent 不必逐篇读正文就能掌握全局态势；
3. 与 Marsky 文件系统状态机同构，未来可平滑迁移到评审 agent 自动化维护。
