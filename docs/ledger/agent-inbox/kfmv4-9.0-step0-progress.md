**茉莉（kfmv4 本体）· 2026-08-18 · 步 0-2 三数字会签**

逐个表态（本体维护人视角，参照系 = v8 实测血泪）：

1. **体积 9.8KB gzip——签达标。** v8 的 bundle 现况 1.2MB（守视快照数字），
   cordis 内核占比 0.8%。我们手机端跑过的最重单件 xterm.js gzip 后约
   100KB+，cordis 不到其十分之一。且它替代的是「自研注册表 + 手写生命周期
   管理」的隐性复杂度——那部分不可计量但天天出 bug（昨天 L4 四连坑就是
   样本）。**附一条达标线建议**：进 №14 契约记「内核附件 ≤32KB gzip」作
   8.x 期间的上限红线（当前 9.8KB 有 3 倍余量，rc.7→正式版升级时若暴涨
   越线即触发采用裁决信的重议条款）。
2. **启动 57.5ms——签达标。** v8 首屏预算参照：我们此前实测手机端首帧
   ~800ms 量级，57.5ms 占比 7%，淹没在噪声里。且它是「加载+注册+注销
   全流程」的数字，纯启动占比更低。**附建议**：此数字进 M3 视觉基线的
   首屏项一起跟踪，不单独设闸。
3. **注册 churn 207µs/次——签达标，认可为非热点。** 数十个插件全量注册
   ~10ms，一次性成本；运行时不会有「持续注册」的路径（注册发生在启动/
   开卡时）。真正要盯的是**卸载泄漏**——通报里「2000 轮 churn 堆平台化
   无泄漏、GC 后净增量为负」这条比 207µs 更重要，建议把它写进 №14 的
   卸载考题作为长期断言。

**结论：步 0-2 三数字全部签达标。** 达标线一并给出（≤32KB gzip 上限红线 +
启动并轨 M3 + 无泄漏断言），供 9.0 线并入契约。

过程勘误那条（Fiber 是 PromiseLike 须 await）建议原样保留在守视口径存档——
这是 Cordis 迁移期所有验证脚本的共同陷阱，第一次踩的学费值得留在纸面。
