## 1. 点按浅青浮层（用户真机报告①）

**现象**：点把手/标签，除自身动作外还有一层浅青色浮层，像调试定位框，不像 UI 动效。

**定罪**：WebView 默认 `-webkit-tap-highlight-color`，nz 代码从未设置过。观测手段声明：8026 CDP **screencast 帧序列** + `NzNative.tap` **真触摸原语**（走系统真触摸管道，与用户手指同款）——点按前/中连拍，f001 帧把手上浅青蓝半透明层现形，f000 对照无。

**修法**：tokens.css 全局 `-webkit-tap-highlight-color: transparent`。点按反馈由组件 `:active` 动效承担，无损失。

**验证**：CDP 注入同款 CSS（免 reload）→ 同法连拍 → 同机位帧浮层消失（双向因果）。用户真机确认「修复有效」。

## 2. 展开时先出标签栏、后转按钮（用户真机报告②）

**现象**：展开顺序不对——先出现标签栏，后旋转按钮；收起正常同步。期望两者同时播放。

**定罪**（观测手段：CDP 25ms 粒度 computed-transform 采样 + 真触摸）：

| 时刻 | 修复前把手 transform | 含义 |
|---|---|---|
| 26-176ms | `matrix(0.989..0.96, 0, 0, ...)` | **纯缩小零旋转**（`:active scale(.96)`） |
| ~200ms | 才开始出现旋转分量 | 旋转滞后 |
| ~450ms | 才到 `rotate(90°)` | 对不齐标签排 250ms |

根因：`:active` 的 `scale(0.96)` 与展开态 `rotate(90deg)` **函数列表不匹配 → 矩阵插值**（非角度插值），旋转被压到后段。收起时起点是纯 rotate、终点 none 可按恒等列表分解，所以正常——与用户「收起正常」的观察完全吻合。

**修法**：把手全状态函数列表统一为 `[rotate, scale]`（`rotate(0deg) scale(1)` / `rotate(90deg) scale(1)` / 两态 `:active` 同款带 scale(.96)），角度独立插值。

**验证**（同法采样，同机同触摸）：

| 时刻 | 修复后 | 对比 |
|---|---|---|
| 26ms | 已转 **19°** | 修复前 0° |
| 50ms | **58°** | 修复前还在缩小 |
| ~200ms | **90° 到位** | 修复前刚开始转 |

与标签排同拍。headless animation-check 全断言绿。

## 3. 教训入账

1. **CSS transition 的函数列表是插值路径的开关**：列表不匹配走矩阵插值，视觉上分量顺序不可控。做「多状态变换」的组件，所有状态的 transform 必须写全同一函数列表（含零值占位 `rotate(0deg) scale(1)`）。
2. **`:active` 触觉反馈会进入变换插值链**——真触摸 DOWN 的 60ms 足以让 `:active` transition 起跑并污染后续 retarget 路径。设计 :active 动效时要想它与主状态变换的列表一致性。
3. **25ms computed-style 采样是动画级 bug 的定罪尺**：截图帧序列看「有没有」，采样看「什么时候、走什么路径」——本案帧序列抓不到（变化太快），采样一锤定音。已入观测手段库。
