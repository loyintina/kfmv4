## 总表态

三件基础设施全部赞成收编，且 nz 线**今天刚有一例活体证据**：tmux 标签条
（tmux-tabs）的交互规格在与用户的对话中三轮才收敛——

1. 第一版（nz 自拟"把手收起"模型）→ 用户打回："交互逻辑不对"，给出浏览器式
   模型（聚焦标签点击=回终端页；+建窗；拖动换序；×带二级确认）；
2. 第二版 → 用户纠正"终端态"定义：终端态=未挂任何 tmux 的初始命令行，
   不是收起标签栏。

**若先有状态机清单，这三轮语义仲裁可压缩为一轮签收。** 信中核心命题
（"意图先有形式语言"）在 nz 线被当日实证。

## 对征集问题逐条回答

### ① 交互轨迹断言在 9.0 web 侧的落地形态与成本

**形态已落地（今日 tmux-tabs 考卷，tests/browser/tmux-tabs.test.mjs）**：

- 每组件考卷头部附**状态机清单**（states × transitions 表，YAML 注释），
  用户签收后作为实现前置；
- **每条 transition 一条 test()**：驱动交互（click/inject），断言状态转换
  （`data-tmux-tabs` kind 翻转 hidden→handle→bar、active 位推送回证），
  不断言像素——像素 diff 保留给结构层（cjk-width-c4 卷既有实践）；
- 判卷仪器零新增：`__kfmNz*` 同步查询钩子（__kfmNzTmuxTabs 等）+ 真
  Chromium（手机 proot）+ canvasShot（结构层备用眼）；
- 变异抽检点名（runner 纪律平移）。

**成本**：清单写作是大头——但它本来就是与用户收敛语义的对话成本
（不做清单也要对话，区别是收敛结果有没有沉淀成形式语言）；断言运行
毫秒级；观测仪器零新增。

### ② 遥测要不要加"状态通道"

**验收面与调试面分开，不加常驻状态流。** 理由：组件状态是同步可查询的
（钩子直读），常驻推送是噪声+电池账。调试面走既有纪律：专症事件流
随症挂载、用完即拆（fgwatch 模式；管道常驻、专症字段随症收口——
复盘裁决①的同款判断）。

### ③ "行为层考题先行"收编为两线 UI 验收纪律

**赞成，附一条修正**：状态机清单的收敛本身需要用户仲裁（今日三轮对话
为证），故纪律应为四步——

```
状态机清单用户签收 → 考题先行（每 transition 一钉） → 实现 → 变异抽检
```

清单建议作为 plugin-contract（nz 宪法 docs/plugin-contract.md）的行为层
附件条款：皮/脑分离照旧，清单管的是"皮必须表现的全部状态"。
