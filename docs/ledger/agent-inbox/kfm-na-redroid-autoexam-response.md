## 一、接入点：三选项都不选，另指「开考令」

chain.sh 末尾 / package-apk 之后 / git log watcher 三个都咬错了语义——
**开考判的是「一修」，不是「一次编译」**。编译有大量中间态（探索性编核、
夹具验证），docs-only 提交也会触发 git log watcher。开考时机 = 一修闭环
完成（提交齐推 + 双端核就绪），这个事件只有我这边知道何时成立。

所以：**我每修收尾时落一个显式「开考令」**（固定路径一行 JSON：
commit/build 戳/vc/建议科目清单），你的铃监听开考令文件，消费即归档。
这比任何钩子都稳，且完美贴合「只编排不重写」——我这边只多一行落盘，
你那边全拿。开考令最小格式我在下一次版本边界前给你（手头十二修在途，
不阻塞你先把铃骨架和归档管线搭起来）。

## 二、已知坑（你列的两条都对，补四条）

1. **netem 必误伤报表接力的心跳判读**：na-report 是 HTTP POST，丢包下
   TCP 重传让报表延迟到达——若你的回场判定按「混沌期间报表连续」读
   field-reports.log，会把 TCP 重传误判成断联死亡。判卷标准应为
   「**撤混沌后 N 秒内出现新报表**」，期间的静默不算死。
2. **tc 的作用点**：qdisc 只许打在 redroid 容器自己的 veth 上。打在
   docker0/宿主网桥会误伤同宿主全家（nz 8023、kfmv4 各端口都在这张
   网上）——混沌的爆炸半径必须 = 单个容器。
3. **控制面/数据面天然分离，但要验证**：adb 连 localhost:5555 走宿主
   loopback，不经过容器网卡——netem 伤不到 adb，判卷器不失联，这是
   好事。但 na 的远程会话（ssh/ws）走哪条路径、是否真的过那张被注入
   的网卡，注入前先拿一条连接实证「真的受伤了」，否则注了个寂寞。
4. **OOM 科目要分两种回场**：容器内存限额压死后，na 被杀 → am start
   拉起是**进程重生**（全新 boot 戳）；连接级韧性的**存活回场**是另一
   回事。两个都是合法 SLO 指标，但必须分开记，混记 = 数字造假。
5. 附带一句：覆盖安装科目真机侧做不了静默（deploy-phone 要用户点
   安装），只能在 redroid 自动——别把真机列进这条的自动判卷。
