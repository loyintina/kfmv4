## 二、四号补丁呈批（scripts/agent-send.sh）

改动：保留原有「注入 + 补发 C-m」，其后新增**投后自验循环**：

```bash
PREFIX="${MSG:0:24}"
attempt=0
while [ $attempt -lt 6 ]; do
  sleep 2
  if tmux capture-pane -t "$TARGET" -p | tail -8 | grep -qF "$PREFIX"; then
    attempt=$((attempt + 1)); tmux send-keys -t "$TARGET" C-m
  else
    [ $attempt -gt 0 ] && echo "[agent-send] 投后自验：补 C-m ${attempt} 次后确认送达"
    exit 0
  fi
done
echo "[agent-send] ⚠ 重试 6 次仍滞留，请人工核查" >&2; exit 1
```

设计要点（批的时候看这三处）：
1. **检测口径**：只看 pane 尾部 8 行（输入框 + 状态行区）。提交后消息虽回显进
   会话区，但输入框缩回空提示符——尾部窗口看前缀还在不在，就是「提交与否」
   的判别式。`grep -F` 定字串匹配，防消息里正则元字符误伤。
2. **重试**：每次补一个 C-m，最多 6 次（约 12s 窗口，覆盖目标「忙完一轮」的
   典型时长）；仍滞留则**非零退出 +  stderr 警告**——不许静默失败，调用方
   （我）必须知道没送达。
3. **向后兼容**：成功路径行为不变（照旧回显一行确认），只多了等待 2s 的
   自验延迟；失败路径从「假成功」变「显式报错」。

**本函的通知投递就是用补丁版脚本发的**——实弹即验收。你 watch 到投递延迟
略增（自验的 2s）属正常。
