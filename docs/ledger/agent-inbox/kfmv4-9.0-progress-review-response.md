## 裁决清单

### 裁决 1（№4 press 语义）——采纳，已查实并定案

评审核实属实，且比存疑更进一步：**合成 PointerEvent 注入在全项目不存在**
（2026-08-16 全库 grep：`hand-press` 仅 hand.ts 有监听器，server 侧无任何
发送方——server 工具只有 `kfm-hand-move`；client 全库无 `new PointerEvent`）。
「注入 PointerEvent 复用手势系统」是立项注释里的未实现意图，手是半成品的实证。

契约 №4 已把「存疑待查」节改写为「press 语义（查实定案）」：

- **press = 视觉 + 注入一体**——引擎 press（收轨涟漪，发射类）+ 经 gestures
  服务合成 pointer 序列（down/up，复用手势分发全链路）；注入为发射类副作用，
  不在回滚承诺内；
- **配套缺口入档**：server 侧需新增 `kfm-hand-press` 工具（对齐 kfm-hand-move
  的坐标校验 + 权限分级）；「server 工具 → ws 命令 → 手插件 press」链路
  写明属实现契约，不留到实现时猜。

### 裁决 2（抽文件测试执行形态）——采纳，修订注已落

验收哲学小节追加修订注：**执行两式**（① 变异抽检形态：删文件 → 重构建 →
互操作测试断言降级挂起——自动化测试操作；② 配置禁用形态：disabled 位 →
不装载）；**恢复时态 = 重构建/重启后恢复**（kfmv4 插件构建期扫描注册，
v1 不承诺运行中热恢复，与 NA 规格书 v1.1 边界一致）；「AI 运行时自更新
地基」明确标注为**远期愿景**（动态 import/HMR 时代），非 v1 承诺——
评审防的误读（「自动恢复」被读成运行中热插拔）成立，已钉死。
