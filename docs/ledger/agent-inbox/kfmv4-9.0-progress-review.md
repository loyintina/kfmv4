## 一、№4 手——认可（试点契约的高质量示范）

### 认可的三点

1. **三状态归属是最干净的示范**：登记类（ws 订阅/pointer 监听/rAF）逆序摘、
   发射类（canvas 像素）不承诺、数据（位置/尾迹/补间进度）私有草稿随卸载
   蒸发——与议题 3 归属表逐字对应，且「数据：没有」这一格是**最诚实的写法**
   （多数组件会硬塞一格，它承认手没有跨生命周期状态，这正是零负担的证据）。
2. **硬契约点全是血泪入档**：时基唯一（rAF now，2026-08-12 事故）、用户可拖
   （48px 命中核 + 1.5s 回归，2026-08-13 用户定稿）、视觉代理（pointer-events:
   none 不抢 DOM 命中）——三条都有事故/用户拍板出处，是「契约不是愿望」的
   样板。
3. **确定性考题**（同种子同时间序列必同位置，零数值积分）——把「手」从
   观感物变成可判卷对象，这是试点契约该有的样子。

### 存疑待查：press 合成事件——我核实了，存疑正确，落实路径必须写进契约

文档自标「hand.ts 的 press 只画涟漪，合成事件注入不在这 436 行里，大概率在
server 工具侧」——**我核实属实**：`hand.ts` 全文件无 `new PointerEvent`，
第 6/390 行只有注释声称「注入 PointerEvent 复用 gesture-registry」。这是
**契约级缺口**：press 到底是「纯视觉」还是「视觉 + 注入一体」决定契约的
press 语义（后者涉及 gesture-registry 交互链，是发射类 + 副作用，不是画个
涟漪）。**裁决：press 语义必须在写实现契约前落实，落实路径（合成事件从
server 工具注入 vs 客户端 hand 触发）写进契约正文，不得留到实现时猜**。
这也是 №4 手唯一不能「照着 v8 抄」的点——v8 的 press 行为本身不完整。

## 二、抽文件测试——判据化好，但执行形态需澄清

「随机抽掉/禁用任何一个插件文件 → 系统正常 + 依赖者降级挂起 + 放回恢复」
作为验收哲学（不用的干净消失）的判据化，**方向正确**，三要件（依赖未齐=合法
挂起 / 数据不在插件里 / 单插件隔离）与规格书 §4.3 PENDING / §4.1 状态存活 /
§4.4 失败隔离一一对应，且「内核 ctx 不在此列」的边界划得对。

**需澄清一处：对编译期插件，「抽掉文件」的实际执行形态是什么？** kfmv4 是
编译期插件（vision.md §2.3：构建时扫描注册）——「抽掉插件文件」= 删文件 +
重新构建，这是一次变异测试操作，不是运行时操作。两种形态语义不同：

- **变异抽检形态**（删文件 → 重构建 → 跑互操作测试 → 断言降级挂起不崩溃）：
  这是测试，自动化做，对应 NA 规格书 §5 互操作测试的变异抽检；
- **配置禁用形态**（disabled 位 → 不装载）：这是配置级启停，v1 已支持，
  对应「放回后自动恢复」的时态。

**「放回后自动恢复」要写明时态**：对编译期插件，放回文件需要重构建/重启才
生效（不承诺运行中热恢复——与规格书 v1.1「热插拔 = 配置级启停，不是运行中
换」一致）。文档末句「AI 运行时自更新的安全地基」是**远期愿景**（HMR/动态
import 时代），v1 的抽文件测试是「重构建后降级恢复」，两者要说清，否则
「自动恢复」会被误读成运行中热插拔承诺。

## 三、契约 №5 插件包预告——需跟踪，且需补与 NA 的对齐

契约模板已预告「插件包是正式形态（2026-08-16，契约 №5 首立）：单插件 vs
插件包（总插件 + 供稿段，如眼睛/池卡）；四规矩见契约 №5」——**但契约 №5
正文还没写**，「四规矩」悬空。两条：

1. **跟踪项**：契约 №5 正文落定时，契约模板的「见契约 №5」引用才闭合——在这
   之前池卡/眼睛的契约按「单插件形态」评审（它们当前没有 bundle 内容）；
2. **对齐项**：插件包（总插件 + 供稿段）在 NA 规格书是「group 嵌套」——
   paper-digest 不采用清单第 2 条明确「NA 不采用 group（编译期插件清单固定，
   嵌套留待『插件加载插件』场景）」。**kfmv4 的插件包 = 同构于 NA 规格书的
   group，两线对这个机制一个用、一个不用，需写明是端形态差异还是理论分歧**
   ——若 kfmv4 用「总插件 + 供稿段」而 NA 不用，建议参照连接 provider 先例
   （两线分工的有意差异）在契约 №5 里注明对齐关系，别让「9.0 用了 group」
   反噬 NA 规格书的不采用决定。
