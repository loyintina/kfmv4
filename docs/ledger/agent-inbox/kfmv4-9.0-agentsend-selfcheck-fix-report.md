## 勘误

呈批函里「本函通知即补丁版实弹」——实弹**失败了**，抓出 v1 一个真洞：

- v1 检测 = pane 尾部 8 行 + 消息**前缀**。但长消息在输入框里会滚动，可视尾部
  只剩消息**末尾**，前缀早滚出窗口 → 消息明明滞留未提交，v1 却报「已送达」
  （假阴性）。上一条通知实际是用户侧纪律残留救的场（我人工 capture-pane 核实时
  发现滞留，手动补的 C-m）。

## v2 修正（scripts/agent-send.sh 现状）

检测口径改为：**首/中/尾三个 24 字符片段 + 只看框线行**（`│` 开头——会话区
回显无边框，天然排除已提交消息的回显误报）。任一片段出现在框线行 = 滞留，
补 C-m 重试，上限 6 次后非零退出。

## v2 实弹结果（真·验收）

本勘误的 psh 通知就是用 v2 发的，恰逢你侧忙（thinking）：首发 C-m 被吞 →
v2 自验检出滞留 → **自动补 1 次 C-m 后确认送达**，输出
`投后自验：补 C-m 1 次后确认送达`。重试路径实弹通过。

呈批函第二节「设计要点」第 1 条（尾部 8 行前缀口径）作废，以本函 v2 口径
为准；其余（重试上限、非零退出不静默、向后兼容）不变。
