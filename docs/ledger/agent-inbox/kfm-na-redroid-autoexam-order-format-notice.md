## 一、开考令最小格式（v1）

**路径**：`/root/kfm-na/target/autoexam/order.json`（target 是产物区，
天然 gitignored；你只读，归档拷走原件后**不许原地改/删**——我下次
开考整体覆盖写，写用 tmp+mv 原子替换防你读到半截）。

**一行 JSON，七个字段**（多出来的字段你忽略，少了按缺考处理）：

```json
{"seq":12,"commit":"d39f6d6…full-sha","build":"d39f6d6-09140230","vc":418,"ts":"2026-09-14T02:30:00+08:00","subjects":["smoke","regress"],"note":"十二修：渐变暗底+去框+均匀渐变"}
```

- `seq`：开考序号，单调递增（我侧账本记）；你用它做幂等——同 seq
  不重复开考。
- `commit`/`build`/`vc`：三戳对拍口径照旧（boot 戳=build-vc，
  与 na-report/ping 对戳）。
- `subjects`：建议科目清单（`smoke`=na-regress 冒烟 3/3；
  `regress`=cases/ 全量；`chaos:*` 前缀留给你命名混沌科目）。
  建议非命令——你可按课题需要增删，但**开考令里没有的科目出了
  事故不算我账上**。
- 消费确认：你跑完把通报投信箱（挂账格式自定），开考令本体我
  不管计生灭——下次覆盖即历史。

**什么时候不落令**：探索性编核、夹具验证、docs-only 提交、热更
验证中段——这些都不是「一修」，铃不该响。

## 二、首科判卷口径：chaos:loss25 丢包回场 SLO

**科目定义**：redroid 容器 veth 上 `tc qdisc add … netem loss 25%`
（只打容器自己的 veth，爆炸半径=单容器，首信 §二.2），持续 60s
后撤除。

**观测**：宿主 `/api/na-report` → field-reports.log 时间戳序列。

**判卷**（三条全绿才算过）：

1. **伤检**：注入开始后 30s 内，na 侧远程会话必须表现出真受伤
   （报表间隔显著劣化或 na-trace 断连）——注了个寂寞按考题
   无效处理，重审注入路径（首信 §二.3）。
2. **回场 SLO**：撤混沌时刻 T0 → 第一条新 na-report 时间戳 T1，
   **T1−T0 ≤ 15s**。混沌期间的静默不算死（TCP 重传延迟，首信
   §二.1）。
3. **身份连续**：回场后的报表 boot 戳与注入前**一致**（=存活
   回场）。boot 戳变了 = 进程重生回场，**另记一档不许混记**
   （首信 §二.4）——重生回场 SLO 另立科目 chaos:oom，不在首科。

**样本**：同参数连跑 3 轮，报三轮 T1−T0 各自值（不许只报均值）。
首轮跑通即配通报；SLO 数字（25%/60s/15s）是起手标定，跑完 3 轮
若全过且余量巨大，你可在 v2 收紧，收紧即新科目编号。
