## 二、三条漂移候选表态

### #1 scrollback 容量——承认未显式化，按用户拍板落地显式钉值（值维持 1000）

- **现状病灶**：1000 是**三处散写字面量**，无常量、无理由注、无压帽考题——与 na 钉 10000 前同病。
- **落地承诺**（同款 na @ 6ae00c8 三件套）：抽 `SCROLLBACK_LINES = 1000` 常量单源 + 注释注明理由 + 压帽考题（灌超量输出后历史恒 =1000）。
- **值的理由**（「各钉各的+注明理由」裁决的 nz 注）：nz 每行历史 = DOM div+span 节点，千行即千级节点挂在手机 WebView 渲染树里，内存/重排成本随行数线性涨；na 是 GPU 网格渲染，万行成本结构完全不同——**数量级差异是平台成本本征，不是随手不同**。1000 行 ≈ 33 屏翻史深度，手机单手场景够用。跨线体验差异（翻史深度不同）接受为有意分歧。
- 排期：随手可做，挂最近落地窗口（不挡 P2/8.8.4 主线，夹缝落）。

### #2 鼠标报告 SGR 1006——**实现缺失**，非考卷缺失（实锤）

- **全库取证**：`nz/` 全树 grep `1006 / mouseevent / onmouse / ?100[0-3]h`，产品码**零命中**（仅实验区 `experiments/term-core-eval` 语料旁及，非产品路径）。无鼠标上报模式解析（?1000/?1002/?1003/?1006）、无滚轮/点击 SGR 编码、无 DOM 鼠标事件→PTY 字节通路。
- **影响面**：TUI 内鼠标交互（htop 点列头排序、ranger 点击选行）nz 静默不可用——属实。缓冲因素：手机主场景的「滚动」=触摸上滑，由滚动容器接管，不依赖鼠标滚轮上报；实质缺口收窄为 **TUI 内点击定位**一类。
- **定性**：功能缺口（从未实现），非回归、非考卷漏写。
- **修复预期**：登记 TASK 待办。排期建议交用户拍板——nz 主场景是手机触屏，鼠标上报价值密度低于 tmux 窗口（8.8.4/8.8.5），建议挂 tmux 线之后；若未来接桌面浏览器场景则权重上调。
