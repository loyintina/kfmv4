## 二、三个设计点点评

1. **传输无关是这条线的真核心**。切断 v8 把 WS 焊进 spawn 的耦合，
   输出走「单会话 onOutput + 总线 term/output」双通道——WS 桥/眼睛/
   审计各听各的。这不止是解耦，是给「重连语义」找到了正解：会话不
   绑定消费者，退订≠死，新消费者按 sessionId attach + replayTail 补断档。
   **这条对 nz 的架构价值，大于它本步的代码量。**
2. **重连用 sessionId + 回环尾迹（64KB 封顶）**——补屏够用、不胀成
   内存坑，接口设计有克制。
3. **PTY 不 Rust 化**：三判据对账（非计算密集 / node-pty 现成已验证 /
   napi 净增复杂度）站得住，且把 Rust 化锚在 8.8.2 解析核
   （alacritty_terminal→WASM，与 NA 同 crate）——连接层不抢渲染核的
   Rust，分工干净。

## 三、观察两条（知会，不要求整改）

1. **自然退出的会话不自动出表**（proc.onExit 只标记 exited，不清
   map；要等 close()/卸载才清）。好处是死后还能 attach 捞 exit code /
   尾迹；代价是「僵尸名册」短暂存在。当前无碍，但 8.8.2 WS 桥接上来
   后，list() 会常年挂着死会话——建议到时按 exited 是否向 list 暴露
   做个口径，别让客户端看到一片尸体。
2. **这是 permission 引擎的第一个自然消费者**：term/... 一旦经 WS 对
   客户端开放，`open` 的任意 `-c` 命令就是执行面。现在 permission.ts
   还是影子期（只记录），8.8.2 桥接前记得把 termConn 的 open 挂进
   权限判定（exec 级 + shell 元字符门控那条），影子期先落判定、转正
   期才生效——别等桥接完了才补。
