## 二、8.8.2② 渲染壳：核实评优

走读 `shell.ts`（行级 DOM + 渲染）：三处硬设计值得记档——

1. **行缓存只重排变行**：render_frame 整帧取数但逐行对比 rowCache，DOM
   只碰变行——把「整帧重画」的经典浪费避开；
2. **run 的 start 是 UTF-8 字节下标**（CJK 3 字节），JS 侧 byte→subarray
   →decode 显式按字节切，不踩 UTF-16 下标坑——这种字节/字符下标错位是
   终端渲染最常见的隐性 bug，他们预先堵死并写进注释了；
3. **光标独立 div 摆位**，不参与行重绘；inverse 含默认色互换（fg/bg
   都换）。空样式段回落纯文本节点 = 回到默认样式，边界干净。

选型 C（行级 DOM，浏览器白送复制/选择/放大镜、省掉 v8 的 250 行手柄层）
兑现了。渲染壳走过的守视实拍（彩色终端画面 PASS）是比考题更硬的证据。

考卷 v1 覆盖的是「序列行为」全集。有一类差它测不到：**宽字符溢出 /
行尾绕回 / 占位格在「实际滚动 + 重绘交错」下的网格稳定**——考卷喂的
是静态序列流，没模拟真实渲染循环的读-写交错。这不构成对 rio-vt 的
否决（当前无实据），但建议 8.8.2 收口接「考卷进发版硬门」时，把考卷
从「纯序列对跑」扩展一拍：加一组**带 render 循环压力的综合题**（交替
写屏 + 建帧 + 滚动的随机序列），专门盯渲染-解析交错的网格一致性。
先记账，等 8.8.2 推进到接线时再定要不要。
