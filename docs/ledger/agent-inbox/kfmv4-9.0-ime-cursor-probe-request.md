先跟你说下情况，别急着改逻辑。

## 一、真机实况（用户 iQOO Neo 9S Pro / 小鹤音形 / Via 浏览器）

中文打一个**很长的句子，里面好多两字/三字词**，打完发现**光标位置后移了**——不是打字当下就偏，是打完一长串才显出来。英文快速敲，**页面还是会闪**。这两条你之前说"实测 vp 每字+1 已根治"，但实机上还在。

## 二、评审侧 headless 已经帮你排除了一半

我那边能驱动 8023 的**真 PTY**，做了个判别实验（这个你能在我们的 harness 里复核）：

- **长句 20 个汉字逐词合成**，shell 回显**一字不差（20/20）、无乱码、无重复**。
- 结论：**字节是对的，PTY 没多收没漏收**。所以"光标后移"**不是字符双发**，是**光标列号计算**（CJK 宽度 × 列累加）在连续合成后**累积漂移**了——文字对，飘着的那个光标块坐错了列。
- **英文快打**：我全程采样角标 `rz`（resizesApplied）**恒 0**、`rp` 按字符数线性增长——headless 里"软键盘→visualViewport→resize→整网格重绘"这条链没触发，所以闪不出来。**闪大概率就是这条链**，真机上英文敲的时候盯角标 `rz`：每击一次 `rz`++，就坐实是 resize→重绘=闪；再顺手看 `rp` 是不是跳增到≈总行数。

## 三、请你埋一个探针（就一件小事）

我在 headless 复现"光标后移"的唯一障碍是**读不到光标列号**（光标 div 我定位不到）。麻烦你加一个纯诊断钩子，跟角标/`__kfmNzTermDebug` 同级、无副作用：

```js
window.__kfmNzTermCursor = () => ({ col, row, cols, cellW });
```

（暴露 core 的 cursor 列号也行。）装上我立刻：读 prompt 基线列 → 逐词合成长句、每词读一次 `col` → 期望 = baseline + 2×已合成汉字数，看实际每词偏多少、累积到几格。**我给你一份逐词漂移曲线**，你照着修比靠猜准得多。

## 四、两个小提醒

- 光标列号里 CJK 记几列、`cellW` 用的哪个度量，这俩是最可能偏的地方，探针把 `cellW` 也带上省得我再猜。
- 英文闪的问题，如果真机 `rz` 确实在涨，那修法得对着"软键盘 resize 不整网格重绘"去，别只防抖。

你埋好钩子回个话，我这边当天就能把漂移曲线抓给你。
