## 裁决 1（方案 A/B 分叉）——批准方案 A，两道旧题迁移明示批准

**批准方案 A**（修饰键状态进 `input.modifiers` 服务，`static MODS` 删除），
理由三条：

1. **§4.5 全合规**：共享可变状态必须挂服务键，`static MODS` 是规格书点名要
   消灭的进程级静态（§4.5 共享态纪律）。方案 B 的「明示例外」是**还债拖延**
   ——它今天省两道考题迁移，代价是渲染层读全局静态的耦合留在原地，下次动
   keybar 时这笔账还在（设计页自己点破了这一点）。
2. **演化纪律允许**：TermEmu trait 签名变更（render_keybar 吃 mods 参数）正是
   「调用方驱动的变更」——trait 方法面 = android_app 现调集合的推论，§4.5
   是正当理由，不违反「方法面零增删」的演化纪律（那是给无调用方先例的新增
   方法设的门，这是有调用方先例的签名调整）。
3. **连带收益**：render_keybar 从「自读静态」变「参数传入」，**解掉了终端插件
   方法体内读全局静态的耦合**——否则终端插件一落地就带着一个全局静态依赖，
   与插件化方向相违。

**两道旧题迁移明示批准**：`keybar_spec::spec_修饰键_一次性粘滞` 断言原样搬
到 ModifierState 实例、`termview_spec::spec_快捷键行_渲染冒烟` 改传 mods 参数
——断言一字不改、只换具身，判卷语义不变。这是「旧题一题不动」纪律的第一个
正当例外，**例外本身要入档**（落地通报的基线记录里写明「哪两道迁移、断言
未改」），否则下次「动旧题」会拿这次当默认。

## 裁决 2（共享实例直挂 = 第三种合法形态）——认可

**认可**。「工厂必然性」的论证反过来恰好支持不用工厂：前两刀需要工厂是因为
实例是 `&mut` 独占可变（registry 的 Arc 共享语义装不下）；本域两个服务都是
Sync 内部可变（AtomicU8 / Mutex），共享即正确形态，Arc 语义天然合身——**三种
形态（工厂 / 直挂 / 胶水不进插件）的分野是「可变性形状」，不是「这个域想不想
插件化」**。建议规格书 §4.2 补一句形态判别准则（独占可变→工厂；Sync 共享→
直挂；进程静态入口→胶水不进插件），让后续域照判别不照先例。

## 裁决 3（ime_queue 不进插件）——认可

**认可**。JNI extern fn 是进程静态入口，Java 侧随时可回调，回调线程没有 ctx
拿不到基座——它不是「服务」是「桥端点」，与 report.rs 同性质。定性 B 档平台
胶水正确。**一个边界注记**：ime_queue 虽是胶水不进插件，但它的**行为契约**
（push 缓存语义、drain 后 keymap 翻译）已被 ime_queue 7 道考题钉住——胶水
≠ 无考题，这条已满足（7 道不动）。

## 裁决 4（JniInsets 句柄走构造注入）——认可

**认可**。「什么配进 config schema」的边界定义正确：config 表是启动静态配置值
（url/command 是值），AndroidApp 句柄是运行时对象——塞进配置表语义错位
（配置表里放一个运行时指针，序列化/比较/重载全是坑）。构造注入 + 注入缝
（`InputIme::new(insets: Arc<dyn ImeInsets>)`）与前两刀注入缝同族，是**第三种
注入形态**（构造函数注入，区别于 conn 的 Spawner 缝和 term 的 candidates 缝）
——同一「注入缝」纪律在不同形态下的复用，好。

## 裁决 5（连续第三刀零总线事件）——认可

**认可，且这不是「不为用而用」的消极**——BAR-006 实锤是积极证据：本机
Ime::Enabled/Disabled 从未触发，事件驱动在这条设备链路上是死路，轮询才是
活路（已修复且 C 档实拍判卷）。「总线第一个真实用户留给第二批插件」正确：
**总线的价值要等有真实消费者（卡片堆/AI 会话）时才成立，为一个没消费者的
事件建派发模式是空转**。与裁决 1 先例（连接 provider「事件零总线」）同构。

## 附带发现（2 条，非阻塞）

1. **规格书 §4.2 补形态判别准则**（见裁决 2）：三形态分野 = 可变性形状，值得
   写进规格书让后续域照判别不照先例——建议走规格书修订记录追加。
2. **方案 A 落地时的一个顺序细节**：两道旧题迁移要和考题先行同步做（设计页
   附录第 2 步已列「方案 A 获批则同步迁移」）——确认执行顺序：先迁移旧题

   迁移与新增分开验证，别混在一次跑里。
