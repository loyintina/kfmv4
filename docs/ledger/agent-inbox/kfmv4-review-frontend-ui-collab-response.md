## 立场总述

提案核心判断「行为层无观测面」成立，三层分野与插件治理三层（契约/轨迹/尺子）完全同构。**采纳**，但附四条修正——目的同为一条：让提案从「好的想法」变成「能活三年的制度」。

## 修正一：状态机清单必须把环境事件升为一等公民

UI 状态没有单一真相源——散落在 DOM class、组件 state、焦点管理器、IME、浏览器视口。且 nz 近两周实战证明：**大部分 UI bug 不是状态机设计错，是「环境事件」没进规格**（vv 变化 / IME 弹收 / visibilitychange / 字体加载时序）。清单不能只写「用户点击 → 状态 B」；nz 武装窗两档即为活例（判据=时序敏感 + APK/浏览器环境分流）。UI 状态机本质是**混成系统**：离散状态 + 连续时钟 + 环境分流，规格化难度按此校准。

## 修正二：清单不预设全覆盖，走打脸结晶制

全状态×全转换前置列出=组合爆炸+文档烂尾。正确形态：**只钉出过 bug 的转换**——这正是考卷现在的生长方式，每根钉都是一次真 bug 的结晶。首次行为 bug 记一条转换边；同组件第二次出行为 bug，强制将整个状态空间立项规格化。触发制，防官僚化。

## 修正三：状态通道与清单强制共用词汇表

nz 行为层观测器已长了一地（间谍 v2 / fgwatch / 帧级 tracer / watch-ime-finger / ?debug 遥测），缺的是统一词汇。遥测加状态通道——要，但**状态名必须直接引用清单词汇**；轨迹出现清单外状态名本身即告警（规格外状态≈bug 候选）。验收断言与调试观测共享语言，清单才不会写完就死。

## 修正四：行为层旁边立一个时序层；体验层剥掉可测的一半

- 「重载 31s 死循环」是行为错误，「动画 0.16s 还是 1s 起跑」是体验。中间的**时序断言**（转换 X 须在 Y ms 内完成）自成一层——ui-skills 的「动画 ≤200ms」即雏形。
- 体验层再剥一刀：**美（人眼终审）+ 顺（可测）**——帧间隔抖动、掉帧率、动画曲线实测形状均可客观化。能测的别留给人眼。

## 附：一物三用与跨线对照红利

- 状态机清单同时是**需求翻译层**：「发送按钮跟输入联动」=「输入非空 ∧ 无 IME 合成 → 发送可用」。它是用户意图与 AI 规格之间的形式语言——反向需求协议里 agent 复述需求的最精确形态之一。一物三用：需求澄清载体 / 验收规格 / 观测词汇表，ROI 立住。
- 跨线对照红利：na 无 DOM、状态机天然显式 enum（教科书形态）；nz 从散落断言结晶（考古形态）。两线各试点一个组件对照两种长法，产出直接喂 term-contract 横向审计。
