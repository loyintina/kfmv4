## 一、背景（用户真机实测，已钉死）

brt/brb + 逐帧实锤：Via 在"有栏+键盘"态 `vv.height` 多报 ~42px（bar bottom=226=vv.height，真实键盘顶=184=226−42）→ **bar 低 42px，下排被盖**。这是 Via 品牌特有的 vv 测量差，非 9.0 实现错。用户拍板：**做专项适配，但用可调的 URL 代字，不硬编码 Via 死值**。

## 二、方案：`?kbOff=<px>` 代字（像 ?debug 一样是 URL 参数）

1. **页面带 `?kbOff=<px>`** → **keybar 底定位 = vv 底 − kbOff**（bar 上移 kbOff 像素），让 bar 底落到**真实键盘顶**（下排不再被盖）。
2. **用户在 Via 浏览器**（书签/桌面链接）加 `?kbOff=42`（或其它值）→ 生效；**试 40/42/44 看哪值下排刚好露对**，改链接即改行为，**不用改代码**。
3. **无该参数 = 现状不改**（其他浏览器/默认不受影响——正如用户所说"其他浏览器不用做"）。
4. **?debug 标命中**：报 `kbOff: <n>`（实际用的值）——真机确认走没走对，避免测旧包/没进分支。

## 三、为什么用代字而非硬编码 Via

- **你实测调值**（kbOff 是你查出的标尺，不是 9.0 背的死 42——Via 品牌/系统/字体不同，42 可能需微调）；
- **可复现可测**——改链接即改行为，逐帧验证；
- **真机可调**——用户可控，不用每次找 9.0 改码。

## 四、验收 / 落地

- 9.0：加 `?kbOff=<px>` 解析 + keybar 底修正 + ?debug 报 kbOff；
- 用户：Via 链接加 `?kbOff=<值>`，真机逐帧调到位（下排不被盖），把**最终值**告知回函；
- 修好后：kbOff 命中（?debug）+ 逐帧下排不盖 = 收口；双轨/brt 等专症字段随症拆。

## 备注

本案为"浏览器 vv 测量差"真机专属。**教训**：vv/style 公式会骗人（我多轮翻车），**真机逐帧 + 实测 rect（brt/brb）才是判据**；而应对"品牌特有测量差"，**用户可调代字（?kbOff）比代码硬编码稳健**——用户是最终标尺。
