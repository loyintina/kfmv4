# 通报（补充）：开机序列三段闪修复——逐帧实录定罪，DOM 断言≠画面

- 日期：2026-08-30
- 发起：dsh（kfmv4-9.0/nz 线）
- 类型：自验收通报（接 kfmv4-9.0-splash-boot-chain-report.md 的修正轮）
- 触发：用户实拍开机序列「比较长的黑屏→闪烁到一个渲染好的终端页面
  （上面有字符版本的标志）→马上跳到动画→马上进入完整终端」，并质问
  「你确实能接收到画面渲染的过程吗」

## 一、诚实检讨

上一轮验收用的是 DOM 类状态断言（`.on/.out` 时序全对、6/6 绿）——
状态机对，但**画面观感从没被验证过**。用户的质问成立：观感问题的
验收判据必须是逐帧画面，不是类状态。

## 二、观测与定罪

- 真机 CDP `Page.startScreencast` 0 帧（WebView 后台不出帧）、截图
  0 宽——设备后台时像素级观测不可用，改 headless 150ms×40 连拍实录
  （同一份代码路径，阶段序列一致）。
- 实录定罪三处：
  1. **静态小钻标先闪**：showFb 的 FALLBACK_ART（9 行小菱形）与真徽标
     （19×27 双环孤瞳）形状完全不同，本体就绪后被抹掉=第一段闪；
  2. **T0=1000ms 死黑**：v14f 为手动重播拍的「延迟 1s 动线」仪式感，
     在开机时序里是纯等待=用户说的「比较长的黑屏」的主体；
  3. **两截深色色差**：body `#101014` vs 覆层 `#05070f`。
- 另发现隐性坑：覆层 CSS 全部来自本体 ensureStyle()——本体加载前覆层
  无样式，静态徽标浮在裸容器上（透明底）。

## 三、修复（三处，均小改）

1. splash-core v15：`T0` 常量变实例变量 + `show({noDelay:true})` 跳过
   1s 黑场（开机路径用；手动 ?splash/CDP 重播保留仪式感；`render(t)`
   冻结帧恒基准，自验收确定性不变）。
2. 壳开机路径纯暗场盖屏：pre 清空不出 FALLBACK_ART；FALLBACK_CSS 主
   挂载即常驻（管底色/显隐，dispose 摘除）；只有本体加载失败才回退
   静态徽标帧。
3. index.html body 底色 `#101014→#05070f` 对齐覆层。

## 四、复验

- 修后逐帧实录序列：**暗场（扫线即起）→ 完整徽标定帧 → 渐隐融合 →
  干净终端**，全程 ~1.5s（headless 暖启动），三段闪全消除。
- 五卷 + npm 90 + 真机 boot-verify 6/6 + plugtest PLUGTEST_OK 零泄漏
  + typecheck + build 全绿（结果见本轮提交前的复跑日志）。

## 五、方法库候选

- 「DOM 类状态断言 ≠ 画面」：观感类验收必须逐帧实录（screencast/连拍），
  状态机绿只是必要条件。
- WebView 后台时 screencast/截图不可用（0 帧/0 宽）——设备后台期
  像素观测要降级为 headless 同码路径实录 + DOM 探针，并声明边界。
- 「观测行为本身会污染观测」：后台 WebView 的 screenshot 会挂起到
  30s 超时——截图绝不能放在轮询断言环里（会把时序断言污染成 ~31s
  假红，连钓两轮）。截图挪出环后连跑两轮 6/6（offAt 1.7s，reloaded
  探针证无 reload）。稳态 40s 长探针（pageT 单调/ff 恒定/无复活）
  进一步证明页面侧无 bug。
