## 总复

这是 9.0 迄今最重大的决策，而三方的收敛出奇地一致。**采用的理由不是「省事」，
是「自研 = 重新实现一个我们每份契约都在引用的库」**（9.0 线语）——这个洞察
在三线独立成立：卡萝从证据链、9.0 从契约溯源、茉莉从 v8 血泪，殊途同归。
评审的「机制可买、纪律自长」获两线全收，且茉莉补了更重的一锤：**没有边界的
纪律靠人肉钉子钉，钉不完的**（L4 四连坑的 compactToken 双解析器是活标本）——
纪律需要机制撑腰，这正是采用最坚实的理由。

## 裁决 1（大决策：采用 Cordis 本体）——通过

9.0 web 端内核采用 Cordis 本体，自研收窄为渲染宿主 + 手势分发。
台账「内核 ctx 基座（新建）」行改为「采用 Cordis 本体 + 渲染宿主/手势分发自研」。

**附加裁决（纪律不外包）**：采用不改变 9.0 契约体系的地位——Cordis 提供机制
（fiber/effect/派发），9.0 提供纪律（契约模板 / 三状态归属 / 考题先行 / 卸载
遗言 / 性能硬指标）。契约体系从「实现内核」变为「在 Cordis 上约束用法」，
此转变显式记账（见裁决 6）。茉莉背书：**采用后卡片=插件，「一切皆卡片」
（宪法第五条）第一次有了机制底座**——这条记入采用决策的决策史。

## 裁决 2（版本来源）——(c) 上游直装 + 按需移植，全票通过

分工明确：**18 条 dsh 强化评估 = 卡萝主笔 + 9.0 会签**（移植必要性的判据 =
契约语义是否需要）；**茉莉补维护者验收**：移植的强化若改变 ctx 语义的任何
可观察行为，**现有测试基线（576 个）必须全绿**——不只看新考题。

## 裁决 3（rc 版本风险）——锁版本 + 升级契约化

- **锁版本**：`cordis@4.0.0-rc.7` 固定，进 lockfile；
- **升级契约化**：升级评估归 9.0 线（拥有契约），回归判据 = 考题全绿 +
  试点三件套契约测试 **+ 现有测试基线不许降**（茉莉补，不只新考题）；
- 跟随上游是持续工程不是一次性 vendor 决策——升级节奏、评估人、回归钉
  全部写进采用落地记录，不许「凭感觉升级」。

## 裁决 4（契约修订注）——总注 + 差异注，采纳 9.0 线方案

**不逐契约加「对齐 Cordis」注**（11 处文书 churn，契约本实现无关），改为：

1. preface 加**一条总拍板**：内核采用 Cordis 本体 + 语义映射表
   （9.0 契约术语 ↔ Cordis API 对应）；
2. **只在真实差异处逐契约加注**——目前唯一预见：**卸载遗言**（9.0 发明，
   Cordis 无此概念）。差异注 > 对齐注。
3. **契约优先原则**（评审讨论区④）：冲突时 Cordis 能力补契约，或契约修订注
   记录差异，**不反让 Cordis 语义改写契约**——9.0 纪律是宪法，Cordis 是承载。

## 裁决 5（试点路径）——直接跑 Cordis，步 0 三层验证（扩展为四项）

直接试点认可（三件套变量从「自研内核是否成立」变「在 Cordis 上写插件是否
成立」）。**步 0 验证从评审③的 esbuild 最小验证扩展为四项**（吸收两线增量）：

1. **esbuild 最小验证**（评审③）：kfmv4 构建管线实跑 cordis ctx + 注册/注销
   效果，浏览器跑通——dsh 的 client 构建链 ≠ kfmv4 esbuild，此验证必须先行；
2. **移动端指标**（9.0 线补）：cordis core bundle 体积、运行时分配率（GC
   压力）、启动耗时——手机优先项目，发热治理是血泪史，过不了这关 (c) 的
   移植量估计就是空中楼阁；
3. **隐式全局普查**（茉莉补，**最重要的工作量下限信号**）：grep 全部
   `window.__kfm*` 与模块级可变单例（`__anim` / `__gestureRegistry` /
   `KFMState` / `__kfmSessionStore` / `__kfmLastCompact`…），逐个定性
   （该成效果的成效果、该删的删）——这是迁移工作量的真实下限，比 18 条
   强化评估更早暴露体量；
4. **E4 自研件最严验收**（茉莉补）：渲染宿主/手势分发是 v8 血泪最厚处，
   契约测试除行为等价外必须带具体数字——滑动 60 帧掉帧率上限、连续拖拽
   30 秒内存增量上限（泄漏是复发的头牌）、pointercancel 风暴下事件完整性。

## 裁决 6（军规记账）——新增「依赖引入（lib 层）」归宿类型

- **9.0 线澄清采纳**：36,012 行基线不受影响——军规管的是 **v8 旧代码的归宿**，
  采用 Cordis 改变的是**新建代码的来源**，不是旧代码的归宿；
- 台账加一行：归宿类型新增「**依赖引入（lib 层）**」，注明锁版本、升级评估
  归 9.0 线、考题不减少；
- **考题不因采用而减少**，反而可能因上游语义差异而增加（契约优先原则的
  必然推论）。

## 附加采纳（讨论区两条超出原评审问题的增量）

1. **隐式全局普查作为步 0 独立任务**（茉莉，已并入裁决 5-3）——它的产出
   （隐式全局清单 + 逐个定性）本身是台账军规的补充材料，与 36,012 行基线的
   「模块级可变单例」类别直接衔接；
2. **server/client 各侧独立采用，不为对称而对称**（9.0 线提醒）——SSE 边界
   是 kfmv4 的，两侧插件集合不同构（server=工具/数据服务，client=卡/布局），
   v1 各侧独立采用，对称是未来优化不是 v1 目标。**采纳为采用落地的一条边界**。
