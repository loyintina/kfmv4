## 一、背景（用户实拍 + 拍板）

用户：**无代字（?kbOff/无参数）时进入页面、输入内容 → 正在打的命令行滚动消失**（被输出顶出视野）。这是"输入行不固定"的 bug。用户提议并拍板：**换成"固定底部输入行"模式**——输入行始终钉在底、内容从下往上滚、光标始终在底行、键盘弹起整行同步上移（移动端终端标准做法，Warp/iTerm2/fish 同款）。`?kbOff` 只是碰巧掩盖了此问题，不是根解。

## 二、设计：终端拆两区（用户拍板）

```
┌──────────────────────┐
│  滚动区（历史/输出）      │ ← 可上滑翻历史（scrollback，复用 8.8.3c）
├──────────────────────┤
│  固定输入行（命令行）    │ ← 始终钉底，光标在此，键盘弹起整行上移
└──────────────────────┘
```
- **PTY 输出** → 滚动区（历史），输入行不动；
- **prompt/当前输入行** → 固定输入行（底），光标永远在；
- **键盘弹起** → 固定输入行随 vv 高度同步上移（IME 合成中不滚焦、落字才回底）。

## 三、验收标准（考题先行，我已立）

**A 档** `nz/tests/browser/fixed-input-row.test.mjs`（RED→实现→绿）：
1. **输入行始终在底/可见（核心，锁"命令行不消失"）**——灌输出+打字后输入行 `getBoundingClientRect().bottom ≈ 视口底`；
2. **输出只进滚动区、输入行不动**——灌大量输出，输入行 bottom 不变；
3. **滚动区可滚/跟底**——复用 `__kfmNzTermScroll()` 契约（上滑历史 + 新输出跟底/不拽回）；
4. **键盘/IME 同步**——vv 高度变小（模拟键盘占位）→ 输入行 bottom 相应上移（更小）。

**B 档**：千行输出冒烟，输入行仍钉底。
**C 档（守视/真机）**：上滑 + 键盘弹起，**输入行始终钉底 + 光标在底行**——守视截图逐帧验证。

## 四、钩子契约（9.0 必须暴露）

```js
window.__kfmNzTermInputRow() → { top, bottom, height, isAtBottom }   // 固定输入行 rect
window.__kfmNzTermScroll()   → 滚动区（scrollTop/scrollHeight/isAtBottom，复用 8.8.3c）
```

## 五、实现纪律

- 输入行**始终钉底**（bottom 恒=视口底，除非键盘占位则上移）；isAtBottom=光标在输入行；
- **输出绝不挪动输入行**（只进滚动区）；
- 滚动区**跟底/不拽回/可翻历史**（8.8.3c 状态机复用）；
- **IME**：合成中不滚焦、落字才回底（输入行天然固定，回底=输入行仍在底）。

## 六、与 8.8.3c 关系

不冲突：滚动区那套标准（scrollback.test.mjs 5/5）**保留复用**；新模式=再加"固定输入行"这一层 + 新断言（fixed-input-row.test.mjs）。**两者叠加成完整终端体验。**

## 备注

这模式顺带**让"输入回底"天然成立**（输入行恒在底），且**躲开 ?kbOff 的碰巧掩盖**——是根治"命令行消失"的正确解。评审据此验收：A 档全绿 + C 档守视过 = 一遍过。
