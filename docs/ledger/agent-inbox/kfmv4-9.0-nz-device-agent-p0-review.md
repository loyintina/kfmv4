## 一、背景（为何是 P0）

nz 实验台（device-agent）已定为最高优先（nz/TASK.md §0.5，用户拍板）。实验台核心三件=**真机渲染截图 + 注入输入 + 读状态**。截图靠 WebView 捕获；但**注入输入、读状态必须终端侧有钩子**——这是设备代理「能动手 + 能读懂」的前提，是依赖链最上游。P0 不打通，APK(P1)/闸门(P2) 无从接。

## 二、请 9.0 加两钩子

1. **`window.__kfmNzTermInject(str)`**：把一段字符串喂进终端**现有的输入管线**（与 kb 按键/IME 上屏同一条路），让 shell 收到；`\r`=回车；**不得绕过现有输入纪律**（IME 合成中不回底、落字才回底、粘滞修饰等——跟 `bridge.input` 同一语义）。返回可空。
2. **`window.__kfmNzTermScreen()`**：返回**当前可视屏**的**纯文本**（可见行拼接，含首行提示符），与 `__kfmNzTermScroll` 的几何/同源一致（读同一终端状态，不建副本）。

## 三、可并列扩展铁律（写死，后补零返工）

- **走同一数据源/管线**：`Inject` 接「现有输入管线」、`Screen` 读「现有终端状态」——**不做独立副本**，否则后补会分叉。
- **接口可并列加**：每个能力是**独立、附加的钩子**——现在先做 `Inject(str)`(整字) + `Screen()`(文本)；将来 `InjectKey({key,ctrl})` / `InjectRaw(bytes)`、`ScreenGrid()` / `ScreenAt(r,c)` 作为**并列入口/出口**直接加，**不改动这版**。请 9.0 在实现时给这两钩子留出「按相同模式接着加」的空间（命名、返回结构对齐，不要用一次性写法堵死后继）。

## 四、验收

- **headless 可测（A 档小考卷）**：`Inject('echo 中文测试\r')` → shell 回显「中文测试」（终端响应）；`Screen()` → 返回含该输出/提示符的当前可视屏文本；两钩子在 `?debug` 下可被外部读取。
- 三卷（bottom-anchor 10/10 + scrollback 5/5 + keybar 19/19）+ npm85 不回退；无 `__kfmNzTerm*` 命名冲突。
- 语义：Inject 走现有管线（IME/回底纪律不破坏）；Screen 与 `__kfmNzTermScroll` 同源、不重复状态。

## 五、备注

- 这两钩子是「nz 终端可编程化」的一环：注入/读屏对**自动化测试、headless 校准**同样值钱，不只服务实验台。
- 实验台后续 P1-P4（wry 壳/文件闸门/report 遥测/插件热更自重启/启动器化）在此 P0 之后按序推进——P0 是它们的共同地基。
