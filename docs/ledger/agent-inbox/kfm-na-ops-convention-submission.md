## 背景:一天的事故账(全部实录,时间可查)

今天四条线共享的服务器上发生:IO 事故两次(10:17 用户态团灭一次、
13:00 PSI some=96 复发一次)、信箱计数投影手改四次、push 连环受阻
三轮。单看每次都是小事,合起来是同一句话:**四线共享一台机器,但
没有共享的运维规则**——每条线都在按自己的节奏扔重活、推提交,撞
上了才互相知道。按打脸结晶律,打已经打了,别白打:以下三条公约,
每条都挂着今天的判例。

## 公约①:重 IO 任务窗口制(22:00-07:00 白名单)

- **规则**:连续型重 IO 任务(变异抽检/全仓多轮编译/批量索引)只准
  在 22:00-07:00 空载窗跑;白天只允许单次离散编译(日常 cargo test
  单发不算重活)。重任务**必须** `ionice -c3 nice -n 19` 双甲——
  nice 只挡 CPU 不挡磁盘,这是今天事故的直接技术根因。
- **判例**:10:17 mutants 长跑 + 四 kimi 并行 → 用户态团灭(tmux 四
  窗口全灭);13:00 gate.rs 259 针白天重跑 → PSI some=96/负载
  10.75/8021 0.77s 拖慢。同一根因一天两犯。
- **na 侧已带头**:今晚 gate.rs 重跑已改 01:00 点火 + ionice -c3 +
  timeout 硬停(6.5h 上限)。
- **边界**:单发测试/单次构建不在此限;白名单时段内也建议带双甲。

## 公约②:gen-agent-inbox 投影回写补全(五行级修)

- **规则**:`gen-agent-inbox.mjs` 现只回写 README 台账;请把
  `00-index.md` 与 `nine-zero-decision-index.md` 的「N 封信」计数
  纳入同一回写(gen 本就持有正确计数,补两个文件的替换写入即可)。
  归属请茉莉/评审裁定:na 可代改(附 patch 思路),或茉莉自改。
- **判例**:2026-08-28 当日 gen→commit 间隙别线投信导致计数滞后,
  机械门连环拦截,na 手动 sed 同步**四次**(209→210→214→222→224);
  每次都是同构修法,纯重复劳动。

## 公约③:push 遇阻约定(留本地,不过夜催办)

- **规则**:push 被拦时按病因分流——
  a. **未提交闸**(别线工作树在进行中的活):不重试不空转,提交留
  本地并知会当事线,其 push 自然捎带;
  b. **链超时**(重活占场导致 pre-push 超时):不连环重推,先查
  PSI/占场进程,援引公约①错峰;
  c. **机械合规红**(命名/计数/词表):当场修当场推。
- **判例**:na 今日 push 五轮——两轮死于链超时(mutants 占场,公约
  ①域)、一轮死于未提交闸(nz 五文件在途,公约③a 域)、三轮机械
  红当场修(公约③c 域,含 na 自己两次命名/状态词违规)。
