# 测试/验证方法库（test-methods）

> 定位：评审/验证线的方法工具箱 + 案例账本。方法按「判卷分类」归档；案例 append-only。
> 谁在用：评审会话 + 各线在"验证某件事"时查阅；未来持续累积。
> 原则（2026-08-23 IME 复盘立）：
>   **先按目标类别选匹配的方法 → 方法不行就换下一个 → 直到所有已记录方法都不行，
>   才说明遇到了需要"新方法"的真问题**（记为新案例 + 标「需新方法」）。

## 判卷分类 → 方法映射（A/B/C）

| 分类 | 判定对象 | 用哪种方法 |
|---|---|---|
| **A 逻辑可测** | 纯逻辑（协议/解析/网格/状态机） | 自动化断言（考题先行：先写红测再写答案 + 变异抽检） |
| **B 胶水/平台** | 系统让不让活（Manifest/wgpu/生命周期） | 冒烟钉（防退化） |
| **C 感官** | 视觉/手感（渲染对齐/是否出现/闪烁） | **守视截图 / 实拍判卷 / 人眼** |

⚠️ **红线（复盘最大教训）**：别拿 **A 类量化工具**（DOM 几何/像素统计/数值）去判 **C 类感官问题**，
然后因测不出就宣布"不可测"——那等于 **拿量尺量颜色，然后说颜色没法量**。类别不匹配是
**「换方法」的信号，不是「不可测」的信号**。

## 回退协议（机械执行）

```
1. 按目标分类，先选【匹配类别】的方法；
2. 若该方法不行 → 换下一个（别吊死在"不行的方法"上反复试同一变体）；
3. 若【所有已记录方法】都不行 → 记「需新方法」案例，写清"卡在哪、试了哪些、缺什么
   观测力"，而不是简单判"不可测"。
```

**边界别过度泛化**：一个方法的限制只在其适用域内成立。例：headless 字体 ≠ 手机字体，
只说明"像素级字形比对"不可靠；但若目标是**格网对齐**（光标在固定 `col×cellW`、CJK 裁进 2 格），
这是**字体无关**的——守视截图就能判，不必因"字体不同"而放弃整类验证。
