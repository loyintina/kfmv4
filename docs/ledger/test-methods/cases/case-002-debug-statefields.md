# case-002：双光标 + 英文抖动——headless 全堵 → 真机 ?debug 状态字段黑匣子实锤

> 日期：2026-08-23
> 目标：验证/定位「开 tmux 双光标」+「英文快打抖动」（均 C 类感官/渲染，headless 测不到）。
> 结论：双双铁证（真机内部状态数字），headless 无法替代。

## 经过（方法试错链）

1. **headless 复现（A 类）**——双光标：headless 起 tmux 输入弹回外层 bash，截图只见一个
   光标；抖动：终端 DOM 不可滚动（scrollHeight==clientHeight），scrollTop 恒 0。**全堵**。
2. **headless 定量（A 类）**——scrollTop 振荡、光标计数，都够不着。**仍是堵**。
3. **改真机上报（A/C 桥）**——请 9.0 在 `?debug` 加状态字段：`col/row`（光标历史）、
   `f/rp/sc`（帧/重绘/滚动计数）、`cb`（光标块清单）。用户真机打三轮，app **主动上报**到
   `/tmp/nz-ime-events.log`（走现有网络，**不依赖 WiFi/无线调试**）。

## 实锤结果（真机数字）

- **双光标**：43 条事件 `cb` 长度 2，`kind` = `["shell","inverse"]`，两块**相距 1 格**：
  `[{"col":5,"row":60,"kind":"shell"},{"col":6,"row":60,"kind":"inverse"}]`。
  → app 把 **inverse（反显）区域当成第二个光标块**，与真光标并排。
- **英文抖动**：累计 `sc`（滚动）0→186（86 次滚动，几乎每次 keydown/input +1）、
  `rp`（重绘）66→17153（爆）。→ **打字本身触发滚动 + 整屏重绘**；"砍滚到底"只修了
  resize 链，打字引发的滚动画是另一条路径。

## 教训（对该案例的回退协议）

1. **headless A 类手段够不着「核心层内部状态」**（DOM 不滚、tmux 不持久、字体/渲染不同）。
   这不是"不可测"，是**缺观测力**——按回退协议，正是该**换/加观测手段**的信号。
2. **「让被测方上报内部状态」是正解**：给 `?debug` 加诊断字段（cb/sc/rp），用户正常操作，
   app 主动上报。**等效真机实测，但不依赖 WiFi/无线调试**（adb 控真机那条路被无 WLAN 卡住，
   这条绕过了）。
3. **C 类问题也能用「可量化内部状态」间接实锤**：cb 清单直接数光标块、sc/rp 直接量化
   滚动/重绘——比纯"看"更硬，又不靠 headless 猜。

## 回退协议对照

step1 headless 复现 → 堵；step2 headless 定量 → 堵；step3 **换观测手段（真机上报）→ 过**。
按协议在 step1/2 失败后没判"不可测"，而是换成"加观测力"——正是「方法用完需新方法」的正确处置。
