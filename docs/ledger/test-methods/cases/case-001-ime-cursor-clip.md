# case-001：IME 光标视觉对齐验证——量化测量卡死 → 守视截图一次过

> 日期：2026-08-23
> 目标：验证「宽字符裁 2 格」修复后，中文长句光标是否紧贴末字（C 档感官）。
> 结论：修复有效（headless 守视截图证实；真机复测确认中文解决）。

## 经过（方法试错链）

1. **DOM 几何测量（A 类）**——读 `cursorEl.getBoundingClientRect().left` 对照
   `Range.selectNodeContents(row).right` 想量化漂移。**卡死**：① 行 div 是整行宽，
   Range 右端≈整行宽非字形终点；② headless 字体 ≠ 手机 Via 字体；③ cursorEl `display:none`
   定位不稳。几次测量数互相矛盾（-92 / -172）。→ 判"headless 测不了"。
2. **帧像素分析（A 类）**——连拍均值/标准差抓闪，对光标对齐无效。
3. **用户提醒：直接截图看** → `守视截图（C 类，正确类别）`：截终端中文行，放大裁剪，
   **一眼看到光标块紧贴末字、无半格空隙**。→ 一次通过。

## 教训（三）

1. **类别错配**：拿 A 类（量化）硬判 C 类（感官）问题，工具不匹配导致"测不出"，进而**误判"不可测"**。
   正确做法：C 类直接上守视/实拍（项目 C 档纪律早有：实拍即判卷）。
2. **默认测量而非观察**：我有眼睛，却先去堆仪器找数字；"看一眼就懂"的问题被硬做成精密测量。
3. **边界过度泛化**：headless 字体 ≠ 手机，只在"像素级字形比对"域内成立；但**格网对齐是字体无关的**
   （光标固定 `col×cellW`、CJK 裁 2 格），守视可判。被"字体不同"锚住后不该整类放弃。

## 回退协议对照

按协议本应在步骤 1（DOM 几何）失败后换 C 类方法（守视），直接判观感；实际却困在 A 类
多轮 + 判"不可测"。**这正是回退协议要防的**——先选匹配类别，失败即换类，别在错类别里打转。
