# TOOL_IO_COMPACTION.md — 工具 I/O 上下文压缩契约（居家级别）

> **地位**：本文档是 kfmv4 AI 对话上下文管理的最高契约之一，与 `AI_CHAT_RUNTIME.md` 同级。
> 修改压缩行为、新增工具、调整豁免策略前**必须**先读本文。
> 本文档由 `check-tool-compaction.mjs` 机械执行：注册工具无压缩器 = 构建中断。

## 一、为什么存在（问题定义）

会话文件是全量真相源（永不压缩），但发给 LLM 的 apiMessages 是**投影**。
实测（2026-07-27，2.1MB 会话）：API 载荷中 **~90% 是工具 I/O 噪音**（工具结果 76% +
工具入参 14%），真正的对话（user 消息 + AI 正文）只占 ~10%。45 万 tokens/轮 →
TTFB 5-8s、缓存读取费用、注意力稀释（"lost in the middle"）三连。

哲学与 UI 投影同源：面板显示全量、会话卡显示纯消息、**API 收到压缩投影**。
三者互不干扰，真相源永远是会话文件。

## 二、核心逻辑（五句话）

1. **压缩证据，保留判决**——工具输出是证据，AI 正文是判决（结论已总结在正文里）。
2. **可寻址的丢失，不是遗忘**——压缩行必须带可恢复引用，AI 需要原文时会自己重取。
3. **工作记忆不动**——最近 2 轮 AI 消息（含其全部工具 I/O）全量保留。
4. **确定性/幂等**——同样输入永远产出同样文本（prompt 缓存前缀不失效）。
5. **只压内容，不拆结构**——`tool_calls` / `role:"tool"` / `tool_call_id` 配对原样保留。

## 三、通用规则（所有工具继承）

| # | 规则 | 理由 |
|---|------|------|
| G1 | 最近 2 轮 AI 消息的全部工具 I/O 全量豁免 | 工作记忆，AI 正在用的"桌面" |
| G2 | 结果 ≤300 字符不压 | 压缩行本身占 token，压了反而亏 |
| G3 | 失败结果 ≤500 字符保留原文 | 错误信息往往正是后续诊断对象 |
| G4 | 最新一个 todo 工具结果永不压 | 承载当前任务状态，压了=失忆当前进度 |
| G5 | user 消息、AI 正文（text）一个字都不许动 | 对话本体，压缩的绝对禁区 |
| G6 | 压缩行禁时间戳/随机数/会话特定 ID | 确定性要求（规则 4） |
| G7 | 未知工具走兜底压缩器 `[{name} → 输出{n}字符已折叠]` | 行为永不出错；但 check 会对未登记工具报红 |

## 四、新增工具的判断流程（决策树）

写新工具的压缩器前，按序回答三问：

1. **输出可重取吗？**（read/grep/bash 可重跑 → 给重取提示；web_search 可重搜 → 留 query；随机/瞬时输出不可重取 → 考虑保留更多）
2. **输出有跨轮引用价值吗？**（错误堆栈、配置内容 → 有，从轻压或豁免；目录列表、日志 → 无，全压）
3. **输出多大？**（≤300 字符 → G2 豁免，不压）

然后查第五节映射表对号；表中没有的，按决策树自写一行规则并**补进表里**（本文档与注册表同步更新是新增工具的 Definition of Done）。

## 五、逐工具映射表

> 格式：`[工具名 关键标识 → 结果摘要]`。`{...}` 为插值，截断长度标在括号内。

| 工具 | 压缩行模板 | 保留的标识符 | 特殊规则 |
|------|-----------|-------------|---------|
| bash | `[bash: {cmd(≤60)} → 成功，{n}行输出已折叠]` | 完整命令语义（截断保留前半） | 失败走 G3 |
| read | `[read {path} → {size}，可用 read 重读]` | path | 可恢复引用样板 |
| write | `[write {path} {lines}行]` | path + 行数 | 入参（文件全文）全压 |
| edit | `[edit {path} 第{a}-{b}行]` | path + 行范围 | old/new text 全压 |
| grep | `[grep {pattern} → {count}处匹配，可重跑]` | pattern | |
| glob | `[glob {pattern} → {count}个文件]` | pattern | |
| todo | 最新不压；旧的 `[todo 更新{n}项]` | 项数 | G4，input 每次重复全量列表故旧的全压 |
| web_search | `[web_search {query(≤50)} → 结果已折叠]` | query | 结果不可重取但可重搜 |
| debug | `[debug {action} → 已折叠]` | action | 输出大但价值密度低 |
| eval / browser_eval | `[eval {expr(≤40)} → 已折叠]` | 表达式前缀 | |
| browser | `[browser {action}]` | action | |
| kfm-snapshot / kfm-exec / kfm-restart / checkpoint / rewind / git / cat | 通常 ≤300 字符 → G2 豁免 | — | **不压**。后来者不得画蛇添足加压缩器 |

## 六、示例与错误示例

### ✅ 正确

输入（5 轮前）：
```json
{"name": "read", "input": {"path": "/src/orb.ts"},
 "result": {"content": [{"type": "text", "text": "// 41,203 字符的文件全文..."}]}}
```
产出：
```
[read /src/orb.ts → 41.2KB，可用 read 重读]
```

输入（2 轮前，G1 豁免期内）：原样保留，一个字不动。

### ❌ 错误示例（每一种都真实踩过或可预见）

| 错误 | 后果 |
|------|------|
| `[read 了一个文件]` | 无可恢复引用 → AI 凭模糊记忆瞎编文件内容（真降智） |
| 压缩行带时间戳 | 每轮 prompt 都变 → prompt 缓存全废 |
| 删掉整条 role:"tool" 消息 | tool_calls 配对破裂 → API 400 |
| 压缩最近一轮的工具结果 | 工作记忆被破坏 → AI 不知道刚才发生了什么 |
| 压缩最新 todo | 任务状态失忆 → 重复劳动/漏项 |
| 压缩 AI 正文里的代码块 | 判决被毁，本项目存在意义被否定 |
| 为 50 字符的输出产 60 字符的压缩行 | 负优化（G2 的意义） |

## 七、绝对禁令（违反任何一条 = 设计错误，必须回退）

1. 禁动 user 消息与 AI 正文（含 reasoning 字段——虽然不上行，也不许在投影层删改数据层）。
2. 禁破坏 OpenAI tool_calls/tool 消息配对结构。
3. 禁非确定性输出（时间戳、随机、运行次数）。
4. 禁压缩会话文件本身——投影层与存储层严格分离。
5. 禁"先上线后补文档"——映射表、注册表、本文档三者同步是 DoD。

## 八、工程位置

- 压缩器注册表：`src/shared/tool-compaction/`（纯函数，双端可用）
- 调用点：`orb-chat-run.ts` doSend 构建 apiMessages 时（唯一压缩点；run 内后续轮次的工具结果是"近期"，天然豁免）
- 机械执行：`check-tool-compaction.mjs`（tools/ 注册名 ↔ 压缩器注册表双向核对，build 中断级）
- 灰度开关：localStorage `kfm-no-compact=1` → 跳过压缩发全量（回退逃生门）
- 观测：压缩前后字符数日志 + 既有 `[chat] usage`/`upstream TTFB` 前后对比
