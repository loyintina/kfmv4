# 工具 I/O 上下文压缩契约（居家级别）

> **地位**：本文档是 kfmv4 AI 对话上下文管理的最高契约之一，与 detail-runtime.md 同级。
> 本文档由 `scripts/check/check-tool-compaction.mjs` 机械执行：注册工具无压缩器 = 构建中断。
> 迁移注（2026-07-28）：自 docs/design/TOOL_IO_COMPACTION.md 整份迁入，原文未删节（原文 v8.2 注销，git show v8.1.1 考古）。

## 一、为什么存在（问题定义）

会话文件是全量真相源（永不压缩），但发给 LLM 的 apiMessages 是**投影**。
实测（2026-07-27，2.1MB 会话）：API 载荷中 **~90% 是工具 I/O 噪音**（工具结果 76% +
工具入参 14%），真正的对话（user 消息 + AI 正文）只占 ~10%。45 万 tokens/轮 →
TTFB 5-8s、缓存读取费用、注意力稀释（"lost in the middle"）三连。

哲学与 UI 投影同源：面板显示全量、会话卡显示纯消息、**API 收到压缩投影**。
三者互不干扰，真相源永远是会话文件。

## 二、核心逻辑（五句话）

1. **压缩证据，保留判决**——工具输出是证据，AI 正文是判决（结论已总结在正文里）。
2. **可寻址的丢失，不是遗忘**——压缩行必须带可恢复引用，AI 需要原文时会自己重取。
3. **工作记忆不动**——最近 8 轮用户回合（含其全部工具 I/O）全量保留。
4. **确定性/幂等**——同样输入永远产出同样文本（prompt 缓存前缀不失效）。
5. **只压内容，不拆结构**——`tool_calls` / `role:"tool"` / `tool_call_id` 配对原样保留。

## 三、通用规则（所有工具继承）

| # | 规则 | 理由 |
|---|------|------|
| G1 | 最近 8 轮用户回合（EXEMPT_USER_ROUNDS）的全部工具 I/O 全量豁免 | 工作记忆，AI 正在用的"桌面"；豁免单位是**用户回合**不是 AI 消息数——一轮多工具调用产生多条 AI 消息，按 AI 消息计数会让跨回合证据 1~2 轮蒸发。定标：2026-07-30 边界实验（4 个真实会话，复取距离中位 4~7 回合、W8=成本拐点） |
| G2 | 结果 ≤300 字符不压 | 压缩行本身占 token，压了反而亏 |
| G3 | 失败结果 ≤500 字符保留原文 | 错误信息往往正是后续诊断对象 |
| G4 | 最新一个 todo 工具结果永不压 | 承载当前任务状态，压了=失忆当前进度 |
| G5 | user 消息、AI 正文（text）一个字都不许动 | 对话本体，压缩的绝对禁区 |
| G6 | 压缩行禁时间戳/随机数/会话特定 ID | 确定性要求（规则 4） |
| G7 | 未知工具走兜底压缩器 `[{name} → 输出{n}字符已折叠]` | 行为永不出错；但 check 会对未登记工具报红 |

## 四、新增工具的判断流程（决策树）

写新工具的压缩器前，按序回答三问：

1. **输出可重取吗？**（read/grep/bash 可重跑 → 给重取提示；web_search 可重搜 → 留 query；随机/瞬时输出不可重取 → 考虑保留更多）
2. **输出有跨轮引用价值吗？**（错误堆栈、配置内容 → 有，从轻压或豁免；目录列表、日志 → 无，全压）
3. **输出多大？**（≤300 字符 → G2 豁免，不压）

然后查第五节映射表对号；表中没有的，按决策树自写一行规则并**补进表里**（本文档与注册表同步更新是新增工具的 Definition of Done）。

## 五、逐工具映射表

> 格式：`[工具名 关键标识 → 结果摘要]`。`{...}` 为插值，截断长度标在括号内。

| 工具 | 压缩行模板 | 保留的标识符 | 特殊规则 |
|------|-----------|-------------|---------|
| bash | 成功 `[bash: {cmd(≤60)} → 成功，{n}行输出已折叠{指标}，可重跑{弧线}]`；失败 `，尾部: …{末200字符}，可重跑`（换行压为 ⏎，弧线在尾部方括号外） | 完整命令语义（截断保留前半） | 失败 = 诊断证据，留尾部采样（stderr 惯例错误在末尾）；指标提取白名单只认 `N passed, N failed`；弧线标注见第九节 |
| read | `[read {path} → {n}行/{c}字符{截断}{去重}，可用 read 重读]` | path（含 `:行区间` 选择器）+ 指纹对 | 行数+字符数 = 修改检测指纹；截断/采样标记透传「未看全」；去重/回退标注见第九节 |
| write | `[write {path} → {n}行/{c}字符已写入]`；入参 `{path, _compacted: "{n}行/{c}字符内容已折叠{爆发标注}"}` | path + 指纹对 | 与 read 同词汇的跨工具指纹链：write 指纹 ≠ 后来 read 指纹 = 写后被修改 |
| edit | `[edit {path}{行号段} → -{old}/+{new}行]`；入参 `_compacted: "编辑已折叠: {行号段}-{old}/+{new}行{爆发标注}"` | path + diff-stat + 行号 | 真实 schema 是 input.old/new（无行号），行号读 result.details.lineStart/lineEnd（编辑当时位置，后续编辑会漂移）；形状自带故事（-0/+12 纯新增 / -30/+3 大幅简化）；失败入参 ≤500 豁免（镜像 G3） |
| grep | `[grep {pattern}{ @ path}{（忽略大小写）} → {count}处匹配，可重跑]`；截断时 `{count}+处匹配（结果被截断）` | pattern + 非默认语义参数 | 「未看全」透传：截断时 count 不全，必须显式标注；参数标注规则见第九节 |
| glob | `[glob {pattern}{ @ path}{（含隐藏）} → {count}个文件]`；截断时 `{count}+个文件（结果被截断）` | pattern + 非默认语义参数 | BAR-COMPACT-03 起工具侧带 `(结果被截断)` 标记行，压缩层透传 |
| todo | 最新不压（G4）；旧的 `[todo 更新{n}项]`；最后一条结果追加投影标注（dismiss/烂尾） | 项数 + 用户信号 | 实测结果全部 ≤188 字符，G2 已天然豁免；入参刻意不压（计划本体，见第九节） |
| web_search | `[web_search {query(≤50)} → {n}条：{标题;连接}，正文已折叠，可重搜{（结果与上方搜索相同）}]`；无标题行兜底 `→ 结果已折叠，可重搜` | query + 标题清单 | 留判决（来源清单）不留证据（snippet 正文）；重复搜索标注见第九节 |
| debug | `[debug {action} → 已折叠]` | action | 实测输出 med 48 字符天然豁免；>300 全是 action 可描述的 state dump |
| eval / browser_eval | 结果 `[eval {首行描述(≤40)} → 已折叠]`；入参 `{_compacted: "代码已折叠: {首行描述}"}`（language 透传） | 首行描述 | 入参代码才是载荷（实测 med 323 字符）；描述符两端同词汇 |
| browser | `[browser {action}]` | action | 实测仅 2 次调用皆失败，数据不足仅记录 |
| kfm-logs | `[kfm-logs → 输出{n}字符已折叠]`（G7 兜底） | — | 日志可重取、跨轮引用价值低，全压 |
| kfm-restart / checkpoint / rewind / git / cat | 通常 ≤300 字符 → G2 豁免 | — | **不压**。后来者不得画蛇添足加压缩器 |

## 六、示例与错误示例

### ✅ 正确

输入（5 轮前）：
```json
{"name": "read", "input": {"path": "/src/orb.ts"},
 "result": {"content": [{"type": "text", "text": "// 41,203 字符、812 行的文件全文..."}]}}
```
产出：
```
[read /src/orb.ts → 812行/41203字符，可用 read 重读]
```

输入（2 轮前，G1 豁免期内）：原样保留，一个字不动。

### ❌ 错误示例（每一种都真实踩过或可预见）

| 错误 | 后果 |
|------|------|
| `[read 了一个文件]` | 无可恢复引用 → AI 凭模糊记忆瞎编文件内容（真降智） |
| 压缩行带时间戳 | 每轮 prompt 都变 → prompt 缓存全废 |
| 删掉整条 role:"tool" 消息 | tool_calls 配对破裂 → API 400 |
| 压缩最近一轮的工具结果 | 工作记忆被破坏 → AI 不知道刚才发生了什么 |
| 压缩最新 todo | 任务状态失忆 → 重复劳动/漏项 |
| 压缩 AI 正文里的代码块 | 判决被毁，本项目存在意义被否定 |
| 为 50 字符的输出产 60 字符的压缩行 | 负优化（G2 的意义） |

## 七、绝对禁令（违反任何一条 = 设计错误，必须回退）

1. 禁动 user 消息与 AI 正文（含 reasoning 字段——虽然不上行，也不许在投影层删改数据层）。
2. 禁破坏 OpenAI tool_calls/tool 消息配对结构。
3. 禁非确定性输出（时间戳、随机、运行次数）。
4. 禁压缩会话文件本身——投影层与存储层严格分离。
5. 禁"先上线后补文档"——映射表、注册表、本文档三者同步是 DoD。
6. 跨调用标注只许向后看——一条压缩行的标注只能依赖它之前或同批的消息，
   违者旧压缩行会随会话增长而改变，prompt 缓存前缀稳定被破坏（变相违反禁令 3）。

## 八、工程位置

- 压缩器注册表：`src/shared/tool-compaction/`（纯函数，双端可用）
- 调用点：`orb-chat-run.ts` doSend 构建 apiMessages 时（唯一压缩点；run 内后续轮次的工具结果是"近期"，天然豁免）
- 机械执行：`scripts/check/check-tool-compaction.mjs`（tools/ 注册名 ↔ 压缩器注册表双向核对，build 中断级）
- 灰度开关：localStorage `kfm-no-compact=1` → 跳过压缩发全量（回退逃生门）
- 观测：压缩前后字符数日志 + 既有 `[chat] usage`/`upstream TTFB` 前后对比

### 投影层附加行为（同属 toOpenAiMessages，非压缩但同契约管辖）

- **空壳 assistant 过滤**：零正文零工具的 assistant 不进载荷（BAR-PROVIDER-02，严格端点 400）。
- **客户端产物占位符过滤**：整条为 `[错误: …]` / `[未收到回复，请重试]` 的 AI 消息不进载荷——
  本地事故记录不是对话内容，上行会污染 AI 的「最近的自己」（实测 k3 400 时代污染最近几十轮）。
  混有真实正文的不在此列；`[已取消]` 保留（用户主动取消是对话信号）。会话文件原样保留，只过滤投影。
- **时间戳前缀**：消息写入侧盖 `ts`（ISO 8601，messages.ts 定义），投影层对 **user**
  正文渲染 `[ts MM-DD HH:MM:SS] ` 前缀（精确到秒：一分钟内可有多轮对话），给 AI 对话时间感。
  旧消息无 ts = 不渲染（向后兼容）。**assistant 侧不盖**（BAR-TS-MIMIC-01）：
  AI 在自己历史回复上看到统一前缀就会学成行文格式复读——换格式、加标签、加声明都
  拦不住（实测产出 `[ts …] [ts …]` 双前缀杂交体）；前缀不上 assistant 身，投影里它的
  历史回复就是干净的，没有可模仿样本。chat.ts 静态 system 段另有防模仿声明兜底。
  不违反 G6：ts 是真相源数据、确定不变；G6 禁的是投影时现生成。
  **投影文本禁止回写真相源**：服务端落盘用户消息必须走请求体的 `userText` 原文通道
  （routes.ts），不得从 apiMessages 提取——投影带前缀，回写会造成前缀叠加污染（v8.3.x 病灶）。
- **会话卡 tokenCount 口径**：压缩投影后的载荷字符数 / 3（session-store._computeStats）——
  对齐「上下文窗口还剩多少」的直觉；旧口径（全量字符 / 3）会让 1M 窗口的模型在界面上早早显示顶格。

## 九、逐工具细化记录

> 本表随"逐工具讨论"逐个细化，每个工具一节，记录定稿的规则、边界用例与理由。
> （write / edit / grep / glob / todo / web_search / debug / eval / browser / 豁免组 / 失败模式 全部定稿，2026-07-28）

### 方法论（2026-07-28 bash/read 讨论定稿）

**保留什么信息的判断标准**：保留的信息必须能「避免一次昂贵/有副作用的重取」，
或「支撑跨轮诊断」。由此分三层：

1. 可重取的成功输出 → 固定描述（占位+导航），默认层，不采样内容；
2. 失败/诊断证据 → 描述 + 确定性采样（尾部），增强层；
3. 统计锚点（行数/字符数/匹配数）→ 所有层都带，成本极低信号极高。

**压缩行是思考链提示**：LLM 不会自发跨历史对比元数据，但压缩行里的显式
短信息会进入上下文、被推理直接使用（典型：指纹对揭示文件被修改）。约束：
提示字段控制在 1-3 个高信号字段，否则压缩行自身膨胀成新的注意力稀释源。

**已否决项**（后来者不得复活）：首行/大纲内容预览（内容非结构，路径已是锚点）、
hash（对 LLM 无语义）、错误行关键词提取（对 tsc 类「每行皆错误」输出退化为
全文，覆盖率不如尾部采样）、智能摘要（非幂等，破坏 prompt 缓存，违反禁令 3）。

### bash（2026-07-28 定稿，实测依据：todo工具测试会话 243 次调用）

- 实测：中位输出仅 110 字符（75% 走 G2 原样保留），大成功输出集中在
  grep/ls/cat/build 类（可重跑、幂等）→ 成功不采样，纯描述行。
- 失败追加尾部 200 字符采样：失败输出是诊断证据，压掉 = 强迫 AI 重跑失败命令
  （可能昂贵/有副作用/不可复现）。stderr 惯例错误信息在末尾，故取尾不取头。
  换行压为 ⏎（压缩行单行契约）。G3（≤500 豁免）不变——小错误全文保留。
- **已知限制**：bash 工具结果文本在有输出时不含 exit code（omp/bash.ts 只在
  输出为空时写 `(退出码: N)`），压缩行拿不到。若未来需要，应改 bash 工具
  统一在结果尾部带 exit code，而非在压缩层猜测。

### read（2026-07-28 定稿，实测依据：65 次调用，35 次为同路径重读）

- **指纹对 `{n}行/{c}字符`**：同一路径两条压缩行指纹不同 = 两次读取之间文件
  被修改（含「行数不变但字符数变」的隐式修改）。重读行为已被实测验证
  （index.ts 读 7 次、debug.ts 读 7 次），可寻址恢复不是理论。
- **行区间保留**：`path:275-370` 选择器（omp/read.ts）留在压缩行 path 里，
  AI 重读时能读对段。后来者不得在压缩层剥离选择器后缀。
- **截断/采样标记透传**：read 工具 >100KB 时结果自带 `仅显示前 100.0KB` 或
  `采样 (前 30 行)` 标记——压缩行必须透传「未看全」，否则 AI 误以为看过全文，
  基于不完整信息做判决。这是从工具真实实现挖出的结构信号，不是理论推演。

### 标注层（2026-07-28 定稿，实测依据：归一化使命令重复识别覆盖率 14%→32%）

**设计公理（适用于一切标注，后来者新增标注前先过这三条）：**

1. **宁漏勿错（成本不对称推导）**——漏报 = 退回现状（零损失）；错报 = 往
   AI 思考链注入假事实（AI 信任上下文，会基于谎言推理）。故标注层永远站
   分类器的高精确率一端。
2. **决策相关性检验**——每条标注必须能回答「AI 看到它会做出什么不同的
   决定？」答不上来或答案是「可能误导」= 不该存在。**覆盖率不是目标**
   （调规则刷覆盖率 = 为了标注而标注，Goodhart 异化），精确率才是。
3. **只向后看**——见禁令 6。

**bash 命令归一化语法**（实现：`normalizeBashCommand`，逐字符测试锁定）：
① 截断 `|` 管道尾；② 去 `2>&1` 重定向；③ 按 `&&`/`;` 切段，丢弃 `cd`/`export`
前缀段，取第一个实质段（带参数，剥 `time` 前缀）；④ 折叠空白。
是「粗化」不是「模糊」：身份由归一化式唯一确定，不做相似度匹配；
语义等价但写法不同（`npm test` vs `npm run test`）宁可漏标。

**bash 重试弧线**：同一归一化命令第 N 次执行时标注 `（第N次执行）`；
含本次连续失败 ≥2 → `，连续N次失败`（反死循环信号：修复没命中）；
本次成功且此前连续失败 ≥1 → `，此前连续N次失败`（弧线收敛信号）。

**bash 环境故障标注（反转版）**：连续 ≥3 次失败**且最近 3 次为不同归一化命令**
→ `（连续N次失败均为不同命令——疑似环境问题）`。逻辑：不同意图同一结局，
共同原因在通道不在命令。注意通用版「工具级连续成败统计」已被否决——
bash 是复用通道（build/test/git 复用一个工具名），不相干失败的累计是
假叙事生成器；只有「命令各异」这个反转条件才有语义。实测抓到的正是
高价值弧线：`systemctl restart kfmv4` 连败 9 次（502 事故）。

**read 去重/回退标注**（指纹是证据、标注是结论，两者都保留）：
指纹同上方 → `内容与上方读取相同`；指纹回退到更早一次 →
`内容回退到第N次读取时的状态`（A→B→A 场景，相邻比对会漏）；否则 →
`内容与上方读取不同（文件已被修改）`。

**指标提取白名单**：只认 `N passed, N failed` 测试结果模式。绝不为各种
输出格式维护专属解析器——白名单外一律不提取。

**grep 截断透传**：`(结果被截断)` 标记 → `{count}+处匹配（结果被截断）`，
与 read 「未看全」同构（截断时 count 不全，必须显式）。

### write / edit（2026-07-28 定稿，实测依据：edit 44 次/write 5 次，14 个文件被多次修改）

- **载荷在输入侧**：write/edit 结果极小（edit 结果中位 18 字符，全部 G2 豁免），
  淹没问题在入参（write 全文 / edit old/new）——它们是仅有的两个
  「入参压缩主战场」工具，故合并讨论。
- **edit diff-stat `-{old}/+{new}行`**：从 input.old/new 行数直算。形状自带
  故事：-0/+12 纯新增、-15/+0 纯删除、-30/+3 大幅简化（心法 18 的直接证据）、
  -5/+30 膨胀信号。变更锚点问题的定案：**留形状，不留内容**（新状态可用
  read 重读；旧内容不可再取但 AI 当时已消费）。
- **edit 行号段 `第{a}-{b}行`**（2026-07-28 追加）：来自 `result.details.
  lineStart/lineEnd`（omp/edit.ts 替换时写入，真相源数据，零工具改动）。
  一次 edit 调用 = 一个连续行段（无多段）。**行号是编辑当时的位置，后续
  编辑会使其漂移**——仅作当次定位，不代表当前文件状态；无 details 时省略。
  result 侧与 input 侧压缩行都带（格式见第五节映射表）。
- **write 指纹对 `{n}行/{c}字符`**：与 read 同词汇，跨工具指纹链打通——
  write 时指纹 ≠ 后来 read 时指纹 = 写后被修改。
- **修改爆发标注**（2026-07-28 由「修改次数」升级）：write+edit 合并计数、
  只计成功调用、**锚定真相源**（从全量会话文件预扫描，与投影窗口无关——
  未来上下文压缩不清空计数，投影压得越狠，计数作为「被压掉历史的存在证明」
  越有价值，标注层公理 4）。爆发语义：同一路径相邻两次成功修改相距
  **≤`MUT_BURST_GAP`（=8，可调常量）轮 AI 消息 = 同一爆发期**，第二次起标
  `（本轮第N次修改）`；相距 >8 轮 = 新一轮爆发，标 `（重新进入修改，此前
  共M次）`——历史累计降级为再进入背景（几轮内集中修改的计数才有时效性；
  隔了很久又回头改同一批文件时，「重新进入」比「第 17 次」更有决策价值）。
  首次修改不标注。
- **失败入参 ≤500 豁免**（镜像 G3）：失败 edit（old 未匹配等）的 old/new 正是
  诊断对象，和失败结果同等保护。
- **schema 教训（实测抓到的真 bug）**：初版 edit 压缩按假设的 `lineStart/lineEnd`
  取行号，真实 schema 是 `old/new`——线上压缩行静默退化为 `[edit {path}]`，
  而测试全绿（测试也按假设 schema 构造）。**教训：测试样例必须照真实会话
  数据构造；假设错则测试跟着错。**（与心法 25 互为表里。）

### grep / glob（2026-07-28 定稿，实测依据：grep 27 次 / glob 7 次，3 个真实会话）

- **参数标注规则（本轮核心产物）**：**影响结果语义的非默认参数进压缩行**。
  由 ignoreCase 单点想法经自我反驳升级——补查数据发现 grep **27/27 全部
  显式传 path**（分布在 15 个不同路径，目录文件混合），不带 path 的压缩行
  让 AI 无法区分搜索覆盖范围（「server 里没有」≠「项目里没有」），决策强
  相关。规则细目：`@ {path}` 传了才标；`（忽略大小写）`/`（含隐藏）` 非默认
  才标；`maxCount`/`maxResults` **不标**（截断时计数=上限可推断，未截断时
  无影响，标了是噪音）。schema 封闭性已验证：grep/glob 各仅 4 个参数，
  无数据外隐藏参数。
- **glob 截断无标记 = 真洞（BAR-COMPACT-03，已修已钉）**：glob 默认上限
  `maxResults=200`，命中上限时输出**无任何截断标记**；native 的
  `totalMatches` 顶格时等于返回数（实测），帮不上忙；真实会话恰好有一次
  `pattern="*"` 顶到 200 行无法判断全否。修法：**+1 探针法**——请求
  `maxResults+1` 个，返回 >maxResults 即确知截断，追加 `(结果被截断)` 标记行
  （与 grep 同词汇）。语义「至少还有 1 个未显示」，不声称精确总数（要知道
  「恰好 201」得请求 202，递归无底；grep limitReached 同构）。恰好等于上限
  不算截断（钉子覆盖此边界）。
- **grep 截断透传已有**：`{count}+处匹配（结果被截断）`，标记行不计入 count。
- **「0处匹配」标注想法被证伪（记录在案，勿再提）**：实测 0/27 零匹配；
  且零匹配输出 `未找到匹配 "pattern"` 仅 ~30 字符，G2 豁免永不进压缩器，
  标注逻辑上不可能触发；工具原文已显式。**先过数据再设计，本轮因此少造
  一个死胎机制。**

### todo（2026-07-28 定稿，实测依据：31 次调用，结果全部 ≤188 字符）

- **无载荷问题，无代码压缩动作（数据证伪预告想法）**：结果 med ~60/max 188
  字符，G2 天然全豁免（压缩器 todo case 实践中休眠，保留作大列表日保险）；
  入参 med 217/max 394，仅 8/31 超 300。「历史 todo 状态迁移提取」想法被
  证伪——载荷太小 AI 本就能看全部原文，提取 diff 是为压缩而压缩。
- **入参登记为「刻意不压」**：todo 入参是任务计划本体，决策最关键，且天然
  小——压缩它省 ~2KB/会话却弄丢计划内容，负优化。
- **G4 与 G2 实践中冗余但保留**：最新结果反正 ≤300 被 G2 豁免，G4 是大
  列表日的保险，成本低不动。
- **投影标注（本轮核心产物，只追加在最后一个 todo 结果上）**：
  - **dismiss 标注 `（面板已被用户手动关闭）`**：用户 ✕ 关闭面板的信号原本
    只存在 localStorage（BAR-ORB-PANEL-22 指纹机制），真相源与投影都没有——
    AI 看到的最后 todo 永远是「召唤时的样子」（实测两个会话都以 in_progress
    收尾）。投影构建时比对最后 todo 入参指纹与 `kfm-todo-dismissed`，命中即
    追加。**措辞只陈述事实不做因果断言**（宁漏勿错）：用户明确过「手动关闭
    有时只是嫌碍眼，不代表任务结束」——信号分不出两种意图，不替用户下结论。
    缓存稳定：一旦关闭恒真（新列表指纹不同会清除记录），标注只翻转一次。
  - **烂尾标注 `（此后超过10轮未更新，可能已过时）`**：AI 会召唤 todo 后
    忘记更新/收尾（用户观察 + 实测收尾证据）。**阈值式单调布尔**（K=
    `TODO_STALE_GAP`=10，可调常量）——直接标「N 轮未更新」会每轮变、缓存
    前缀尾部全废；阈值布尔一旦为真恒真，只翻转一次。措辞带「可能」（hedged，
    同样是宁漏勿错）。
- **观察（未建）**：todo 的 status 无枚举校验，数据出现过一次 `thinking`
  静默降级渲染为 `[ ]`（1/31，边界测试会话，无害）。要堵就是工具加校验的事。

### web_search / eval / browser_eval / debug / browser（2026-07-28 定稿，实测依据：web 13 / browser_eval 26 / eval 5 / debug 68 / browser 2 次）

- **分组框架（用户提出）**：主动命令（debug/eval）价值在「效果」，信息收集
  （web/browser）价值在「内容」——压缩策略分开想。结论：主动命令组天然
  完整（debug 输出 med 48、eval max 145 字符，G2 豁免原文直通），信息收集
  组各有一个缺口。
- **web_search 保留标题清单（A）**：旧压缩行 `→ 结果已折叠` 连判决一起烧
  （来源清单彻底消失，无法复查覆盖度）。实测标题行仅占输出 12-23%——
  **标题清单=判决，snippet=证据**。新行保留标题：每条截 30、`；`连接、
  总截 120（G6 确定性截断，规则必须写死）。
- **eval/browser_eval 入参折叠（B）**：载荷在入参代码（med 323 字符、
  17/31 >300、最大 1327），结果天然小。代码是一次性探针，价值在结果。
  描述符 `codeDescriptor()`：首个非空行去注释符截 40——实测 13/31 首行
  是意图注释，其余首行代码（DOM 查询）也有描述性，100% 有值。**结果行
  与入参行共用此描述符**（同词汇原则）；两端独立触发各自自包含（实测
  结果 >300 ⟺ 入参 >300，相邻 40 字符冗余换自包含，值）。eval 的
  `language` 透传。**可重跑性差异记录在案不分裂机制**：eval 沙盒可重跑、
  browser_eval 依赖页面状态不可——折叠 eval 的损失=重写成本，实测全是
  测试小脚本可接受。
- **重复搜索标注（D）`（结果与上方搜索相同）`**：实测 13 次 web_search
  中 5 次卷入重复对（38% 重复率）——换措辞再搜是 agent 搜索循环的典型
  死法。指纹=**标题键精确全等**（比 read 的「行数/字符数」更强，假阳性
  ≈0）。**空键守卫**：失败/异常结果无标题行，空键不参与比对不入历史——
  两个失败搜索的空键会互相误判「相同」（自我反驳阶段抓到的 bug 胚子）。
  措辞只陈述事实，不加「别再搜了」指令性解读。
- **debug/browser 无动作（C，数据支持）**：debug >300 的 7 次输出全是
  action 名即可充分描述的 state dump（renderer_snapshot/gesture_trace/
  custom_request/evaluate），11 次错误（16%）被 G3 完整保护；browser 仅
  2 次调用皆失败，数据不足仅记录。

### 失败模式重复标注（2026-07-28 定稿，实测依据：66 次失败调用全扫描）

- **压缩层面无缺口（数据结论）**：65/66 失败 ≤500 字符被 G3 完整保留
  （失败是诊断证据，保留是设计本意）；唯一 >500 的 bash tsc dump 已有
  尾部 200 规则。「失败保尾部」不推广到其它工具——无实例无依据。
- **真正的缺口是「重复犯错意识不到」**：实测 read 失败 10 次中 5 次是同一
  个 `EISDIR`（反复读目录）、同一路径不存在 ×2、URL 当文件读 ×2；debug
  「未配置」×2。失败原文全保留 AI 每次都看得见，但不会自发意识到「这是
  同一个错」（LLM 不自发对比元数据的老教训）。
- **机制**：错误文本指纹（trim 前 100 字符精确匹配），同会话同工具重复
  时结果追加 `（第N次相同错误）`。**阈值 FAIL_REPEAT_MIN=3（可调常量，
  用户定）**：第 2 次可能是合理重试，第 3 次才是模式。**守卫**：无信息
  失败文本（`(未完成)`/`(已取消)`/`(退出码: N)`/<20 字符）返回空指纹，
  不入库不比对——实测 bash 失败 17/34 是 `(未完成)`，是不同命令的不同
  结局，参与比对会互相误判。**bash 不参与**本层（有更精细的弧线/环境
  故障机制）。标注不限压缩区（G1 豁免区内的连续失败最需要即时提醒）。
  只陈述事实不开处方（不写「请改用 glob」）。
- **顺带修复：read 指纹历史不再计入失败读取**。旧逻辑不区分成败，EISDIR
  这类错误指纹（「1行/52字符」）会污染历史，让后续成功读取误判「文件已
  被修改」——宁漏勿错 violations，失败的 read 不是「读到了内容」。

### 豁免组 + 工具删除（2026-07-28 定稿：kfm-snapshot / kfm-exec 删除）

- **kfm-snapshot 删除（眼睛机制是严格上位替代）**：与 page-state.md 同一
  数据源（wsServer._latestSnapshot），但眼睛三维度全胜——更新鲜（每次
  工具循环末尾自动刷新注入对话尾部，snapshot 只在调用那一刻）、更丰富
  （page-state 三层「看到什么/页面元素/能做什么」，snapshot 格式化只有
  元素+能力两层，连内容层都没有）、零成本（不占工具调用不留历史输出）。
  实测 3 个会话仅 3 次探索性调用。理论缺口（无眼睛角色临时看页面）无
  实证——两个主力角色均配眼睛；真需要时给角色卡 dynamicPromptFiles 加
  一行即可，轮不到工具来补。
- **kfm-exec 删除（与 bash 同一实现的双胞胎）**：逐行对比同一 executeShell
  /同一输出格式/同一 isError 逻辑，仅超时默认值不同。实测 bash 330 次 vs
  kfm-exec 4 次（1.2%）。实际危害：**kfm-exec 调用逃逸 bash 全部统计**
  （重试弧线/环境故障预扫描只认 `bash` 名）——两个入口 = 统计流分裂。
- **历史兼容**：旧会话里的 kfm-snapshot/kfm-exec 块落 G7 兜底压缩器
  （`[kfm-exec → 输出N字符已折叠]`），行为永不出错——兜底设计的本意。
- **剩余豁免组（实测验证）**：checkpoint 3 次（41-61 字符）/ rewind 1 次
  （17 字符）/ kfm-restart 9 次（5-133 字符）——G2 豁免全部成立。
  git / cat 是 v7 死工具，历史块同走 G7。「豁免但偶尔超 300 落 G7」的
  悬案随 snapshot/exec 删除自然消解。

### 标注层公理 4：统计量锚定真相源

一切跨调用统计量（修改次数、执行序、指纹历史）必须从全量会话文件（真相源）
预扫描计算，**禁止锚定投影窗口**（发给 API 的消息切片）。这样无论投影层未来
如何压缩（滑窗/摘要/丢弃旧消息），统计量都稳定、只向后看、不破坏 prompt
缓存前缀（宪法第四条 + 禁令 6 的推论）。

**已知边界**：错误演化三档标注（相同/相似/新错误）已设计未实现——
签名规则（首个错误行剥独立数字、保留 TS2307 类错误码）留待下一批，
「错误已变化 = 进步信号」的语义已在弧线注解中部分覆盖（此前连续N次失败→成功）。
