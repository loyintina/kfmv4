## 起点：用户一句话

「tmux attach 后上下滚动没有效果。」——从 term 插件的 tmux 体验线起步，
长成了宪法 §6 Step 2 的第一个 React 皮组件试点。

## 流程段（每段：产物 / 坑 / 纪律产出）

### ① 前置：term 插件 tmux 体验三连修（标签栏的土壤）
- 滚动无效→方向反→修好：滚轮语义与 tmux 行模式的对接，用户真机确认方向直觉。
- **疯狂滚动**：attach 后历史重放致页面滚 3-5s（kimi/omp/opencode/dsh 全中），
  输入法弹收同样触发。修法=信息流尾部追平+settle 去抖缓冲。
- **事故（本线最贵的一课）**：慢滚 revert 链删了 `scheduleSettleFlush` 定义
  却漏改 onOutput inSettle 分支调用点（terminal-card-04.ts:638），后续提交
  把死调用带回 master——settle 期输出缓冲永不 flush 的运行时 ReferenceError。
  na 线推信被 pre-push tsc 闸挡住才暴露。
- 纪律产出：**revert/删除符号后必须全库搜调用点，tsc 全绿才算删完**；
  pre-push tsc 闸的价值实证（挡的是真运行时事故，不是风格）。

### ② v2 状态机试点：四步纪律首次完整执行
- 产物：docs/tmux-tabs-v2-state-machine.md——四状态显式枚举
  （HANDLE/EXPANDED/OVERLAY_NEW/OVERLAY_CLOSE）+ 转换表 + 禁止条款 P1-P7。
- 做法（评审裁决采纳的四步纪律）：**清单用户签收 → 每条转换一颗考卷钉 →
  实现 → 变异抽检**。考卷蓝本 tests/browser/tmux-tabs.test.mjs。
- 单源 reducer + 同步查询钩子 `__kfmNzTmuxTabs()` + ≥40 拍转换环形缓冲；
  词汇表强制统一（清单外状态名≈bug 候选）。
- 纪律产出：**先写行为规格再写组件**；规格里的禁止条款（P 系列）比正面
  描述更能挡回归。

### ③ 会话化仲裁：标签对象从「窗」改回「会话」（0902 用户拍板）
- 关键认知：窗版走 `tmux -C attach` 控制通道，每连接每会话一通道，复杂且
  有 automatic-rename 抢名竞态；会话版=服务器 `tmux ls` 3s 轮询推送
  （变化才推），客户端对列表**不固执己见**（P5：推送为唯一真源）。
- 连锁退役：拖动换序 T11（会话无顺序语义）、改名竞态消失、?tmuxSession 参数移除。
- 嵌套禁止（P7）：已附状态下直接注入第二次 attach 会被 tmux 拒——
  T2s 必须先 detach 350ms 再 attach。
- 纪律产出：**数据对象选型（窗/会话）是架构决策，先跟用户对齐再动工**；
  轮询推送比控制通道简单一个数量级，够用就选简单的。

### ④ 多路验证纪律落地（v2.2，用户拍板）
- 产物：nz/AGENTS.md「Bug 修复验收纪律」（L1-L4 路径层级）+
  tests/browser/tmux-tabs-l2-crosscheck.mjs（浏览器钩子 × 服务端 `tmux ls` 真值互证）。
- 核心条款：**每条修复通报必须声明用了什么观测手段**；修复类 bug 至少 2 条
  隔离路径，**其中一条必须最贴近用户体验**（实际渲染截图/真机操作）。
- 兑现记录：v25 tokens.css 缓存漏网——headless 全绿照样真机红
  （headless 每次全新无缓存，永远测不到缓存类 bug），渲染截图路径立功。
- 纪律产出：「多路验证必有一路最贴近用户体验」不是口号，是抓到过真 bug 的网。

### ⑤ 视觉迭代链 v23→v26：tokens + 动画 + 真机 C 档
- **v23 闪烁/延迟三连**：点聚焦标签回终端历史清空+闪烁两下；首次 attach
  延迟 ~2s、切换会话 0.5-0.7s；点击收起后又展开（把手闪）。
  定罪靠延迟考卷（first-attach/switch/focus/new-session 四把尺）逐段掐表。
- **v24 tokens 层**：颜色/时长/曲线/圆角全部变量化，组件零硬编码字面量；
  主题切换二期只需加 `:root[data-theme]`。
- **v25 把手旋转+标签排伸出收回**：展开=按钮顺转 90°+标签排从按钮后伸出，
  两者**同帧起跑**（用户仲裁：先栏后钮的顺序不对）。
  坑=tokens.css 引用无哈希缓存破坏（bundle 有 tokens 没有）——
  **新增静态资源引用时缓存破坏必须与引用同天落地**。
- **v26 tap-highlight 清浮层 + 展开同步根治**：
  - 浅青浮层=WebView `-webkit-tap-highlight-color` 默认值，不是组件动效，清零。
  - 展开时先栏后钮的根因：`:active` 的 `scale(0.96)` 与展开态 `rotate(90deg)`
    **transform 函数列表不匹配→走矩阵插值**（非角度插值），旋转被压到后段；
    收起时列表可分解所以正常——与用户「收起正常」的观察严丝合缝。
    修法=全状态统一函数列表 `[rotate, scale]`（零值占位 `rotate(0deg) scale(1)`）。
- 纪律产出（v26 三条，动画组件通用）：
  1. **多状态 transform 组件，所有状态必须写全同一函数列表**（含零值占位）；
  2. **`:active` 触觉反馈会进入变换插值链**——真触摸 DOWN 的 60ms 足以让
     `:active` transition 起跑并污染 retarget 路径；
  3. **25ms computed-style 采样是动画级 bug 的定罪尺**——帧序列看「有没有」，
     采样看「什么时候、走什么路径」（已入观测手段库）。
- 另：**样式钩子与状态语义分家**——属性选择器同时承载两者，状态翻转时
  样式规则跟着失效还误伤兄弟元素；样式钩子用独立 data 属性。

### ⑥ 形态微调（0903 用户拍板链）
- × 从标签外收进标签内部右端（控制不游离于视觉之外）；
- 标签行胶囊化（圆角 pill 对齐圆形把手）、加号改 24px 正圆贴最后一个标签右侧
  （新标签出现位置=加号位置，浏览器直觉）；
- 窗数徽记仅 >1 时显示（常态单窗的 `·1` 是纯噪音）；
- 标签加长防误触：chip padding 3/6/3/8→5/12/5/14，× 热区 16→20px。
- 纪律产出：**纯样式微调也要过考卷+渲染截图人审**（L1+截图两路），
  改动即提交（吃过未提交被外部 checkout 回退的亏）。

## 纪律产出汇总（通用，不限本插件）

1. 先状态机清单签收，再实现；每转换一颗考卷钉。
2. 修复通报必含观测手段声明；至少两路隔离验证，一路必最贴近用户体验。
3. revert/删符号后全库搜调用点 + tsc 全绿。
4. 静态资源引用与缓存破坏同天落地。
5. 样式全部走 tokens，组件零硬编码。
6. 多状态 transform 写全同一函数列表；设计 :active 动效想插值链一致性。
7. 数据对象选型先对齐用户；列表数据以服务器推送为唯一真源。
8. 改动即提交；bundle 改动通报必须写明「下次页面加载生效」。
