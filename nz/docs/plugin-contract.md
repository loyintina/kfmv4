# nz 插件契约 v0（UI 宪法）

> 2026-09-01 用户拍板立项。配套决策：React 全量采用（真机点火成本
> 21-47ms，1e540823）；双运行时有竞态，组件系统必须唯一。
> **修订规则：本文件是宪法级文档，任何修订须用户拍板，评审存照。**

## 0. 三原则

1. **一切皆插件**：页面上的每个可见物（终端、键栏、标签条、输入栏、
   卡片）都是插件，内核不知道任何插件的存在。
2. **无黑盒**：项目里不允许出现"我们改动不了的纯黑盒"。引入外部库的
   门槛不是"自研"，是 ①源码可读可补丁 ②过契约边界 ③逻辑层不绑框架。
   React 可读可补丁，故可进。
3. **组件系统唯一**：同一棵 DOM 树只有一个主人。当前所有 UI 插件约定
   用 React 适配器；**这是约定不是强制**——内核只认契约签名，不知道
   React 存在。

## 1. 三层架构

```
┌─ 内核 kernel（vanilla TS，永不换，小到可笑）─────────────┐
│ 插件注册表 · 槽位 · 生命周期 · ctx（桥/配置/主题token/事件）│
├─ 契约 contract（本文件）────────────────────────────────┤
│ UI 插件 = { id, mount(el, ctx) → handle{unmount} }       │
├─ 适配器 adapter（可替换）────────────────────────────────┤
│ reactMount 帮手（createRoot+清理）· 未来的任何新适配器     │
└──────────────────────────────────────────────────────────┘
```

- 内核是"可替换一切"的担保人，因此自己必须是项目里**唯一**不允许有
  取代者的东西；任何让内核变厚的提案都要过用户裁决。
- 渲染底座（React）只是当前得票最高的适配器。换底座=写一个新适配器+
  插件逐个换皮，内核与逻辑层不动。

## 2. 契约签名

```ts
interface UiPlugin {
  id: string;
  mount(slot: HTMLElement, ctx: PluginCtx): UiPluginHandle;
}
interface UiPluginHandle {
  unmount(): void;            // 必须删干净：DOM/监听/定时器/全局副作用
  suspend?(): void;           // 可选：隐藏/降频（如后台省电）
  resume?(): void;
}
interface PluginCtx {          // 内核注入，插件唯一合法的外部世界
  bridge: Bridge;              // ws/PTY 会话
  settings: Settings;          // 池卡配置读写
  theme: ThemeTokens;          // 设计 token 单源（CSS vars）
  events: EventBus;            // 插件间通信（禁直连）
}
```

- 插件**只准在自己的槽位元素内**操作 DOM；越槽位改别人的树=违宪。
- 全局副作用（document 级监听、visualViewport、window 注入钩子）必须
  在 ctx 登记，unmount 时随 handle 一并拆除。
- `?debug` 钩子（`__kfmNzTerm*` 家族）属于观测基建，随插件走但视为
  公共契约，改名/退役须通报评审。

## 3. 逻辑/皮分离（换底座可行性的根基）

每个插件强制分两层：

- **脑（纯 TS，不绑任何框架）**：状态机、键序表、协议编解码、度量。
  例：keybar 的 `KEYS`/`ModifierState`、keymap、scrollback 状态机、
  IME 三闸。
- **皮（框架层，当前=React 组件）**：布局、交互、渲染。

换渲染底座时重写的只有皮，脑永远跟着内核走。**不泾渭分明地写 JSX，
将来就换不动**——评审与自查按此条抓违例。

## 4. 性能边界（终端渲染核特例）

终端网格渲染（term-core WASM + 壳的帧调度/渲染节流）保持自有命令式
实现，装在一个 React 组件的 **ref 边界**内：React 拥有树，但永不进入
边界内操作。边界内代码是我们自己的（非黑盒），无双运行时竞态——
这是全页 React 化下唯一允许的命令式飞地，扩土须用户裁决。

## 5. 黑盒红线（引入任何库的三问）

1. 源码我们读得懂、补得了、最坏能 fork 吗？
2. 它是否只活在插件皮层内、能随 unmount 干净退场？
3. 它有没有把逻辑层绑架到它的运行时上（绑了=把逻辑搬出它）？

三问有一个"否"就不进。当前在册豁免：React/react-dom（适配器）、
esbuild（构建期，不进产物）。

## 6. 迁移路线（存量 vanilla → 全插件化，考卷保护）

| 步 | 内容 | 验收线 |
|----|------|--------|
| 1 | React 宿主边界：main.ts 挂 root+插件注册 | 构建绿+四卷不回退，零 UI 变化 |
| 2 | tmux 标签条=第一个 React 插件（8.8.4，顶部覆盖条） | 真 tmux A 档考卷+C 档实拍 |
| 3 | keybar 迁 React（脑不动） | keybar-click 20/20+keymap A+ime-pan 19/19 |
| 4 | term 容器层迁 React（渲染核进 ref 边界） | 四卷+ime-pan+scrollback 全绿 |
| 5 | splash/eyes 收尾，vanilla UI 清零 | 插件注册表枚举=全部 UI |

每步红先立钉、改动即提交、闭案通报评审（既有纪律不变）。

## 7. 行为层附件：交互状态机清单（2026-09-01 amp 裁决采纳）

每个可交互 UI 插件须有《交互状态机清单》——"皮必须表现的全部状态"的
形式语言。条款五要素（缺一不完整）：

1. **状态枚举**（词汇表唯一真源：观测环/钩子/考卷的状态名必须直引
   清单枚举词；清单外状态名=规格外状态=bug 候选，即告警）；
2. **转换表**：用户手势与环境事件**同列**（混成系统：离散状态+连续
   时钟+环境分流——vv/IME/visibilitychange/字体时序都是一等公民）；
3. **禁止条款**：把"隐藏体验"显式化为红线（无确认不发破坏性命令、
   HIDDEN 不留 DOM、乐观状态必须被事实源校准……）；
4. **可观测性约束**：单源 reducer + 同步查询钩子报全机位 + 转换环形
   缓冲 ≥50 条 + 专症按需落盘（不常驻状态流）；
5. **考卷映射**：每条转换一颗钉（红先）+ 时序预算（转换时限，超限=红）。

**四步纪律**：清单用户签收 → 考题先行 → 实现 → 变异抽检。
**结晶制**：清单起步只含用户点名需求+bug 结晶转换；同组件第二次行为
bug → 全状态空间立项规格化（防全组合枚举烂尾）。
**试点**：tmux-tabs v2（清单 docs/tmux-tabs-v2-state-machine.md，
2026-09-01 用户三轮仲裁+评审四修正后成型）。
