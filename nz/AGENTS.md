# nz 开发纪律

## Bug 修复验收纪律（强制）

所有 bug 修复在提交前必须完成至少两条**互相隔离**的验证路径。路径不能是同源断言的重复，必须具有独立的失败模式。

### 路径层级

| 层级 | 路径 | 验证什么 | 独立失败模式 |
|---|---|---|---|
| L1 | **自动化考卷**（Playwright headless / browser test） | 行为规格是否成立 | 夹具脏、断言写错、headless 与真机差异 |
| L2 | **服务端真值互证**（tmux ls / pty 日志 / 文件系统） | 前端状态与服务器事实是否一致 | 前端状态机自欺欺人 |
| L3 | **真机/CDP 观测**（8026 attach、截图、钩子读数） | 真实浏览器/真实设备上的像素和时序 | headless 无法模拟的 vv、字体、IME、GPU 行为 |
| L4 | **纯逻辑/单元测试**（状态机、纯函数、typecheck） | 规格本身是否自洽 | DOM 和异步干扰，但可能漏环境相关 bug |

### 按 bug 类型选路径

- **普通 bug 修复**：至少 **2 条**，推荐 `L1 + L2` 或 `L1 + L3`。
- **涉及真机交互的 bug**（键盘、滚动、TUI、动画、启动流程）：至少 **3 条**，`L1 + L2 + L3`。
- **架构级/状态机级改动**：至少 **3-4 条**，`L1 + L2 + L3 + L4`。

### 执行纪律

1. 每条路径必须独立写结论（通过/失败/存疑）。
2. 路径结论打架时，先定位哪条观测手段不可信，再修代码。
3. 严禁用同源断言凑数（例如考卷和 console 脚本都只看 `state === 'EXPANDED'`）。
4. L2 服务端互证必须有可复现命令（tmux ls、ss、日志 grep 等）。
5. L3 真机观测优先使用 nz 实验台 CDP（8026 attach）；若无法用真机，需在通报信中声明并降级为 L1 + L2。

## 提交纪律

- 修改即提交，不积压半成品。
- 提交信息说明行为变更，不堆砌无意义形容词。
- 考卷版本号随清单同步升级。
