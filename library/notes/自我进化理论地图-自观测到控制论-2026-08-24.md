## 一、核心命题

> **自我进化的前提不是"能否生成新代码"，而是"能否被自己改不动的东西诚实地验证"。**

- 自我修改（DSH 式：自己装插件/升级自己）= 改能力与配置，相对易。
- 自我进化（真正的）= 改"改自己的那个东西"，跨能力边界。前者是后者的必要条件，非充分。
- 二者之间最关键的一环：**自我测试与自我观测**。没有自观与自验，自我修改就是盲改。

## 二、自观三件套（区别于"被动看"）

> 观测不是相机，是"装观察者 + 做实验 + 回放"。

| 层 | 是什么 | 对付什么 |
|---|---|---|
| **按需自插桩** | 在怀疑的那一行当场加探针/断点、重跑、读精确值 | 预埋日志覆盖不了未知点；按需插桩能 |
| **假设-干预-再观察** | 观察(坏)→假设(X)→最小改动/探针→再观察(是否按假设变)→锁死 | 纯看无法定位，看+干预才定位 |
| **确定性回放** | bug 慢速回放、最高分辨率看 | 让 bug 可复现、可归因 |

**判据层（与三件套并列的地基）**：
- **判据要可信**：变异抽检（故意改坏答案看考题抓不抓得住）——唯一能对付"测试与实现同流合污"的机械手段。kfmv4 教训："考题弱 → 测试全绿行为全错，谁判判卷人"。
- **判据要外部化**：让 AI 对照**它改不了的外部事实**（真实运行/真实验收/真实指标），而非自己写的断言——否则就是让作弊者当裁判。
- kfmv4 心法 25/26/27（真实数据验证/成本不对称/代理指标）正是"判据可信"的纪律化。

## 三、手段 → 成熟学科映射表（"看清项目"这半边有大把理论可借）

| 观测手段 | 成熟学科/理论 | 代表技术 |
|---|---|---|
| 日志/指标/追踪 | 可观测性三支柱 | OpenTelemetry、Prometheus、Dapper |
| 验证代码正确 | 软件测试 + 形式化验证 | 覆盖度、变异测试、属性测试(QuickCheck)、模糊测试 |
| 定位 bug | 调试科学 | Delta 调试(ddmin)、程序切片、故障定位、Zeller《Why Programs Fail》 |
| 按需插桩/运行时检视 | 动态程序分析 + 插桩 | 断点、采样 profiler、侵入/非侵入插桩 |
| 回放/复现 | 确定性重放 + 可复现性 | rr、time-travel 调试 |
| 性能/负载 | 排队论 + 性能工程 | Little's Law、profiling、容量规划 |
| 假设→干预→观察 | 因果推断 | Pearl do-calculus、随机实验、A/B 测试 |
| 系统全局反馈 | 控制论 | Kalman、能观性 Gram 矩阵 |

## 四、控制论主框架（本笔记的理论脊柱）

> **agent 是黑盒，控制论有把黑盒按需可控化的完整方法论。** 你提出的每个概念都有精确对应。

| 用户概念 | 控制论对应 |
|---|---|
| 自我观测 | 能观性(Observability) + 状态观测器(Observer/Kalman) |
| 自我测试 | 参考/设定值(Reference) + 误差信号(Error=实测−参考) |
| 自我调试/定位 | 系统辨识(System ID) + 扰动实验 |
| 自我修正 | 负反馈闭环(Feedback) |
| 自我进化/自我修改 | 能控性(Controllability) + 自适应控制(Adaptive) |
| 决策轨迹语义化 | 系统辨识（黑盒→灰盒的第一步） |
| 过程一致性检查 | 参考轨迹跟踪 + 误差检测 |

**三条硬判据（引用控制论来检验自己）：**
1. **能观 ＋ 能控 是可控的充要前提。** "看不清状态"＝不可观；"不知道从哪干预"＝不可控。这是控制失效的两个必要条件。
2. **处理黑盒标准三部曲**：系统辨识（建模）→ 状态观测（重构）→ 反馈控制（闭环）。你的路线与控制论同构。
3. **没有设定值就没有控制。** 判据/地面真相/好的标准路径 = setpoint，且必须在被控系统够不着处（判据外部化）。

## 五、研究纲领：决策轨迹语义化 × 过程一致性检查

> 用户原话凝练："从 agent 的思维工作对话记录里抽象出标准的思路"——这是真的研究，且不空白。

**成熟学科交叉**：过程挖掘（van der Aalst：事件日志→过程模型+**一致性检查**）× 论证语义学（RST/argumentative zoning：推理步功能分类）× 可解释性（机制）× RL 技能发现（轨迹→可复用技能）。DSH 的 CoT-leakage 8 类 taxonomy 是微观种子。

**关键设计**：必须是**闭环**（抽象标准路径 → 一致性检查发现偏离 → 偏离当修正信号 → 喂回），否则只是"描述性考古分类学"。价值在闭环，不在 taxonomy。

**真正开放的两处**：① LLM 轨迹是乱序/自由文本/异质工具调用，适配过程挖掘到 LLM 决策记录是开放问题；② "好的推理"地面真相难定——需判卷尺校准（复用 kfmv4 判卷/变异抽检纪律）。

## 六、自指极限（分水岭）

> 控制论给框架与词汇，经典方法（LQR/PID/Kalman）不能直接套 agent。

- 工程层（能观/能控/反馈/设定值）有成熟方法——**看清项目**这半边可踩实建。
- 自指层（agent 修改自己的 plant + controller + setpoint）——**控制一个正在试图控制自己的系统**，是控制论没驯服的无人区——**看清自己的思维**这半边是真前沿。

## 七、落点（kfmv4/na/nz 共同方向）

- **优先级**：自观可观测性（尤其运行时/决策状态层）**高于**功能推进——它是战略能力，不是功能。但须锚定"看清哪一层"（不可观/不可控那层），勿吞项目。
- **na/nz 待打磨**：na 现有截图/文本/控命令行 = 看症状（外部观察）那半边；缺**内部插桩 + 实验 + 回放**，再往里是**决策轨迹语义化**。
- **家底**：kfmv4 已有 check 闸、history、心法、可回放会话、DSH Trajectory 种子——自观基建的四梁八柱已部分在手，闭环差"决策层"这一块。
