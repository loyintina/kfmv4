## 需求缘起（用户原话要义）

2026-04-06，用户在手机上用 Claude Code，给出 kfmv3 的原始需求：

- 本体：一个**面向手机浏览器的网页程序**（工作台）
- 素材三源：
  1. `~/w/项目/termux-operitai/写入区/kfm/` ——已做好的样式（动画、盒子样式、交互逻辑）
  2. `~/w/项目/kfmv2/` ——canvas 技术栈 + CI 与测试系统
  3. `~/w/信箱/prompt_context_harness_farm/`（四个文档）+ `~/w/信箱/kfm_design.md` ——设计参考
- 任务：在 `~/w/项目/` 建 kfmv3 项目文件夹，用 kfmv2 技术栈复刻 kfm 的样式设计
  与 kfm_design.md 参考，**并融入 prompt_context_harness_farm 的设计思想**

## 为什么 kfm 离开了手机（第一手事故记录）

会话后半程全部卡在 Claude Code 在 Android/Termux 上的沙盒权限问题：

- Bash 工具需要 `/tmp/claude-10496` 作工作目录，Termux 上不存在且无法创建
- 尝试 `~/.claude/settings.json` 禁沙盒（`sandbox: {enabled: false}`）——写入成功但
  **需重启会话才生效**，重启后仍未验证通过
- 用户问"禁用沙盒后你就可以跳出工作环境操作外部文件了？"——是，但配置始终没跑通
- 最终用户 `/exit`，4-8 号之后 Claude Code 在手机上死亡，`.claude` 目录 4 个多月零活动

推论：kfm 系列从手机（Termux）迁往服务器的原因之一是 **Claude Code 类工具在
Termux 上沙盒不可用**——这是 kfmv3 之前的技术约束，不是设计选择。
