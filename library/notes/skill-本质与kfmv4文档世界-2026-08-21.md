# skill 的本质与 kfmv4 文档世界——一条概念线的闭环笔记

> 这是什么：2026-08-21 会话讨论的整理笔记——从「skill 是什么」一路推到
> kfmv4 知识体系的全景定位。
> 素材来源：agentskills.io（Agent Skills 开放规范）；library/collected/ 下
> grill-me 与 brainstorming 两条剪藏；experiments/README.md；docs/guides/spec-driven.md。
> 性质：研究笔记（非剪藏），内容为对话蒸馏，非外部原文。

## 一、skill 的本质

剥到底，skill 就是一个文本文件（SKILL.md：YAML 头 + Markdown 正文，可挂 scripts/references）。
被"调用"时系统做的事只有一件：**把正文原样注入对话上下文**——没有执行、没有注册、没有运行时。

- 不是工具/函数：工具 DO 事情，skill 只 SAY 事情
- 不增加能力：模型权重不变，变的是它**此刻知道该怎么表现**
- 不是 RAG：无向量检索，触发靠模型读 description 自判
- 加载机制是三段渐进披露：启动只读 name+description → 匹配才读全文 → 执行中按需读附带文件

为什么三行字能改变 agent 行为：模型是通用指令追随者，prompt 是写进工作记忆的
自然语言程序；skill 只是把这个事实工程化——**prompt 的资产化 + context 的按需加载**。
类比：prompt 是口语（随会话消散），skill 是文字（知识脱离单次对话存活）。

## 二、概念演化线（为什么 skill 压轴出现）

API → prompt → context → agent → harness → subagent → **skill**

skill 必须最后出现：它要等 agent 有工具（能读文件）、harness 有约定（扫描目录）、
上下文贵到值得省，才有存在的意义。前面每层解决"这一回合模型看到什么"，
skill 解决"哪些知识不必每回合都在场"。

## 三、kfmv4 文档世界 = 同一想法生长成的建制

skill 是「零上下文继承」的原子单位；kfmv4 文档世界继承的不止事实，有三层：

1. **知识**：契约、SOP、指南——系统怎么运作（skill 只覆盖这层）
2. **纪律**：心法、LEVEL 约束、沉淀五问——什么比功能更重要（skill 标准无此类别）
3. **状态**：stack.yaml、history、agent-inbox——现在进行到哪（skill 不碰状态）

另一个维度差：skill 是平铺原子，无生命周期；kfmv4 是有向图 + 时间轴——
文档互相引用、有任务型/参考型命运判定、check 脚本机械保证「仍然为真」。
**skill 回答"怎么继承一份事实"；kfmv4 回答"怎么让一茬茬 agent 永远继承一份仍然为真的事实"。**

## 四、中间层：pack 与"换项目还成立吗"判据

原子（单个 skill）与整体（项目文档世界）之间的中间层，市面带名字：**pack / plugin**
（superpowers 即一捆互相咬合的 skill+命令+钩子）。kfmv4 内部也已长出中间层：
`docs/domains/{域}/`（有边界的域契约簇）、workflow、library/notes/ 的研究簇。

中间层该装什么事实，判据一条：**"换一个项目，这坨事实还成立吗？"**
成立 → 可携带资产（手艺跟着人走）；不成立 → 留在项目文档世界（房子留在原地）。

必要性不看三层对称美感，看两个痛点信号：单个 SKILL.md 装不下（开始互相引用）；
想带走时被项目拽住（知识散落埋在项目特定叙述里）。

## 五、全景：车间—仓库—出厂

| 角色 | kfmv4 对应 | 职能 |
|------|-----------|------|
| 生产车间 | `experiments/`（coldstart/paradigm/docprobe/dsh-na/agent-mailbox） | 生产中间层事实：协议/试卷/地面真相/判卷尺/挂证据的报告 = 事实的出生证明与质检记录 |
| 仓库 | `library/` | 存放类资料：剪藏 + 研究笔记，可检索不占执行者注意力 |
| 质保 | check 链 + 实验契约 | 机械保证事实持续为真、结论挂证据 |
| 出厂 | **（缺）** | 结论毕业 → 打成可携带包（skill/pack）→ 发给别的项目/工具/agent |

最妙的一桩对应：**coldstart 研究的问题（冷启动 agent 接手需要什么）与 skill 要解决的
问题（零上下文 agent 直接继承事实）是同一个问题**——一个在做科研，一个在做工程范式。
实验线是在给 skill 这类包装测定内容物。

「出厂」这一步现在不造：按 experiments 契约原则 5（模式从撞墙中演化，
不预先设计没被撞过的需求），等第一条结论真的要离开这栋楼时，
包装的形式自然会从那次搬运里撞出来。现在最多顺手标记哪些资产"可携带"。
