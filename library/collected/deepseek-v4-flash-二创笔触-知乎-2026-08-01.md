## 正文

我把流程包装成 skill 了！有两个重要文件，一个是扫描照片得到结构张量，这个是固定的，另一个是让 agent 重写的绘图脚本，是在结构张量基础上纯文本识别出照片元素，从而创造出特定的笔触。另外这个 skill 也包含了星月夜的结构张量信息以 json 文件存在用以进入上下文。

怎么看出它有没有二创呢？看一下屋檐，是顺着纹理方向绘制的，滤镜这种基于像素的变换是做不到这种修改的。基于图像元素特定的修改笔触正是 agent 能力所在！

没想到随便一试的回答突然火了。那我再补充一点细节。

看到一个回答说，让 deepseek 去扫描结构张量学习一下笔触再用 svg 重绘。

起了兴趣于是 pi agent+flash，先扫描了星月夜，然后再去扫描这张苏州河拍三件套的照片。笔触进入上下文了那 svg 重绘一下。

那一刻仿佛核弹爆炸瘫坐在椅子上！

注意，这不是多模态，也不是让 deepseek 直接从零画三件套照片！是让 flash 通过图像处理工具提取星月夜的笔触信息，这些笔触信息自然就进入到了上下文中。而后是一样的操作，通过图像处理程序（也不算是图像处理，本质上就是图片的多维数据进入了上下文）了解到三件套的真实照片长这样。而后把笔触信息叠上去。这里并不是加上了滤镜，因为根本没有一个被称为滤镜的文件，而是 flash 基于照片的多维数据进行了二创！二创后再渲染出图。我也尝试了让 flash 根据照片的数据想象一下从侧面看的东方明珠的样子，但很遗憾这个效果就不佳。

anyway！简单来说，就是 flash 通过触觉知道了星月夜的风格，然后在照片上雕刻！

## 要点提炼

1. **核心机制**：DeepSeek-V4 Flash + 图像处理工具，把名画（星月夜）的**笔触结构张量**提取进上下文，再据此对真实照片做 SVG 重绘——"二创"。
2. **不是滤镜**：基于图片多维数据进上下文后由 agent 重绘，非像素级滤镜叠加；屋檐顺着纹理绘制是区分点。
3. **实操路线**：pi agent + flash → 扫描笔触（结构张量 json 进上下文）→ 扫描目标照片 → SVG 重绘。
4. **局限**：让 flash 根据照片数据想象"侧面看东方明珠"效果不佳（想象性生成仍是短板）。
