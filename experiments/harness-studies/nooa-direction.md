## 1. 核心概念（一句话）

**一个智能体 = 一个 Python 类**：字段=状态，方法=能力，docstring=提示词，
类型注解=输入输出契约。方法分两种——有函数体的是确定性代码，函数体只写
`...` 的由 LLM 在运行时驱动。**灵魂（LLM 决策）与肉（确定性逻辑）在同一
接口下自由配比**——与我们「灵魂和肉」分解直觉同构，他们做成了语言级机制。

## 2. 六个模型侧接口能力（论文主张：首次集于同一接口）

1. **Typed I/O**：方法签名即契约，模型输出违约自动重试（省纠错轮次）
2. **Pass-by-reference**：大数据留在活 Python 对象，模型只看 preview
   （不全文回灌上下文——从工程侧解我们的「注意力稀释」问题）
3. **Code as action**：模型在 Jupyter 式 REPL 写 Python（循环/条件/库），
   不从固定工具菜单挑选——**循环密集型任务的轮次压缩 10-50×**
4. **Programmable loop**：开发者可编程智能体循环
5. **确定性门控**：验证器做成类型化方法当硬门（代码判定通过才算数）——
   与我们检查脚本/错误码自修正回路同哲学，形式更优雅
6. 上下文/事件 API（model-callable context）

**实测成绩（论文口径，待我们复核）**：SWE-bench Verified / Terminal-Bench 2.0 /
CyberGym 上**约一半 token 成本达到或超过 SOTA**。

## 3. 与我们架构的对照（2026-08-07 讨论结论）

| 维度 | kfmv4 tool-flow | NOOA REPL |
|---|---|---|
| 工具循环 | 每次往返 = 一次完整 LLM 调用（带思考链），历史全量重发（缓存抵消大部） | 模型写循环代码，1 次调用 + 确定性执行 |
| 大工具结果 | 全文回灌上下文（贵+稀释） | 活对象引用，模型只看 preview |
| 格式错误 | 浪费整轮 | 契约校验自动重试 |
| 幻觉边界 | 工具白名单+写监狱+沙箱 | AST 校验+deny-list（纵深）+OS 沙箱（边界） |

**「快几个量级」直觉的裁决（2026-08-07 讨论）**：不成立——harness 不换发动机，
LLM 推理瓶颈不变，论文实测是「省一半」不是「快百倍」。真实增益集中在三类
任务形态：循环密集（轮次 10-50× 压缩）、大数据搬运、格式纠错。

## 4. 课题靶点（e20 候选，未点火）

**正确问法**：在什么任务形态下，REPL 式 harness 比工具菜单式 harness
快多少、省多少、精度谁高？（不是「它比我们快多少」。）

**草案**（基建全可复用 session-runner/batch-run/judge-llm）：
- 同模型（v4-flash）× 三族任务（循环密集 / 数据密集 / 讨论型对照——
  对照组理论上两架构应无差异，有差异说明测量有鬼）
- 双 harness：我们的 tool-flow vs 沙箱 pip 装 nooa 跑原版
- 四指标：墙钟时间 / token 消耗 / LLM 调用次数 / 任务成功率
- 每格 8-10 臂（架构级差异若存在会很大，不需大样本）

**预期产出**：我们自己尺上量出来的架构差异曲线，与范式包、冷启动同级的
认知资产；对 C（面板挂载开关）和工具压缩机制有直接参考价值。

## 5. 安全姿态备忘

论文明示：AST 校验与模块 deny-list 只是纵深防御，**真正的容器边界是
OS 级沙箱**（他们配 NVIDIA OpenShell）。与我们「写监狱不是 chroot，
执行层再拦一道」的纪律同构——若开工，nooa 必须跑在隔离环境里。
