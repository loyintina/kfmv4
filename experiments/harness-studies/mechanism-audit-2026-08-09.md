# 机制体检报告（2026-08-09）

> **这是什么**：对 `docs/active/mechanism-registry.md` 17 个机制的失效信号做逐个验证——
> 每个机制声称"坏了现实会叫"，验证这个信号真的会叫。
> 方法：探针覆盖盘点（check-probes 夹具）+ 可测性分析 + 缺失补强。
> 背景：机制注册表（递归终止框架）落地后，地图需要一份体检报告。

## 体检方法

对每个机制问三问：
1. **失效信号**是否明确？（注册表里的"现实怎么叫"）
2. **有验证手段吗**？（探针夹具 = 检查器对负例必须报红）
3. 没有探针的，是**可补**（纯逻辑检查）还是**豁免合理**（依赖 git 历史/运行时）？

## 结果：17 个机制全部有失效验证路径

| 验证方式 | 机制 | 状态 |
|---|---|---|
| 探针夹具（11） | 检查链/探针自检/工作流消费门/文档预算/落成门/BAR 钉/权限引擎/生成器族/数据区结构/工具压缩登记/工作流系统 | ✓ 负例必报红 |
| git 历史型豁免（3） | 契约新鲜度 / 耦合门 / secrets 扫描 | 依赖 git 历史，造假成本高，真实环境天然检验——豁免有据 |
| 运行时 BAR 钉（1） | 读写监狱 | 路径逃逸有运行时测试钉 |
| 滞后信号 + 抽查（2） | external-sources 登记 / 错误码引导 | 接受滞后（升级踩坑才知/失败才引导），用户抽查兜底 |

## 本轮补强：2 个核心检查器探针

- **check-kfmv4-data**：加 KFM_PROBE_ROOT 注入 + 夹具（账本回潮根目录负例）——数据区结构是
  2026-08-08 新建机制，最该被验证。
- **check-tool-compaction**：加 KFM_PROBE_ROOT 注入 + 夹具（工具无压缩登记负例）。
- 探针总数 22 → 24。

## 发现

1. **探针体系覆盖良好**：核心机制（安全/数据完整性/文档纪律）基本都有"坏会叫"的锚点。
2. **两个 git 历史型豁免合理**：contract-freshness（域代码 vs 契约时序）和 secrets
   （工作树扫描）本质依赖 git——造假 git 历史成本远超收益（check-probes 既有豁免条款）。
3. **错误码引导是弱信号**：构建失败无引导码时，agent 可能瞎修——但这是"引导缺失"不是
   "机制坏"，可接受（错误码表有登记规程）。
4. **下一批缝隙候选**：注册表里"机械化=约定"的机制（external-sources、工作流系统的手工
   部分）——若长期无真实使用触发，按退役规则处理。

## 报错引导审计（撞墙含金量，2026-08-09 追加）

**背景**：机制税讨论修正——高频失败=机制在呼吸（不是税）；真税=撞了没学到
（报错无引导/被无视/重复同错）=墙倒了。报错提示本身是教育引导。

**审计**：54 个有 console.error 的脚本，29 个带引导（⛳ 错误码 / 读 xxx / 跑 xxx），
25 个无引导。无引导的 25 个按错误码体系判断标准（自解释不加码）初步分类：
- 自解释型（报错文本已说清修正，符合标准不加）：deploy-freshness（跑 deploy-fast）、
  secrets（删 key）、versions（打 tag）、uncommitted（提交）、gen-route-table（包裹标记）、
  probes/checks（转发子检查器自带引导）等
- 半引导型（位置明确但无修正指引，可后补）：as-any（escape-ok 标记在第二行）、
  commit-docs（docs:na 说明在第二行）、console（位置无修法）、doc-symbols 等
- 待核实型（{msg} 转发，需看实际输出）：cards/css-wiring/docs/hooks/registry/
  schema/inbox-heartbeat/code-doc-refs/card-meta/doc-linerefs/zindex/anim/test-patterns

**标准（预防性条款）**：新检查器/改检查器报错，必须带"病因 + 位置 + 修正路径"三者；
存量无引导者不批量补（反预设），等撞到"报错后 AI 反复不会改"的墙倒案例再逐个补。
