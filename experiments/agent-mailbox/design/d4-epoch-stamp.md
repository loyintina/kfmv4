# D4：代际戳落地设计（状态戳格式化 + 过期回执对账判红）

> 2026-08-18 · 评审会话
> 上游：phase2 契约 3 原文——「**代际戳**（NA 实例比对映射）：状态列更新带
> 更新者+日期，过期回执覆盖新状态对账判红」；D3 设计稿机械件 3 草拟
> （「状态翻转在信件侧留下更新者+日期」）；沙漏送审第四条（防旧撤销条
> 误删新状态的文档世界版）。
> 关联：check-agent-inbox e 查（停滞检测，现时钟 = 发信日，本稿落地后换
> last-touch）、D2 险情 2（旧会话内存覆盖新状态）、Q4（回执契约）。

## 问题

状态翻转目前只在 `> 状态:` 括号注里**约定俗成**地带日期（「已回（2026-08-16
9.0 回信：…）」），但不是机制：

- 无格式约束——写不写、写哪、什么格式全凭习惯；
- 无对账——旧会话拿过期视图把状态翻回去，没有任何检查能发现（契约 3
  点名的「过期回执覆盖新状态」当前零防御）；
- e 查停滞时钟只能用发信日——一封发信 6 天、昨天刚推进过的信不该算
  停滞，但 v1 分不出来。

## 设计决策

### 1. 载体：不加第八字段，戳骑在状态字段里

正式化既有括号注为机读格式：

```
> 状态: ✅ 已回（2026-08-18 茉莉：五条裁决全入 preface）
         ↑词表词  ↑YYYY-MM-DD ↑更新者  ↑自由备注（可省）
```

理由：契约原文说「状态列更新带更新者+日期」——戳随状态走；另立
`> 戳:` 字段 = 同一事实两处维护 = 双事实源（沙漏送审第三条「同名=报错」
的教训）。既有 44 封里 29 封已天然合规，说明这是实践自己长出来的格式，
本稿是收编不是发明。

### 2. 两类豁免（戳缺省 = 发信日）

- **待\* 状态**：尚未翻转，最后推进时刻 = 机读头「日期」；
- **纯通报**（收敛判据 = 无需回信）：状态永不翻转，括号注免日期
  （现存 8 封「通报完毕（无需回信）」即此型）。

### 3. 机检：check-agent-inbox 新增 f 查（三小条）

- **f1 戳格式**：非豁免状态的括号注必须含 `YYYY-MM-DD + 更新者token`
  （更新者 v1 只要求非空 token，不校验线名词表——先观测实践再收束）；
- **f2 戳单调**：戳日期 ≥ 机读头「日期」（戳不可能早于发信）；
- **f3 头体咬合（对账判红本体）**：信体签名行（`——线名 · YYYY-MM-DD`，
  一轮追加一条的既有 convention，27/44 封有据）的最大日期 ≤ 戳日期。
  违反 = 信体有比状态戳更新的轮次——翻转忘更头，或**旧头覆盖新态**
  （过期回执），判红。只扫签名行不扫全文，正文提及未来日期不误伤。

### 4. e 查时钟切换

last-touch = 戳日期（豁免情形 = 发信日）。停滞语义从「发信超 7 天」
升级为「**最后推进超 7 天**」——阈值参数 STALE_DAYS 不变，误报面收窄。

### 5. 生成器零改动

README 台账状态列是机读头原文投影，戳随状态列自动进台账，不加列
（D3 草拟「投影行尾注 last-touch」实证不必要——原文已携带）。

## 过渡方案

1. **存量 7 封**非豁免但括号注无日期的信（全为 8-15/8-16 前 D3 时代）：
   LEGACY 豁免列入脚本常量（同 LEGACY_NAMING 模式，信件只追加不删改，
   不回填改写历史）；其 last-touch 回退发信日，与 v1 行为一致；
2. **新纪律**（写进 README 阅信纪律「读后即翻」条）：翻转状态必带
   `（YYYY-MM-DD 更新者…）` 括号注；
3. 落地顺序：本稿送审（茉莉表态 + 用户终审）→ f 查实现 + README 纪律
   增补 + 登记（error-codes 新码 / 机制注册表历史节）→ e 查时钟切换。

## v2 候选（本稿不做，列出备议）

- **暂存区对账**（commit 时 git 耦合）：状态字段在 diff 中变化时，新戳
  ≥ 旧戳且状态机序位不倒退（倒退须带「回退：理由」标注）——能拦
  f3 够不着的同日并发覆盖。挂 check-commit-docs 同款暂存区检查位。
  缓建理由：词表 ≠ 全序（过程态分叉：已收到/已回应/已会签不在主链上），
  序位映射要先定稿，设计量超本稿。
- **更新者词表收束**：实践跑稳后把更新者 token 对齐线名集合。

## 风险与不做

- f3 依赖签名行 convention——新信回信不带签名行则该轮对账失明
  （f1/f2 仍有效）；签名行写进 README 送信/回信格式要求，从 convention
  升纪律；
- 不引入 git 历史反查回填 LEGACY 7 封（能查准，但改写历史信头违反
  「只追加不删改」，豁免比回滚干净）；
- 不做实时 watcher（Q7 另案，立场延续）。
