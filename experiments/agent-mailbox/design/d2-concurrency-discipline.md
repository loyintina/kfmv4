# D2：多 agent 并发协作纪律（共享工作树约束下）

> 2026-08-18 · 评审会话（用户动议：agent 并发需要纪律）
> 上游：phase2 契约 3「即刻手工纪律两条」（回信自更新状态列 / commit 只 add
> 自己线文件）。本稿不重复定稿，只补 2026-08-17/18 实战撞出来的新三条。

## 根本约束

所有 agent 共享同一个工作树（/root/kfmv4 一份检出，四线同时读写）。
纪律管的是「撞车概率」与「撞车后归因」，不做工作区隔离（worktree/分支
是重型方案，当前规模下隔离成本 > 撞车成本，不取）。

## 实战险情账（每条有实证）

1. **同文件竞写**：2026-08-18 18:32，评审与 9.0 线同分钟写 agent-inbox
   README（各自追加不同行），靠 append 语义侥幸无损。
2. **提交边界混入**：茉莉 inbox 提交曾把评审的未提交信件卷入；评审回信批
   一度误以为「已被顺带进库」（实际未提交，HEAD 计数滞后暴露）。
3. **链红串扰**：茉莉在途 compact 工具使 check-tool-compaction 变红，
   评审的全链验证被别线工作流中断。
4. **台账手写漂移**：审计实证（漏登/倒挂/计数滞后）+ 本日计数五连追
   （33→36→38→40→42）。→ 结构性根治归 D3，不在纪律范围。

## 纪律三条（契约 3 两条之外的新增）

- **写后即交**：对共享热点文件（台账、索引、计数、registry），编辑完成
  立即提交，开放窗口压到分钟级；持有未提交共享文件改动跨任务 = 违规。
- **改前重读**：编辑共享文件前重读磁盘最新版（git log/status 确认无人
  刚交），不信会话内存里的旧印象。追加操作用 append 语义（尾部加行），
  不重排他人行。
- **链红先归因**：检查链变红时先 `git status` 看有无比线在途文件——红在
  别线工作流内（其 src/docs 改动对应的红）不替修、不惊动，等该线自己
  收；红在公共面（台账/索引/生成物）才出手，且先查是不是自己的漂移。

## 与各线职责的衔接

- 路径归属沿用现有分工（kfmv4 本体→茉莉；nine-zero→9.0 线；dsh-na→NA 线；
  台账状态列按线分工见 README）；跨线信/公共面 → 评审仲裁。
- 机械化路径：「commit 只 add 本线文件」的脚本化检查（契约 3 git 卫生 v0）
  与台账生成化同属 D3 落地范围，落地后本条纪律的遵守由机检兜底。

## 边界

- 纪律是 v0 手工层；撞车成本显著上升（如三线同周改同一契约文件）时再议
  隔离方案，不预设。
- 长驻 agent（不重启会话）覆盖不到「改前重读」的时机——归 Q2 停滞检测
  与归属行扫描器（契约 3 机械件）补位。
