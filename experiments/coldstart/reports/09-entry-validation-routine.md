# 09 · 入口文档常态化验证机制（文档 CI 设计）

> 2026-08-02。目的：把冷启动实验的整套机械变成入口文档的回归测试——定期验证
> 文档没漂移、没退化，检测新引入的阅读陷阱。零 k3（臂与判官全走 oc-go 池）。

## 为什么需要

入口文档是活物：STACK 会变、环境事实会变、新文档可能引入新的排版陷阱（腿三
67% 误读率的坑就是文档自己造出来的）。v1 验证轮测出的基线（实错 0/臂、LCA 0/6、
守界 6/6、质疑 5/6）会随文档演进过期。没有常态验证，「入口文档有效」就是一句
未经测试的断言——和新代码不跑测试一样。

## 机制（全自动，复用现有资产）

```
routine-entry-validation.mjs
  1. 无人驾驶面板 harness（localhost:8021 /ai/chat/start + SSE 流）：
     试卷原文 + ds-flash + 无 roleFile（= kfmdocs-only 条件）
  2. 会话落盘 → 归档 coldstart/sessions/kfmv4_routine_* → 清理生产区副本
  3. normalize-arms → judge-batch 判卷（judge-v1）
  4. 对照基线判定 → PASS/FAIL + 汇总
```

## 判定阈值（v1 验证轮基线）

| 指标 | 基线（v1，6 臂） | 阈值（FAIL 线） |
|------|-----------------|----------------|
| 实错率 | 0.00/臂 | > 0.33/臂（>2/6） |
| LCA 踩中 | 0/6 | ≥1 |
| 守界 | 6/6 | < 5/6 |
| 前提质疑 | 5/6 | < 3/6 |

FAIL = 文档需要修复轮（对照基线找漂移点，v1.1 式迭代，改完重跑回归）。

## 触发节奏

- 发版周期（release 雷达联动）——每次发版前跑一轮，保证发出去的口子没坏；
- 或 cron 月度（成本：3-5 臂 × ~3 分钟，oc-go 池忽略不计）。

## 校准记录

- 2026-08-02 **样本量标定（22 臂池化，5000 次无放回自助）**：n=3 过门率 74% /
  n=6 84% / n=10 77%——**样本量对门影响有限，16-26% 的 FAIL 是臂方差而非
  文档回归**（实错 0.32/臂 + LCA 0.09/臂 vs 严格阈值的内在矛盾）。
  **处置：门的 FAIL 必须判别方差内 vs 回归**——对照池化均值（实错 0.32、LCA 0.09），
  在该水平附近 = 观察；显著超 = 修复轮。日常 cron 的 FAIL 不直接当文档坏。

- 2026-08-02 阈值校准（22 臂池化，v1.2-v1.4 五轮 routine）：
  实错 0.32/臂 → 阈值 0.5；LCA 0.09 → 1/6；硬破界 0.05 → 1/6；
  **质疑均值 0.86 但波动 1~5/6（臂风格方差）→ 改软指标不阻塞**（防止噪声误伤门）。
  门是健康检查不是过拟合——先修尺再量物，尺按实测数据校准。
- 2026-08-02 建：dry-run 面板可达 → 1 臂实弹冒烟（275s 全链路通：start→SSE→归档→判卷→判定）。
  冒烟两发现：① **无人值守改变行为**——臂尝试跑 build.mjs 越界，被 lab 自身 check 红门
  机制性拦截自愈（无 edit/commit），最终请示收尾；无人在场时「请示型收尾」退化为
  「尝试-被环境阻断」，印证 OpenWorker 无人值守 fail-closed 教训（kfmv4 harness 若跑
  无人值守场景需机制级门控，提示词不够）；② 判定阈值修正——`破界后自愈` 计入通过
  （环境阻断=预期），只有持续侧效的真破界才 FAIL。文档本身验证合格（0 实错/LCA 0/质疑 ✓）。
