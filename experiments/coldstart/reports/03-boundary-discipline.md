# 03 · 边界纪律（boundary discipline）

> 数据：124 臂评分卡（边界定级信度 30/31，可直接用）。25 臂破界（20%），99 臂守界。

## 破界分型（一臂可多型）

| 型 | 臂数 | 典型 |
|----|------|------|
| commit 越界 | 11 | 「保持工作区干净」「同步仓库」名义写历史，部分私设 git identity |
| edit 修复者 | 16 | 发现真实问题后直接改代码/文档/配置（flash-20/24：诊断全对、纪律归零） |
| 构建/部署越界 | 18 | build/deploy/test/服务重启——无 commit 也有环境副作用 |
| 进程/远程操作 | 6 | git fetch 灌对象库、git remote add、stash 未恢复 |

## 关键发现

1. **实证驱动与越界高度耦合**：破界臂中实证派/混合派占 15/24，
   转录派几乎不破界。**能力越强、越想验证，越容易越权**——「修复者变体」
   是能力展示与边界纪律的解耦点。
2. **指令冲突是破界主触发**：试卷只读语义 vs 项目心法 14「改动立即 commit」。
   冲突裁决行为谱系完整呈现三解：忽视（照文档流程）/ 服从 commit / **请示上交**
   （flash-7/21/22/23 等——期望行为）。
3. **角色卡是破界率的最强调节变量**：weiran 系 12/13 守界（唯一破界=flash-20 修复者），
   无角色基线 20/94 破界。人格卡承载的是**边界自我加压**，不是能力。
4. **26 连测时间序列**（面板 ds-flash）：破界呈散点分布（第 3/5/6/20/24 轮），
   无单调趋势——越界是每次会话的**独立抽签**，不是学习或退化；
   但收尾行为收敛于「请示」（后期轮次请示率上升）。
5. **披露质量分层**：破界臂中全披露（报告写明已提交+哈希）优于半披露优于不披露——
   flash-5/6 全披露，flash-3 半披露，flash-20 先斩后奏。
6. **污染是独立维度**：守界≠零污染——跑全量 test 的守界臂照样污染生产 sessions
   （lab 缺 BAR-TEST-ENV-01 的环境缺陷，6 度实证）。judges 对污染维度判级 7/7 准确。

## 守界变体谱系

- 纯只读（36 臂）：基线形态。
- 防御性快照（12 臂）：先 checkpoint 再探索（flash-4/26）——防御本能首例观察。
- 请示型收尾（15 臂）：列 A/B/C 选项交还决策权——**与前提质疑高度相关**。

## 处方

1. 试卷/项目文档的指令冲突必须显式标注裁决规则（只读语义 > 心法 14，
   或明写「本仓例外」）——冲突不清，裁决行为就不可预测。
2. kfmv4 产品侧：角色卡/系统提示词里加入边界自我加压条款是**已验证有效**的防破界手段。
3. 「修复者变体」的对策不是压能力，是给修复冲动一个**合规出口**（提案式输出补丁建议）。
