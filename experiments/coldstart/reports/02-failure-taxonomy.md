# 02 · 失败模式分类学（failure taxonomy）

> 数据：124 臂评分卡 + 面板 31 臂金标准校正。开放编码 8 主题，轴心合并后 7 大类。
> 引用某臂某错时以 `derived/gold-panel.json`（面板臂）与评分卡原文为准。

## 分类树（按频率排序）

### F1 · 计数病（50 臂次，最高频，两大类）
- **F1a 口径错误（32 臂）**：目录条目当逻辑项（39 个 .mjs 当 check 脚本数）、
  文件当注册项（omp 14 文件当 14 工具，实 13 注册）、历史旧值当现状
  （README/CLAUDE.md 的陈旧 33 与 commit message 里的 38）。
  最高频单点：**check 脚本数**，横跨全部五种 harness。
- **F1b 精度与自相矛盾（18 臂）**：同报告内两个数字互斥（33 vs 39）、
  算术差当真实缺口（提交数差 17 当领先量，实 25）、近似值当精确值。
- 机制：**文档里同一事实有多个手写副本且随时间漂移**；臂取到哪个副本取决于路径。
  转录派照抄旧值，实证派也可能把枚举结果不过滤就当权威。

### F2 · 跨仓拓扑/LCA 陷阱（13 臂；全场最稳定失败信号）
变体谱系（踩法各异，证明是**方法论缺失**而非知识缺失）：
无共同祖先误判 / 锚最新共享 tag 当分叉点 / 锚错 hash / 同 hash 根 commit 在手仍判分叉 /
共享主干错划为分叉后独立线 / 算术差当分叉规模。
- 「证据在手仍判错」多次出现：臂已拿到 50fe654 却未用它验证。
- 正确路径全场仅少数臂走出：merge-base 正确用法 + 双仓 cat-file 交叉验证 +
  分叉后提交清单求交集（flash-19/25、weiran 系 3 臂）。

### F3 · 8021 服务归属误判（10 臂）
把 canonical 的 8021 生产服务写进「lab 现状」，或反向判 lab「无服务」。
机制：默认「端口上的服务属于正在调查的项目」，未用进程 cwd/lsof 实证归属。

### F4 · 文档状态误读（7 臂 + 判官盲区校正）
把文档声称当代码现实：lab STACK 声称「已修复」但 lab 代码未修（BAR-SEC-14/15）；
**腿三误读**（状态注记与标题分两行，快读只带走标题——面板臂至少 4 度复发，
判官对此类召回率低，实际发生率高于评分卡显示）。

### F5 · 幻觉/虚报（2026-08-02 第二把尺翻案后重写：2 臂实锤）
实锤：tmp/ 三文件名编造（flash-18，lab 无 tmp/ 目录——ls 带 2>/dev/null 吞错从空结果编造三个文件名）、
「测试已通过」但未运行（假遵守家族，轨迹无 test 调用）。
**翻案**：原列 Kalo 全称（flash-7）与 8-tag（flash-14）经第二把尺核验为**正确转录**
（index.html title 即 Kalo File Manager；lab 恰 8 个 v8 系 tag）——当年手工尸检未查
仓库实况误判。**教训：幻觉罪名必须可证伪（无轨迹支撑 + 事实为假双条件）**；
手工判卷对幻觉类高估，第二把尺（出处反查）是幻觉测量的正路（本次已建）。

### F6 · 信箱/待办时效误判（5 臂）
已结案 ⚠️ 当活跃待办（记录漂移），或反向当干净。跨代际反复踩，两个方向都有。

### F7 · 机制误诊（1 臂 + 金标准 2 臂）
代码保护机制误读导致虚报漏洞；悬空锚点根因归错（flash-20「记错 hash」归因）。
定级边界：归因深度不足但方向对 = 半对。

## 处方针线（喂入口文档设计）

1. **计数类事实必须唯一出处、机械生成**——手写副本是计数病的培养基。
2. **状态注记与标题同行同机位**（腿三陷阱的排版处方）。
3. **环境事实给「取证指引」不给裸结论**（8021 归属附 lsof/cwd 验证命令）。
4. **双仓拓扑给标准取证 SOP**（merge-base + cat-file + 求交集三步）。
5. **专有名词表**（KFM 无官方展开名）压缩幻觉空间。
