# flash 哨兵层设计提案（基于标定 #1/#2 数据，2026-08-04）

> 数据来源：experiments/paradigm/results-flash-calibration-01.md（30+30 臂两轮实测）。
> 定位：语义审计概率区的便宜模型常驻哨兵——双区管线「模糊层」的 flash 化升级候选。

## 一、数据支持的结论（设计依据）

| 结论 | 数据 |
|------|------|
| flash + 只读工具（read/grep/glob）+ 声称注入：**误报 0/60 臂** | 两轮全零，真声称零冤枉 |
| 符号/常量类召回满分（6/6） | colors.ts 幽灵、50dvh 常量（grep 实锤即判） |
| 计数类有单臂方差（M01 5/6~6/6、M11 3/6→6/6） | 需采样并集 + 口径对齐 |
| 格式纪律 30/30（通道稳定后） | 空 text 收尾 = 断连干扰，非 flash 固有 |
| 并发 40 一次全绿（零失败零重试） | terminated = 服务重启干扰；重连+重试兜底就位 |
| 30 臂 ≈ 19 分钟（并发 40，flash 便宜链） | 每日全库成本可忽略 |

## 二、哨兵形态：声称注入式核实（不是开放漫游）

标定最强的任务形态 = **给声称、查现实、报差异**。自动化哨兵 = 把「声称」从
手工注入改为**自动提取**：

```
声称提取器（机械）→ 从文档提取断言（反引号符号/计数/状态词/机制名）
     ↓
flash 核实器（声称注入式，N 臂并集）→ read/grep 查代码现实
     ↓
差异 → 信箱（附 claim/against 行号 + quote）
     ↓
裁决流（现状：人拍板）
```

- 声称提取候选来源：code-map 断言、contract 计数、STACK 状态行、README/CLAUDE 声称
  （提取器是机械的——只提「可 grep 核实」的断言类型，不碰开放判断）
- 已机械化的形态（check-doc-scripts 等）不重复喂哨兵——哨兵只盯机械层覆盖不了的
  （跨文档矛盾、方向漂移、语义级 stale-claim）

## 三、参数建议（基于数据）

| 参数 | 建议 | 依据 |
|------|------|------|
| 并发 | 40 | 30/30 全绿实测；重连+重试兜底 |
| 采样 N | 3 臂并集 | 计数类单臂方差实测（3/6~6/6）→ 并集保召回；误报 0 已证，冗余不为防误报 |
| 频率 | 每日全库 + 事件触发（发版/大改后） | flash 便宜（30 臂 19 分钟）；与 semantic-chain 4:17 巡逻对齐或并入 |
| 工具白名单 | read,grep,glob | 只读核实，禁副作用（标定即用此配置） |
| 模型链 | Opencode Go Google/deepseek-v4-flash（现役链） | 标定对象 |
| 裁决 | 信箱 → 预裁决 → 人拍板 | 现状流复用 |
| 校准 | 周变异基准（--with-bench 模式） | 分数看趋势（历史结论：单轮不作数） |
| 成本 | 每日全库 ~19 分钟、flash 调用 | 可忽略（史官账本 agent-calls.jsonl 可观测） |

## 四、与现役 semantic-chain 的关系

- 现役：每日 4:17 巡逻（23 探针，混合 provider 链，LLM 开放判断）——贵、慢、方差大
- 哨兵：flash + 声称注入式——便宜、可高频、精确率 0 误报（已证）
- 建议：**不替换，先并行**——哨兵跑高频浅层（声称核实），semantic-chain 跑低频深层
  （方向漂移/开放矛盾）——双星系统分层，数据长出来再谈合并

## 五、落地路径（分三步，每步可裁决）

1. **声称提取器**（机械，~100 行）：从目标文档提取「可 grep 核实」的断言清单
2. **哨兵脚本**（scripts/agent/sentinel-*.mjs）：提取器 + batch-run 通道（并发 40、
   采样 3）+ 信箱投递（差异带 claim/against/quote）
3. **挂 cron**：每日全库 + 发版触发；周基准校准并入

## 六、开放问题（待裁决）

- 声称提取的**断言类型边界**（哪些文档元素算「可 grep 核实」）——先做枚举型
  （计数/符号/机制名/状态词），开放判断留给 semantic-chain
- 采样 3 vs 历史 6 样本并集——哨兵高频场景下 3 并集的漏报代价 vs 成本，需一周
  真实运行数据再定档（先 3，趋势不佳升 6）
- 哨兵发现的**处置流**：直接进信箱 vs 先机械复核（quote 引文契约可复用）
