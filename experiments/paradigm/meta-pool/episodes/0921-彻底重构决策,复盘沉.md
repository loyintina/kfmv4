### 问题全貌

当前 `orb.ts` 里有**两套**会话管理，互不协调：

```
initOrb()                           buildPanelContent()
─────────                          ──────────────────
activeSessionId   ←── 事件桥接 ──   会话选择器 (UI 可见)
loadSessions()                      独立加载 sessions
loadActiveSessionId()              不读 active-config.json
initSessionSelect() ← 死代码!       不更新 activeSessionId
updateSessionSelect() ← 死代码!
saveSession() ← 依赖 activeSessionId
doSend()      ← 依赖 activeSessionId
```

实际能工作纯靠 `kfm-session-change` 事件做了桥接——用户在 UI 选会话 → 事件 → `initOrb()` 的监听器更新 `activeSessionId`。但代码里躺着一整套从未被调用的死代码（`initSessionSelect`、`updateSessionSelect`、`sessionSelect` 变量），而且 `loadSessions()` 加载的 sessions 只用于给 `activeSessionId` 提供一个 `sessions[0]?.id` 兜底值。

### 修复方案

最小改动、不改架构：

1. **删除死代码**：`initSessionSelect()`、`updateSessionSelect()`、`sessionSelect` 变量
2. **删除冗余的 `loadSessions()` 调用**：`activeSessionId` 直接从 `loadActiveSessionId()` 取，不需要 sessions 兜底
3. **保留**：`activeSessionId`、`loadActiveSessionId()`、两个事件监听器（P0-2 会合并它们）、`saveSession()`、`generateSessionTitle()`
4. **`buildPanelContent()` 的会话选择器不动**——它是实际工作的 UI，P1-5 再修它的恢复选中问题

净效果：删 ~40 行死代码，零行为变更。
