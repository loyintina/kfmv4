## 架构全貌

```
BrowserTool (browser.ts)          ← AI 调用入口，解析 params
    ↓ open/run/close action
tab-supervisor.ts                  ← tab 生命周期管理，持久化跨 run
    ↓ 启动 Worker
[Node.js worker_thread]           ← tab-worker-entry.ts 作为入口
    ↓ 连接到
WorkerCore (tab-worker.ts)        ← 2000 行，puppeteer page 的全部操作
    ↓ 通过 CDP
Chromium (headless)               ← puppeteer-core 启动
```

**cmux** 是另一条路径——连接到已经在运行的真实 Chrome，通过 socket 通信，**可选，不影响 headless 核心功能**。

**aria-snapshot** 是 Playwright 的 ARIA 树抓取，编译成 `aria-snapshot.bundle.txt` 注入到页面——纯 JS，可直接用。

| 依赖 | 在哪用 | 能替换吗 |
|------|--------|----------|
| `@oh-my-pi/pi-utils` → `getPuppeteerDir` | launch.ts，Chromium 缓存目录 | 换成 `~/.kfmv4/puppeteer` |
| `@oh-my-pi/pi-utils` → `logger` | 日志 | 换成 kfmv4 的 `log()` |
| `@oh-my-pi/pi-utils` → `postmortem` | abort 错误标记 | 换成直接 throw |
| `@oh-my-pi/pi-utils` → `Snowflake` | run ID 生成 | 换成 `crypto.randomUUID()` |
| `@oh-my-pi/pi-utils` → `workerHostEntry`/`consumeWorkerInbox` | worker 消息预缓冲 | 换成标准 `parentPort.on('message')` |
| `@oh-my-pi/pi-utils/worker-host` | tab-worker-entry | 同上 |
| `@oh-my-pi/pi-agent-core` → `AgentTool` 接口 | browser.ts 入口 | 换成 `KfmTool` |
| `@oh-my-pi/pi-agent-core` → `ToolSession` | tab-supervisor，截图目录等 | 换成 `ToolContext` |

## Chromium

1. 先扫描系统路径（`which chromium-browser`、`/usr/bin/chromium` 等）
2. 找不到则用 `@puppeteer/browsers` 自动下载到 `~/.omp/puppeteer`

kfmv4 改成下载到 `~/.kfmv4/puppeteer`，`@puppeteer/browsers` 已作为 puppeteer-core 的依赖存在，不需要额外安装。
