# H1 对照实验 #1：无范式包 vs measured-decision（2026-08-04）

> 实验线：paradigm 研究（spec-v1 批次 1）。第一个真范式包（measured-decision，
> 3.5k token 短示范）出厂后的首次同化验证。
> 复现：`node experiments/paradigm/tools/batch-run.mjs --task-file <任务> --paradigms "无,measured-decision" --arms 3 --prefix pd-`

## 实验设计

- **任务**：决策型——「kfmv4 接入 deepseek 官方 API，给出完整接入决策过程（确认需求→调研→验证→落地定稿），第一人称叙述思考过程」
  （与范式包同主题——直接测同化效果；对照组/有组同任务）
- **对照**：无范式包 vs measured-decision 范式包
- **模型**：deepseek-v4-flash @ Opencode Go Google（便宜链——H2「弱模型+好范式包」方向）
- **样本**：2 组 × 3 臂（重复测量）；首轮 4/6（2 臂 fetch failed），断点续跑补全 6/6
- **工具**：未限白名单（自由——观察范式包是否改变工具选择行为）

## 结论（H1 初步正信号，3 臂一致）

1. **任务理解改变**：同任务，无组全部理解成「执行」（动手写码+提交），有组全部
   理解成「决策复盘」（叙述决策过程）——任务问的是「决策过程」，范式包臂更贴合
   任务意图。**范式包改变了 AI 对任务的定义**。
2. **token 省 3.6 倍（中位数）**：有组中位 14k vs 无组中位 51k——范式包臂聚焦
   （读证据链→复盘），无组瞎探索（全链路读+外部调研+写码）。成本维度收益显著。
3. **工具选择收敛**：有组 2/3 只用读类（glob/grep/read）；无组全含 bash/web_search
   （执行/外部探索）——范式包示范了「读文档验证」而非「动手改」，行为模式被吸收。
4. **决策结构同构**：有组臂的叙述结构（先问为什么→读现状→复盘）与范式包示范
   （根因→文档→实测→纠偏）同构，无组是通用「需求-实现」结构——**示范被抽象成模式**。

## 混杂与局限（诚实标注）

- 无组 token 高部分因为真的执行（写码）+ r0 异常高（165k，全量探索拉高均值）——
  token 差异与「任务理解」混杂，非纯效率信号；用中位数而非均值
- 任务无工具白名单 → 无组自由发挥；后续控制变量轮加白名单分离「工具选择」与「决策结构」效应
- 未盲判（判卷者知道条件）——后续盲判去偏见
- 单任务单模型（deepseek-flash 便宜链）——H1 需多任务多模型复验
