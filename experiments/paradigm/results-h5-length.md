# H5 长度梯度实验 #1：无 / 短 3.6k / 中 5.8k（2026-08-04）

> 实验线：paradigm 研究（spec-v1）。H5「长度倒 U 形」的下沿采样——同一素材
> （接 deepseek 官方决策）的精编版（measured-decision 3.6k token）vs 全量版
> （measured-decision-full 5.8k token）vs 无。8k/16k 档待素材库扩充。
> 复现：`node experiments/paradigm/tools/batch-run.mjs --task-file <任务> --paradigms "无,measured-decision,measured-decision-full" --arms 3 --prefix pl-`

## 实验设计

- 任务：与 H1 相同（「给出接入 deepseek 官方 API 的决策过程」）——同主题直测
- 对照：无 / 短 3.6k / 中 5.8k（同素材不同长度）
- 模型：deepseek-v4-flash @ Opencode Go Google
- 样本：3 档 × 3 臂 = 9 臂（首轮 3/9 + fetch failed 抖动，断点续跑补全 9/9）

## 初步发现（梯度存在，判卷需迭代）

1. **同化强度有梯度**（输出结构）：中（事故驱动+账本+根因+需求重述）> 短（背景+触发+需求）
   > 无（通用需求分析）——中组臂「翻账本确认」「事故驱动的方向修正」是范式包特有的
   「根因定位」模式，无组臂不会做。
2. **token 维度不适用**：token 受探索/执行行为主导（短组用了 write/browser/web_search），
   与范式包长度无关——**H5 判卷不用 token**（H1 的「省 token」结论也需复验，见下）。
3. **H1 vs H5 矛盾**：H1 有组 token 12-29k（省 3.6 倍），H5 短组 42-64k（反超无组）——
   同组同任务结果相反 → **H1 的「省 token」是采样噪音，不是稳定信号**（index.md
   实验方法论：单次跑可能是噪音，需重复测量定案）。H1 的「任务理解改变」（执行 vs
   决策复盘）在 H5 无组也出现（无组 r1 说「本次任务是决策与验证，不需要写代码」）
   ——该信号同样不稳。

## 设计教训（下一步迭代）

1. **任务判别力不足**：任务直接说「给出决策过程」→ 所有臂都叙述决策，范式差异被
   叙述基线淹没。改进：任务改成**不提示决策方法**的纯任务（如「评估接入官方 API 的
   方案并给出你的决定」），看 AI 是否**自发**用范式方法（查证/矩阵/纠偏）。
2. **判卷需结构评分**：关键词有无（查证/数据/复盘）三档全有，判别不出梯度；
   改为结构元素评分（0-3 分：事故驱动 / 账本引用 / 参数矩阵 / 纠偏承认）+ 盲判。
3. **重复测量不足**：3 臂/档 + 1 次异常臂 → 有效样本 2/档。提到 5-8 臂/档 + 取中位数。
4. **fetch failed 抖动**：实验期间服务端间歇失败（2 轮补跑）——batch-run 断点续跑
   兜底已生效，但提示实验窗口避开服务重启/并发高峰。

## 结论

长度梯度（3.6k vs 5.8k）有**结构同化梯度**的初步信号（中 > 短 > 无），但判卷与
任务设计需迭代后才能定案。8k/16k 档待素材库（另一个 agent 的 material-index）
扩充后补做。
