## 论文一句话主张与贡献清单

一句话:把 effect/coeffect 从编译期类型注解**提升为运行时机制**——可逆效果
(每个上下文变换带运行时追踪的逆元)+ 反应式 coeffect(上下文每次变化按规格
分类为 activating/deactivating/neutral 并驱动激活/卸载),统一进单一上下文类型
Γ∞,再给出一套动态组合演算,其元理论(恢复精确性、序、进展、汇合)把单组件
的时空可组合性抬升到整个系统。(PAGE 1, 6)

贡献清单(PAGE 6):① 形式化 revertible effects(局部时间可组合性);② 形式化
reactive coeffects(局部空间可组合性);③ 统一上下文 + 观察等价供给效果独立性
(范式成立);④ 动态组合演算 + 元理论(全局保证);⑤ Cordis 实现:核心库
(效果追踪 + coeffect 解析)+ 声明式 loader(配置调和 + HMR)。

## 增量认知逐条

### I-1 逆元是「按施加点见证的左逆」,且见证正确性是作者义务而非运行时性质

- 论文语义:effect function e(γ)=(δ,g) 只要求 **g(δ)=γ 在施加点成立**,g 在
  其余状态不受约束(Def 8,PAGE 12);Theo 15:累积器也被精确复原 **当且仅当**
  g∘f=id,否则只有 soundness 不变式 φ(γ)=γ0 保持(PAGE 14-15);Theo 16:
  **LIFO 逆序回滚不需要任何额外假设**——每个逆元恰好遇到自己应用产生的状态
  (PAGE 15)。实现侧明言:ctx.effect **不检查** witness,「逆元能复原其伴随的
  效果是组件作者的义务,不是运行时验证的性质」(PAGE 56)。
- Rust 含义:**印证**规格书逆序 unwind 决策——单插件内 LIFO 无条件安全,对应
  `Vec<Box<dyn FnOnce>>` 逆序跑即可。同时给规格书 §5 契约测试一个理论定位:
  基座无法验证 disposer 正确性,「忘回滚 → 测试红」的变异抽检就是唯一的执行
  点。规格书应把「disposer 正确性 = 插件作者义务 + 测试强制」写成明文条款。

### I-2 跨组件乱序回滚的精确条件:独立性 = 变换两两交换 + 互不扰动对方逆元

- 论文语义:Def 19 独立性两条(PAGE 16):① 一方的**一切**变换(正向映射与
  产出逆元都算)与另一方的一切变换交换;② 一方的变换不改变另一方在任意状态
  产出的逆元。Cor 21:两两独立 ⇒ 任意排列序回滚都回到 γ0(PAGE 17)。独立性
  不成立处,序必须由别的东西承载:组件内由累积器(LIFO),跨组件由声明的
  coeffect(提供先于满足)(PAGE 17 末)。
- Rust 含义:把笔记 §4「逆序回滚」与 §9.5「卸载拓扑序」精确化:**同插件内
  LIFO 无条件;跨插件任意序仅在独立时安全**。NA 落地规则:每个服务的操作若
  可交换(见 I-4),其消费者卸载序自由;不可交换的服务(如有序链)必须通过
  inject 依赖把序声明出来。这是规格书§4.3 应补的「卸载序安全条件」条款。

### I-3 coeffect 上下文是带前置条件的依赖偏函数;同一键禁止二次提供

- 论文语义:Σ=(k:K)⇀V_k 依赖偏函数;set(k,v) 前置条件 **k∉dom(σ)**(不能
  重复提供),撤销要求 k∈dom(σ),违前置 = 错误且无转移(Def 22-23,PAGE 18);
  组件 = (d,p,e) 三元组,p 是**可提供的键集**,O-Insert 前置条件强制各 fiber
  的 provision 两两不交 ⇒ 每键至多一个可能的提供者(单一来源纪律,PAGE 28-31)。
- Rust 含义:规格书 v0 没说两个插件提供同名服务怎么办。按论文:registry 应
  **拒绝**第二次 provide(返回错误/debug panic),而不是覆盖。服务多实现要走
  §6.2 的 broker 模式(见 I-12),不是同名覆盖。

### I-4 键的三元结构 (V_k, ≃_k, A_k) 与「交换键」判定:注册表式接口可交换,有序链不可

- 论文语义:每个键不只是值类型,而是(值类型,观察等价,操作集)三元组
  (Def 24,PAGE 18-19)。Def 39:键可交换 ⇔ 其任意两操作独立;Theo 40:不同键
  上的操作恒独立;Theo 42:所有共享键可交换 ⇒ 任意两组件的效果函数独立 ⇒
  Cor 21 任意序回滚成立(PAGE 25-26)。论文亲自举例:**值是「条目可独立增删的
  表」的键可交换**(注册路由/事件监听是代表);**值是有序链的键不可交换**
  (middleware 插在前在后语义不同,任一序不可在不扰动另一方的情况下撤回)
  (PAGE 25)。
- Rust 含义:这是给 NA 服务作者的设计准则:**把服务接口设计成注册表式**
  (增删条目、按 id 寻址),卸载序就自由;**waterfall/中间件式有序链是论文点名
  的不可交换键**——规格书事件五派发里的 waterfall 恰好是此类,其监听器顺序
  构成语义,卸载/重载时必须靠依赖声明保序,或接受位置语义并在文档钉死。
  呼应规格书「派发模式即公开契约」:有序链服务的**顺序也是公开契约**。

### I-5 观察等价:恢复只保证「无观察者能区分」,不保证逐比特复原;它使交换性可达

- 论文语义:恢复等式全部按 ≃ 读:堆布局、生成式名字不恢复(Def 33 引言,
  PAGE 23)。σ≃σ′ ⇔ 定义域相同且逐键值 ≃_k 相关;**没有键绑定的状态部分被遗忘**
  (PAGE 23)。Lemma 35:≈_A(操作不可区分性)是操作所尊重的最粗等价,任何
  可采纳的 ≃_k ⊆ ≈_A(PAGE 24)。按 ≃ 读交换性才「可达」——两操作留下 ≃ 等同
  的值即算交换(PAGE 25)。分配器例:句柄不被任何操作比较 ⇒ 按重命名等价,
  可交换;地址可作为结果被比较 ⇒ 不可交换(PAGE 25)。
- Rust 含义:规格书 §5 契约测试的卸载判据应表述为**观察等价**:「卸载后经由
  ctx 服务/事件可观察的行为与加载前不可区分」,而非内存/句柄逐比特相等。
  实操:回滚测试断言「服务表/监听表内容相等(按值比较)」,不断言句柄 id 复用。

### I-6 isolate/intercept 是派生实现(derived realization):不写共享表,恢复 = 丢弃子上下文

- 论文语义:Def 27 效果有两种实现:原地(改上下文 + 非平凡逆元)与派生
  (产出新上下文,逆元 = 恒等,恢复 = 丢弃)(PAGE 20)。isolate/intercept 直接
  取派生实现:**共享表不变,无逆元可追踪**(PAGE 21)。Σiso=(ρ:K⇀R)×(σ:R⇀V_r)
  两层解析,dom(ρ) 外的键解析到自身realm(PAGE 21)。intercept:每键元数据是
  幺半群,get 时求值 σ(k)(d(k) ⊕ ι(k)),**右偏——上下文携带的 ι 覆盖组件声明
  的 d**,让外层上下文能在不改组件的情况下约束其 coeffect 使用方式(PAGE 22)。
- Rust 含义:**印证**规格书 isolate 作用域决策,并修正一个精度:作用域是
  **按服务键的 realm 表**(K⇀R),不是整个 ctx 一刀切;NA「每终端会话一个
  子 ctx」是粗粒特例,够用。intercept 的论文形象是**读时元数据 + 提供者函数**,
  不是笔记 §5 的「激活时祖先链合并」一个侧面——它还能做访问控制(I-13)。
  规格书可显式把 intercept 列为 v1+ 候选(见「不采用」节)。

### I-7 统一上下文 Γ∞ = μΓ.Γ×(Γ→Γ)×Σ:Σ 吸纳一切跨组件共享态,这是纪律而非构造性质

- 论文语义:Γ∞ 递归自相似:每级上下文自带状态 + 本级累积器 + coeffect 表;
  **「Σ subsumes all shared mutable states, not just inter-component dependencies」
  ——任何需跨组件共享的状态都应编码为某键上的依赖**;组件与环境的一切交互
  经过这一个实体(PAGE 22-23)。Theo 42 的适用前提同样在此:系统无法 reify 为
  coeffect 的位置在定理边界之外(PAGE 26-27)。
- Rust 含义:规格书应加一条宪法级纪律:**插件间共享可变状态必须挂在服务键
  后面,禁止全局 static/旁路通道**。这既保证卸载正确(一切效果可追踪),也是
  汇合定理(I-10)前提。Rust 里这条纪律可由「插件只能拿 &Ctx,不暴露全局
  可变单例」的 API 形状天然支持。

### I-8 编排规则三分:O-Insert/O-Retire/O-Remove;retire 与 remove 分离,remove 丢累积器即泄漏

- 论文语义:orchestrator 从不直接设生命周期态,只有插入与退休两个外部输入;
  O-Retire 无条件(是请求),O-Remove 要求 θ=Inactive 且无子 fiber——**退休中的
  Active fiber 必须先卸载,提前 remove 会丢弃累积器 = 泄漏**(PAGE 31)。注册
  原语(Def 47):组件激活中可注册子组件,其逆元是 O-Retire 而非 O-Remove
  (逆元必须处处可应用,而 O-Remove 有前置条件);祖父级由逐层级联到达
  (PAGE 31-32)。限制(Def 48):效果只能写自己的表 + 读自己声明的键对应的
  提供者表,**不得读未声明 fiber 的控制字段**(PAGE 32)。
- Rust 含义:NA 基座 API 形态:「禁用插件」= 置 retire 标志(幂等、立即返回),
  实际移除由生命周期循环在 Inactive 后完成;**两个阶段分开**。编译期插件下
  remove 可即「配置项失效 + fiber 句柄销毁」,但 retire-then-remove 的语义顺序
  要保留:先停供、排空、回滚,再丢句柄。

### I-9 生命周期四态 + 十条规则的精确转换语义:迭代边界才可转向,失败不重试,惯性链接

- 论文语义:Θ = Inactive(ζ)|Reloading(i,g,ω)|Active(g,ω)|Unloading(g,ω,ζ)
  (Def 49,PAGE 33)。L-Iter/L-Finish 只在 target=ω 时推进;**L-Divert 只能落在
  迭代边界**(Maybe 继续子 = 具现的界定继续体,对应 generator 的 yield,
  PAGE 35-36);异步惯性:已发射的迭代必须落地,落地后发现 target 已变 → 转入
  Unloading 而非经 Active(避免向将死者激活依赖)(PAGE 37);L-Raise:失败先
  恢复已累积逆元再记错误,到达 Inactive(ξ);**L-Begin 以 Inactive(⊥) 为前提 ⇒
  失败 fiber 不会自动重试**——「对环境未变的状态重试一个已暴露不健全的效果
  函数」被明确拒绝;失败记在 fiber 上不传播给父级,兄弟照常跑(PAGE 37-38)。
- Rust 含义:① **印证**显式 async unload:tokio 下 in-flight 的 apply future 不能
  在半 await 处安全中止 → 同样只能落地后转向;**取消点 = 效果边界(两次
  注册/await 之间),不是任意 await**。② 规格书 v0 缺失败语义,须补:插件
  apply/disposer 失败 → 永久 Failed,不自动重试,需配置变更等显式编排动作;
  失败隔离到单插件。③ 论文脚注 2(PAGE 59)点名 Rust:futures 是惰性的,
  **生命周期转换必须 spawn 成任务**(fiber.inertia ≈ JoinHandle),不能内联
  await——这是基座事件循环的具体形状。

### I-10 元理论四条定理给出的可判定/可依赖性质(比笔记的「拓扑序回滚」强得多)

- 论文语义:Theo 61 恢复精确性:两两独立时,纤维累积器在交织状态下运行,
  撤掉的**恰是该纤维的贡献,不多不少**(按 ≈,PAGE 43-44);Cor 62 终结恢复:
  关闭的 episode 不留痕迹,**无论结局含失败**(PAGE 45);Theo 63 序:消费者
  episode 严格含于提供者 episode 内(b<b′ 且 u′<u),且**消费者在整个拆除期间
  读到的绑定值不变**——提供者停供先于其逆元运行,guard(¬relied)按绑定而非
  按纤维判(PAGE 34,45-46);Theo 64 解析相干:一次转换的每个迭代都对着同一
  个 committed 解析跑(PAGE 46);Theo 66 进展:**要求 ≺(依赖 precedence)
  无环** + 迭代长度有界 ⇒ 无死锁且终止,S(n)≤(K+4)(V(n)+1)(PAGE 47-48);
  Theo 73 汇合:同一批编排输入下,**任何调度到达的 quiescent 态 = 静态组装态**
  (唯一正规形,可差一个重命名);失败是真分歧源,但只影响该纤维自己的
  生命周期态(PAGE 52-53)。
- Rust 含义:① **汇合定理是规格书 §8「行序无加载语义」的形式许可证**——配置
  调和可以任意序增量应用,结果与从头加载相同;NA 的「配置级启停」因此安全。
  ② 进展定理的**无环前提是笔记没有的**:规格书须补「依赖图必须无环;环 =
  双方永久 Inactive(非死锁),可在声明期静态检测并报错」(§6.5,PAGE 71)。
  编译期插件下这甚至是 build 期可检的。③ 终止界提示防重载风暴:target 反复
  翻转才让步数爆炸,基座可对单位时间内的重载次数设熔断(非必需,记录即可)。

### I-11 ctx.effect 是唯一变异原语;dispose 必须幂等(至多触发一次)

- 论文语义:Cordis 里**一切**上下文变异(coeffect 提供、组件实例化……)都归约
  到一次 ctx.effect 调用(PAGE 56)。armed 标志 + 自处置:dispose 触发两次 =
  「在没有应用产生的状态上跑逆元,无任何东西约束它复原什么」——必须至多一次
  (PAGE 56)。dispose 前插到父上下文的累积器上(子效果的逆元本身是父的效果,
  即 ∂²Γ 递归结构)(PAGE 56-57)。
- Rust 含义:① 基座不变式:Ctx 上一切可变操作内部都必须走注册-追踪路径,
  API 设计上**不暴露**未追踪的变异入口。② dispose 幂等:Rust 的 FnOnce 类型
  级保证单次调用,但「显式 async unload」与「Drop 兜底」两条路径可能竞争 →
  内部用 `AtomicBool`/`Mutex<Option<Disposer>>` take 一次。这是规格书 §4.3
  「显式 unload + drop 兜底」必须补的实现注记。③ 子插件效果的逆元自动挂进父
  插件的 disposer 栈 → Drop 树形级联,与 Rust 所有权树同构。

### I-12 目标视图按提供者身份(uid)比较:原地覆写自己的绑定不被观察;替换 = 先撤再装

- 论文语义:fiber.target 是 target view 的摘要 = 各声明键的**提供者 uid 元组**;
  uid 新鲜不重用 ⇒ 换实现必被察觉,等值不算;**「提供者原地覆写自己的绑定不
  被观察;想让替换传播,就撤回旧绑定再装新绑定」**(PAGE 60)。notify 只认
  同 realm 的依赖者(guard 的运行时形态);排空等待放在整个恢复之前而非某个
  逆元内部(PAGE 60)。
- Rust 含义:印证笔记 §7 epoch 设计,并补一条服务语义钉:**服务值对依赖者
  是「绑定级」不可变的**;可变状态应封装在服务接口内部(内部可变性),而不是
  重新 provide 同名服务(那等于换实现,会触发依赖者重载)。NA 的
  `Arc<dyn Service>` 语义恰好如此:换 Arc = 换实现 = 重载依赖者;服务内部
  `Mutex` 状态变更 = 不触发。这条要写进规格书服务语义。

### I-13 访问即能力 + 代理在执行点强制规格;论文点名 Rust 的正解是 trait impl + 过程宏

- 论文语义:proxy 沿 fiber 链上行:committed 命中 → 返回;声明了但未提交 →
  INACTIVE_ACCESS;到根未声明 → UNDECLARED_ACCESS;裸 ctx.get 从不失败,
  proxy 在使用点强制 d(PAGE 61)。§6.3:inject 声明 = 能力请求,**静态可知**,
  编排者可在加载时审查;interception 元数据 = 细粒度策略,运行时调整不触发
  重载(PAGE 69)。§6.4:**「Typeclasses (Haskell) and traits (Rust) 让提供者
  从自己模块用 impl 扩展上下文类型」;「compile-time metaprogramming(e.g.,
  Rust procedural macros)为每个依赖发射类型化声明 + 访问器,dispensing with
  a general-purpose interception primitive」**(PAGE 70-71)。§7.3 还点名:
  「Linear types, RAII, and Rust's ownership system 把资源释放绑在词法区域……
  Cordis 把词法资源管理视为**互补**,适用于单组件内的局部资源」(PAGE 77)。
- Rust 含义:**强化印证**规格书 §4.2 的分层 ctx 决策,且给出更激进的选项:
  用过程宏把 `inject` 声明展开成类型化访问器,**编译期**强制「只能访问已声明
  依赖」(§5.1.4 说该检查原则上可编译期做,PAGE 61)。registry downcast 路径
  保留给插件间服务,但错误分两种:DeclaredButInactive vs Undeclared。RAII 的
  定位被论文钦定:**组件内局部资源用 Drop,跨生命周期的上下文效果用累积器**
  ——规格书「Drop 兜底」的语义边界由此划清。

### I-14 loader 调和:逐字段最小扰动分派;intercept 永不重载;config 变更由组件自决

- 论文语义:条目 = {id, url, isolate, intercept, config, disabled}(Def 74,PAGE 62);
  条目之所以是 fiber 的忠实规格,因为支撑集只读 τ,π,d,p(Lemma 70)。调和按
  字段分派:id/url → 重建;isolate → realm 重指派(Algorithm 7,delimiter 标签法);
  **intercept → 原地更新,无需重载**(读时咨询);**config → 交给组件,组件 diff
  后仅在实质变化时重载**;group 的 config = 子条目列表 → 按 id 键控 diff 递归;
  disabled → 卸载/重载。模块可并发加载,无加载序需安排(Theo 63)
  (PAGE 62-63)。托管 realm:isolate:true = 按条目 id 打标签的本地 realm(随条目
  移动);字符串 = 同名条目共享的全局 realm(PAGE 63)。
- Rust 含义:规格书 v0 的「配置级启停」被细化:**配置变更 ≠ 一律重启插件**;
  应区分 ①启停(disabled 位)→ 卸载/激活;②参数(config)→ 投递给插件
  (`on_config_change`),插件自行 diff 决定局部应用还是自我重载;③(将来)
  读时元数据 → 永不重载。NA 编译期插件下无 url 字段,条目 = {id, config,
  disabled}。印证笔记 §8「行序无加载语义」,并由汇合定理(I-10)形式背书。

### I-15 HMR 三阶段与事务式重载;「状态存活」要放进更长寿命的依赖

- 论文语义:HMR 三阶段:模块分类不动点(一个 import 被接受则接受;全部
  import 被拒则拒;**环上悬而未决者默认拒**)、陈旧条目检测(依赖树 ∩ accepted
  ≠ ∅ 即陈旧,以 declined 为边界)、**事务式重载**(失效缓存并备份,dispose 旧
  fiber + 重新 import 装新 fiber;任一失败则恢复缓存并全部从备份重建——
  系统永不处于半重载态)(PAGE 64-66)。无需开发者标注 accept 边界(对比
  Webpack/Vite)。§7.3 自陈代价:**组件自身内存态不在重载后存活,除非放进
  更长寿命的依赖**(PAGE 76-77)。
- Rust 含义:NA 编译期插件不采用运行时 HMR(见「不采用」),但两条思想
  移植:① **事务式配置变更**:一次配置调和涉及多插件时,失败要能整体回退到
  旧配置(备份-换入-失败回滚的形状);② **状态存活规则钉进规格书**:需要
  跨启停/重载存活的状态(会话、连接、缓存)必须注册为长寿命内核服务,插件
  自身状态视为可随时蒸发。这对「连接 provider 插件」设计直接相关。

### I-16 系统边界:获取(可追踪)与发射(不可追踪)的两分;发射只能暂缓或补偿

- 论文语义:位置在边界内 ⇔ 系统能独占修改且能复原;边界外的操作相当于 id_Γ,
  不被追踪。越界操作两阶段:**获取**(open/malloc/fork 安装边界内记录 = 可逆
  效果)与**发射**(write/send 把数据推出边界 = 不可恢复)。要恢复发射只有
  暂缓(output commit)或补偿(应用自定义的更粗等价,LIFO 组合律仍成立但
  元理论不转移)(PAGE 67-68)。
- Rust 含义:规格书 §5 契约测试的断言范围由此划界:**回滚测试只能断言「获取」
  类效果**(注册的服务/监听器/句柄全 unwind);「发射」类效果(写到终端的字节、
  已发出的网络包、Android IPC)不在回滚承诺内。规格书 §4.1 的承诺边界应把
  acquisition/emission 两分写进去——这比现在「注册效果全 unwind」更精确。
  终端渲染输出、按键注入都是发射。

### I-17 依赖环 = 永久 Inactive(非死锁),声明期可判;环的化解 = 拆出集成组件

- 论文语义:A 要 B 的键、B 要 A 的键 ⇒ 两者满足谓词永假,**永久 Inactive**;
  与并发死锁不同,这**从声明即可预测,加载时即可报告**(PAGE 71)。化解范式:
  双向交互拆成两个 core + 每方向一个集成组件(server-core / access-control-core /
  request-mediation / policy-management 四组件例);最坏集成组件数 O(n²),但组件
  轻量、正确性不受影响,代价是开发者体验(打包/约定式接线/脚手架缓解)
  (PAGE 71)。
- Rust 含义:规格书补「环处理」条款:基座启动时(或 build 脚本)对声明依赖图
  做拓扑检测,环 → 明确报错而非静默双挂起。设计评审时遇到疑似互依,用论文
  的四组件拆法裁决(例如「AI 会话插件 ↔ 工具卡插件」若互依,拆 core + 集成)。

### I-18 服务复用两形态:独占绑定扰动全部消费者;broker 吸收扰动(连接 provider 设计直接相关)

- 论文语义:单接口多实现:① 独占绑定——切换实现 = 卸旧装新,**每个消费者
  的依赖短暂扰动(全部重载)**;② 服务 broker——中央服务作接口入口,提供者
  与消费者都 inject broker,**换后端提供者消费者无感**;broker 支撑负载均衡、
  滚动更新(新提供者 ACTIVE 后渐进切流、旧者排空请求后卸载)、跨进程调用
  (接口须按异步契约设计)(PAGE 68-69)。
- Rust 含义:直接指导规格书阶段 2「连接 provider」:若要求「切连接后端(russh
  ↔ kfmv4 适配器)不惊动终端/会话等消费者」,则需一个 `connection-manager`
  broker 服务;若接受消费者重载,独占绑定即可。v0 可先独占(简单),规格书
  注明 broker 是已知的升级路径。跨进程调用必须 async 契约,与 kfmv4 协议
  适配器设计一致。

### I-19 笔记与论文的口径校平(不算增量,但防止误读)

- 笔记 §4 的「六态」是 cordis 实现态;论文形式态只有四个(Table 2,PAGE 55:
  LOADING=Reloading,FAILED=Inactive(ξ);DISPOSED=条目移除/遗迹条目
  Lemma 57;PENDING=target≠⊥ 的 Inactive(⊥),非独立形式态)。两者一致,
  引用时注意语境。
- 笔记 §5 的「intercept 配置合并(祖先链 base 优先)」是 service 层实现细节;
  论文层 intercept 是读时元数据幺半群、**右偏(外层上下文优先)**(PAGE 22)。
  两者不矛盾(不同键各自的 ⊕ 语义),但规格书若引 intercept 应以论文语义为准。

## 与规格书 v0 的冲突点或需修订点清单

1. **§3 插件域清单残留「事件四派发」**(规格书 line 51)——笔记与论文均已证
   五派发,纯笔误,改。
2. **§4.3 缺失败语义条款**:补「apply/disposer 失败 → 永久 Failed,不自动重试,
   失败隔离单插件」(I-9,PAGE 37-38)。
3. **§4.3 卸载协议应写成三相**:①停供(标记 Unloading,键从注册表可见性
   撤出,依赖者重算为不满足)②await 依赖者排空(按绑定判定)③LIFO 跑
   disposers;并注明 dispose 幂等(armed/take-once),取消点=效果边界
   (I-9/I-10/I-11,PAGE 34,56,60)。
4. **缺单一来源纪律**:同名服务二次 provide = 错误,拒绝注册(I-3,PAGE 18,31)。
5. **缺依赖环条款**:环=永久 Inactive,启动/build 期检测并报错(I-10/I-17,
   PAGE 47,71)。
6. **缺共享态纪律**:跨插件共享可变状态必须挂服务键,禁止旁路全局态(I-7,
   PAGE 23,26-27)。
7. **§4.1 承诺边界细化**:回滚承诺只覆盖「获取」类效果;「发射」类效果
   (终端输出、网络发送、IPC)不在承诺内(I-16,PAGE 67-68)。
8. **§5 契约测试判据改为观察等价**:卸载后按 ctx 可观察行为不可区分,不要求
   句柄/id 逐比特复原(I-5,PAGE 23-25)。
9. **配置语义分层**:disabled=启停;config 变更投递给插件自决 diff;不要一律
   等同重启(I-14,PAGE 62-63)。
10. **§4.2 可强化(可选)**:过程宏展开 inject 声明为类型化访问器,编译期强制
    「只访问已声明依赖」;registry 路径错误分 DeclaredButInactive/Undeclared 两种
    (I-13,PAGE 61,70-71)。
11. **连接 provider 设计注记**:独占绑定(消费者随切换重载)vs broker(消费者
    无感)是显式权衡,v0 取独占,注明升级路径(I-18,PAGE 68-69)。
12. **状态存活规则**:插件自身状态不跨启停存活;需存活者注册为长寿命服务
    (I-15,PAGE 76-77)。
