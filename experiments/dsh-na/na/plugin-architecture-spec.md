## 0. 命题

kfm-na 是完全 Rust 驱动的高性能安卓端软件。架构形态：**先立插件基座（dsh 式），
再往里填插件实现内容**。kfmv4 的「一切皆卡片」与 dsh 的「一切皆插件」在此统一：
卡片 = 插件，「一切皆卡片」=「一切皆插件」。

**否决**：kfmv4 服务端转发瘦客户端方案（SSH 隧道回环直连 8021 只读复用协议）——
影子无法接管主人，「NA 接管 kfm」终局愿景要求 NA 自含能力（会话/工具/AI/存储），
转发架构下这些全在 kfmv4 手里。

## 1. 背景事实

- dsh = DeepSeek Harness（`deepseek-ai/deepseek-harness`，开发者预览），由
  vendored 的 Cordis（`@deepseek-ai/cordis` 4.0.0-rc.7）驱动；设计论文
  《A Programming Paradigm for Spatiotemporal Composability》
- dsh 五机制：① plugin = `apply(ctx)` + `inject` 依赖声明；② ctx = 服务仓库，
  按 `ctx.<key>` 查找不 import 具体实现；③ 类型化事件**五派发**（emit 同步观察 /
  parallel 并发 / serial 顺序短路 / bail 同步短路 / waterfall 环绕委托），
  派发模式即公开契约（源码验证：vendor/cordis/src/events.ts）；④ 可逆效果
  （注册进 fiber 的 DisposableList，卸载逆序回滚，async 支持）；⑤ profile/bundle
  分层组合（patch 按行 id 寻址整行替换，last-write-wins）
- kfm-na 现状（2026-08-14）：尖刺 1 尾期，BAR-001~017 全闭环；BAR-017 判词
  「覆盖层 UI 统一 Rust 自绘」；下一步切片 = 快捷键行 → 左缘手势文件树 → 光球
  对话 → 眼睛/手 v2 + 工具卡。资产与「连谁」无关，重构只涉 protocol/session/conn

## 4. 三个关键机制（Rust 落地题眼）

### 4.1 热插拔语义（先钉死定义）

dsh 的热插拔是 Node 进程内模块装卸；NA 是安卓单进程 Rust。现实选项：

- **编译期插件**（特性开关 + 注册表 + 配置启停，重启生效）——Rust 主流、安全、
  崩溃隔离天然。**核心插件的默认形态。**
- **运行时 dlopen**（.so 动态装载）——NDK 可行但符号/ABI/崩溃隔离全是工程。
  **仅远期候选**（如浏览器壳）。

规格书承诺边界：「热插拔」= 配置级启停 + 可逆卸载回滚（注册效果在卸载时全部
unwind），**不是运行中换 .so**。承诺做不到的事是规格书第一宗罪。

### 4.2 ctx 类型化（Rust 版 Cordis 的题眼）

TS 靠 declaration merging 动态扩展 ctx key；Rust 没有对应物。候选：

- 类型化 `Ctx` struct（字段即服务，编译期全检查，新内核服务要改内核）
- `AnyMap` 动态注册（灵活，运行时 unwrap）

**分层决策**：内核服务用类型化 struct（`ctx.term`/`ctx.events`/`ctx.config`），
插件服务用 registry + trait downcast（`ctx.registry.get::<T>()`）——兼得安全与
扩展。此为真设计点，不是抄作业。

### 4.3 插件形态

```
trait Plugin {
  fn name(&self) -> &str;                       // 插件身份（= dsh 行 id）
  fn apply(&self, ctx: &mut Ctx) -> Result<()>; // 安装（注册服务/监听/效果）
}
```

- 依赖声明：`inject` → `fn deps(&self) -> &[ServiceId]`，基座按依赖图激活
- 可逆效果：apply 内注册的每个效果返回 disposer，卸载时**逆序 unwind**
  （DisposableList 语义，最新注册先回滚——cordis utils.ts:27-30）。
  **Rust 移植真设计点**：Drop 不能 await，卸载接口定为显式
  `async fn unload()`（逆序跑 disposers）+ drop 兜底路径
- 事件五派发：emit = 同步 for / parallel = futures join_all /
  serial + bail = 顺序循环 + Result 短路 / waterfall = 委托链
  （continuation 参数，不调即否决）。每个事件在事件枚举上标注派发模式
- 作用域：isolate 标签（cordis context.ts:18-19）——终端会话/对话会话可各持
  独立服务作用域，服务查找按标签解析；NA 首个用途 = 每终端会话一个 ctx

## 5. 测试标准（回答「插上后确保不出 bug」）

NA 已有考题先行三档（A 纯逻辑考题先行+变异抽检 / B 胶水冒烟钉 / C 感官实拍），
插件架构升级为四层：

| 层 | 内容 | 档位 |
|----|------|------|
| 契约测试 | 每插件必测：注册成功 / 卸载回滚（注册的效果全 unwind）/ 事件派发顺序 | A（变异抽检咬人：忘回滚 → 测试红） |
| 互操作测试 | 组合矩阵：多插件同挂的边界，按 inject 依赖图生成 | A |
| 回归钉 | BAR 编号照旧，钉在插件契约层 | A |
| 实拍判卷 | 感官/平台（渲染手感/IME/生命周期），飞鸽传书证据链 | C |
