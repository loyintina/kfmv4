## 0. 命题

kfm-na 是完全 Rust 驱动的高性能安卓端软件。架构形态：**先立插件基座（dsh 式），
再往里填插件实现内容**。kfmv4 的「一切皆卡片」与 dsh 的「一切皆插件」在此统一：
卡片 = 插件，「一切皆卡片」=「一切皆插件」。

**否决**：kfmv4 服务端转发瘦客户端方案（SSH 隧道回环直连 8021 只读复用协议）——
影子无法接管主人，「NA 接管 kfm」终局愿景要求 NA 自含能力（会话/工具/AI/存储），
转发架构下这些全在 kfmv4 手里。

## 1. 背景事实

- dsh = DeepSeek Harness（`deepseek-ai/deepseek-harness`，开发者预览），由
  vendored 的 Cordis（`@deepseek-ai/cordis` 4.0.0-rc.7）驱动；设计论文
  《A Programming Paradigm for Spatiotemporal Composability》
- dsh 五机制：① plugin = `apply(ctx)` + `inject` 依赖声明；② ctx = 服务仓库，
  按 `ctx.<key>` 查找不 import 具体实现；③ 类型化事件**五派发**（emit 同步观察 /
  parallel 并发 / serial 顺序短路 / bail 同步短路 / waterfall 环绕委托），
  派发模式即公开契约（源码验证：vendor/cordis/src/events.ts）；④ 可逆效果
  （注册进 fiber 的 DisposableList，卸载逆序回滚，async 支持）；⑤ profile/bundle
  分层组合（patch 按行 id 寻址整行替换，last-write-wins）
- kfm-na 现状（2026-08-14）：尖刺 1 尾期，BAR-001~017 全闭环；BAR-017 判词
  「覆盖层 UI 统一 Rust 自绘」；下一步切片 = 快捷键行 → 左缘手势文件树 → 光球
  对话 → 眼睛/手 v2 + 工具卡。资产与「连谁」无关，重构只涉 protocol/session/conn

## 4. 关键机制（Rust 落地题眼）

### 4.1 热插拔语义（先钉死定义）

dsh 的热插拔是 Node 进程内模块装卸；NA 是安卓单进程 Rust。现实选项：

- **编译期插件**（特性开关 + 注册表 + 配置启停，重启生效）——Rust 主流、安全、
  崩溃隔离天然。**核心插件的默认形态。**
- **运行时 dlopen**（.so 动态装载）——NDK 可行但符号/ABI/崩溃隔离全是工程。
  **仅远期候选**（如浏览器壳）。

规格书承诺边界：「热插拔」= 配置级启停 + 可逆卸载回滚（注册效果在卸载时全部
unwind），**不是运行中换 .so**。承诺做不到的事是规格书第一宗罪。

- **承诺边界细化：获取/发射两分**（修订 7，I-16，PAGE 67-68）：回滚承诺只覆盖
  「获取」类效果——注册的服务/监听器/句柄，系统能独占修改且能复原；「发射」类
  效果——写进终端的字节、已发出的网络包、Android IPC——不可恢复，**不在承诺内**，
  只能暂缓（output commit）或补偿（应用自定义更粗等价）。终端渲染输出、按键注入
  都是发射。`<契约测试>`（回滚断言范围只含获取类）+`<文档>`
- **配置语义分层**（修订 9，I-14，PAGE 62-63）：配置变更 ≠ 一律重启。
  ① `disabled` 位 = 启停 → 卸载/激活；② `config` 参数变更 = 投递给插件
  （`on_config_change`——v1 不可达：改配置重启生效，投递语义标注 v1+ 启用），
  插件自行 diff，仅实质变化才自我重载；③（v1+ 候选）
  读时元数据 intercept → 原地更新、永不重载。NA 编译期插件无 url 字段，条目 =
  `{id, config, disabled}`。汇合定理（Theo 73）背书：配置任意序增量调和 =
  从头加载，「配置级启停」因此安全。`<契约测试>`（启停/投递行为可测）+`<文档>`
- **配置延迟解析**（cordis 源码验证，笔记 §7.5，fiber.ts:740）：插件 config
  可以引用注入的服务——**config 求值延迟到依赖就绪之后**，未激活的插件
  不解析配置。`<契约测试>`（Pending 插件 config 不求值）
- **状态存活规则**（修订 12，I-15，PAGE 76-77）：**插件自身状态不跨启停/重载
  存活**，视为可随时蒸发；需存活者（会话、连接、缓存）必须注册为长寿命内核
  服务。配套移植「事务式配置变更」（PAGE 64-66）：一次调和涉及多插件时，失败
  整体回退旧配置，系统不处于半重载态。`<文档>`（设计页模板「状态存活」字段
  强制声明，§8）+`<契约测试>`

### 4.2 ctx 类型化（Rust 版 Cordis 的题眼）

TS 靠 declaration merging 动态扩展 ctx key；Rust 没有对应物。候选：

- 类型化 `Ctx` struct（字段即服务，编译期全检查，新内核服务要改内核）
- `AnyMap` 动态注册（灵活，运行时 unwrap）

**分层决策**：内核服务用类型化 struct（`ctx.term`/`ctx.events`/`ctx.config`），
插件服务用 registry + trait downcast（`ctx.registry.get::<T>()`）——兼得安全与
扩展。此为真设计点，不是抄作业。

- **单一来源纪律**（修订 4，I-3，PAGE 18, 31）：同名服务二次 provide = **错误**，
  registry 拒绝注册（返回错误 / debug panic），绝不覆盖——论文 set 前置条件
  k∉dom(σ)，违前置 = 错误且无转移。一个服务要多实现，走 broker 模式（见 §3
  表下注），不是同名覆盖。内核 struct 字段编译期天然唯一。
  `<编译期>`（内核服务字段）+`<契约测试>`（registry 重复 provide 用例）
- **编译期 inject（方向性强化，v1 定调）**（修订 10，I-13，PAGE 61, 70-71）：
  论文点名 Rust 正解 = trait impl + 过程宏：`inject` 声明由过程宏展开为类型化
  访问器，**编译期**强制「只能访问已声明依赖」。宏落地是实施期任务，不阻塞
  v1；即刻生效的是 registry 路径错误两分：`DeclaredButInactive`（已声明未
  激活）vs `Undeclared`（未声明）。`<编译期>`（宏）+`<契约测试>`（错误两分）

### 4.3 插件形态

```
trait Plugin {
  fn name(&self) -> &str;                       // 插件身份（= dsh 行 id）
  fn apply(&self, ctx: &mut Ctx) -> Result<()>; // 安装（注册服务/监听/效果）
}
```

- 依赖声明：`inject` → `fn deps(&self) -> &[ServiceId]`，基座按依赖图激活。
  **激活语义（cordis 源码验证，笔记 §7）**：依赖未齐 = 合法挂起态（PENDING），
  不是错误；服务上线/下线/换实现 → 依赖者自动激活/卸载/重载（epoch 拓扑签名
  比较，fiber.ts:611-639）；依赖者卸载时提供者先撤（拓扑序，reflect.ts:297-303）
- **依赖环条款**（修订 5，I-10/I-17，PAGE 47, 71）：环 = 双方**永久 Inactive**
  （非死锁）——满足谓词永假，从声明即可预测。基座启动时（build 脚本）对声明
  依赖图做拓扑检测，环 → **明确报错**，不允许静默双挂起。设计评审遇疑似互依，
  用论文拆法裁决：双向交互拆成两个 core + 每方向一个集成组件（组件轻量，
  正确性不受影响，代价是开发者体验）。`<编译期>`（build 期拓扑检测）+
  `<契约测试>`（环用例断言报错而非挂起）
- 可逆效果：apply 内注册的每个效果返回 disposer，卸载时**逆序 unwind**
  （DisposableList 语义，最新注册先回滚——cordis utils.ts:27-30）。
  **执行形态（v1.1 裁决，信箱 2026-08-15 评审裁决 1/2）**：v1 **全同步**——
  disposer = `Box<dyn FnOnce() + Send>`，`fn unload()`（无 async）；v1 效果
  全是注册表式「获取」类，无需要 await 的操作，BoxFuture 是无需求的接口；
  同步化后「取消点 = 效果边界」自动满足（apply 无半 await 状态）。接口层
  预留 async 契约扩展（BoxFuture disposer / async unload）位置，真出现
  「卸载必须等」的效果时才启用，届时复用 conn.rs 的
  「独立线程 + current_thread runtime」模式，**不手搓 executor**。
  **disposer 正确性 = 插件作者义务 + 测试强制**（I-1，PAGE 56）：逆元是
  「按施加点见证的左逆」，基座无法运行时验证 witness，「忘回滚 → 测试红」
  的变异抽检就是唯一执行点（见 §5）
- **瞬时返回契约**（v1.1 新增，信箱评审裁决的上下文修正）：同步基座下
  生命周期转换跑在事件循环上，**apply/unload 必须瞬时返回**——慢活
  （连网、IO、等锁）插件自己开线程，disposer 只「发停止信号 + 丢句柄」，
  不「等它死」。网络关闭帧等发射类动作不在回滚承诺内（§4.1），发出去
  即可，无需等对端确认。`<契约测试>`（假插件 apply 阻塞 → 报警用例）
- **卸载协议（三相）**（修订 3，I-9/I-10/I-11，PAGE 34, 56, 60）：
  1. **停供**：标记 Unloading，服务键从注册表可见性撤出，依赖者重算为不满足
     而先行卸载——提供者停供先于其逆元运行，消费者在整个拆除期间读到的绑定值
     不变（Theo 63，guard 按绑定而非按纤维判）。
  2. **await 依赖者排空**：等所有依赖者卸载落地；排空等待放在整个恢复**之前**，
     不在某个逆元内部。
  3. **LIFO disposers**：逆序跑累积器。同插件内 LIFO **无条件安全**（Theo 16：
     每个逆元恰好遇到自己应用产生的状态，不需额外假设）；跨插件任意序仅当操作
     两两独立（注册表式接口可交换，I-2/I-4）——不可交换的有序链（waterfall/
     中间件式）必须靠 inject 依赖把序声明出来，**有序链的顺序也是公开契约**。

  **dispose 幂等（take-once）**：dispose 触发两次 = 在没有应用产生的状态上跑
  逆元，无任何东西约束它复原什么（PAGE 56）——必须至多一次。`FnOnce` 类型级
  保单次，但「显式 async unload」与「Drop 兜底」两条路径可能竞争 → 内部用
  `Mutex<Option<Disposer>>` / `AtomicBool` take 一次。子插件效果的逆元自动挂进
  父插件的 disposer 栈 → Drop 树形级联，与 Rust 所有权树同构。`<契约测试>`
- 事件五派发：emit = 同步 for / parallel = futures join_all /
  serial + bail = 顺序循环 + Result 短路 / waterfall = 委托链
  （continuation 参数，不调即否决）。每个事件在事件枚举上标注派发模式。
  **v1 实现面（信箱评审裁决 3）**：同步基座下 serial（异步顺序）与
  bail（同步短路）合并为**一个同步顺序短路派发**；waterfall 保留（同步
  委托链可行，且是有序链顺序语义的判卷点）；parallel 缓建（同步基座下
  不可达，有真实并发需求再加）
- 作用域：isolate 标签（cordis context.ts:18-19）——终端会话/对话会话可各持
  独立服务作用域，服务查找按标签解析；NA 首个用途 = 每终端会话一个 ctx。
  论文精度修正（I-6，PAGE 20-22）：作用域是**按服务键的 realm 表**（K⇀R），
  派生实现——不写共享表、无逆元可追踪、恢复 = 丢弃子上下文；「每会话一个
  子 ctx」是粗粒特例，够用。**notify 的 isolate 过滤**（笔记 §7.7，
  reflect.ts:314-336）：服务变更广播只到达同作用域的 fiber——会话 A 的
  服务上下线不惊动会话 B。`<契约测试>`（跨作用域不通知用例）

### 4.4 失败语义（新增，修订 2，I-9，PAGE 37-38, 59）

- **永久 Failed，不自动重试**：apply/disposer 失败 → 先恢复已累积的逆元
  （已注册效果全部回滚）再记错误，fiber 落在 Inactive(ξ)。L-Begin 以
  Inactive(⊥) 为前提 ⇒ 失败 fiber 不会自动重试——「对环境未变的状态重试一个
  已暴露不健全的效果函数」被论文明确拒绝。恢复只能靠配置变更等显式编排动作。
- **单插件隔离**：失败记在 fiber 上，不传播给父级，兄弟照常跑。
- **取消点 = 效果边界**（v1.1 同步化后自动满足）：v1 全同步 ⇒ apply 无半
  await 状态，取消/转向天然只落在效果边界。（原语义备查：异步形态下
  in-flight apply 不能半 await 中止，转换须 spawn 成任务——v1+ 启用
  async 契约时恢复此要求，复用 conn.rs 线程模式，不手搓 executor。）
- **状态清单措辞**（v1.1 裁决 5）：形式态五个 = Inactive(Clean)/Loading/
  Active/Unloading/Inactive(Failed)；**PENDING 不是独立态**，是
  Inactive(Clean) 下 target≠⊥ 的条件态；**v1 无 DISPOSED 态**——编译期
  插件无运行时移除（disabled = 启动不装载、改配置重启生效），显式留白
  防与 cordis 六态表对账时误读。

`<契约测试>`（基座行为测试：构造失败插件，断言 Failed 终态 / 不自动重试 /
兄弟不受影响 / 取消只落效果边界）

### 4.5 共享态纪律（新增，修订 6，I-7/I-12，PAGE 22-23, 26-27, 60）

- **宪法级纪律**：插件间一切共享可变状态**必须挂在服务键后面**（编码为某键上的
  依赖），禁止全局 static / 旁路通道——论文明言「Σ subsumes all shared mutable
  states, not just inter-component dependencies」。这是卸载正确性（一切效果可
  追踪）与汇合定理的前提，是纪律而非构造性质。
- **绑定级不可变**：服务值对依赖者是「绑定级」不可变——可变状态封装在服务接口
  内部（内部可变性）；重新 provide 同名服务 = 换实现 = 触发依赖者重载（且被
  单一来源纪律拒绝）。`Arc<dyn Service>` 语义恰好如此：换 Arc = 换实现 = 重载
  依赖者；服务内部 `Mutex` 状态变更 = 不触发。
- **落地形状**：插件只拿 `&Ctx`，基座不暴露全局可变单例入口（API 形状天然

## 8. 插件设计页模板

每插件立项时填一页。字段（—— 后是「写什么」）：

- **身份** —— 插件名（= dsh 行 id）、所在域与优先级（§3）、一句话职责。
- **提供（服务键）** —— 本插件 provide 的服务键清单；逐键标注接口形态：注册表式
  （可交换，卸载序自由）还是有序链（不可交换，顺序 = 公开契约，§4.3）。
- **依赖（inject）** —— 声明的依赖键清单；与「提供」交叉检查无环（§4.3 依赖环
  条款）。
- **生命周期语义（apply/unload/失败）** —— apply 注册哪些效果；unload 三相各自
  做什么（§4.3）；哪些步骤可能失败、失败后的可见行为（§4.4 永久 Failed）。
- **配置 schema** —— 条目 `{id, config, disabled}` 中 config 的字段表；每字段
  标注变更语义：局部应用还是自我重载（§4.1 配置语义分层）。
- **事件（派发模式）** —— 本插件发射/监听的事件清单，逐事件标注五派发中的哪
  一种（派发模式即公开契约）。
- **状态存活** —— 哪些状态允许随启停蒸发、哪些必须存活；存活者指向长寿命内核
  服务键（§4.1 状态存活规则）。
- **契约测试清单** —— §5 契约测试的具体用例：注册成功 / 卸载回滚（观察等价）/
  事件派发顺序，逐条列断言。
- **实拍判卷点** —— C 档实拍的感官判定点（渲染手感 / IME / 生命周期）及飞鸽
  传书证据链位置。

## 10. 执行层分工

条款后的 `<...>` 标注 = 该纪律由哪一层强制。分层优先级原则（2026-08-15 用户
拍板）：

1. **能编译期强制的不靠测试**——类型、宏、所有权能挡住的错误，不留给运行时
   测试兜底。
2. **能测试强制的不靠钩子**——行为对错的判定进契约测试，不靠仓库钩子扫描。
3. **能钩子强制的不靠文档**——形状/纪律类约束（如禁全局可变态）能静态扫描的，
   写成钩子，不停留在文字。
4. **文档只管为什么与裁决**——理由、权衡、待拍板项、升级路径；前三层能强制的，
   文档不复述为纪律。
