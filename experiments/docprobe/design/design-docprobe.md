# docprobe 线级设计：文档指引系统的功能粒度体检（2026-08-08）

> 预注册文档：假设、指标、判读规则在跑数前冻结。修订须记修订事件。

## 一、从冷启动到 docprobe：考什么

冷启动测「整体接手」——一份试卷一个开放报告，考入口文档的宏观引导。
docprobe 测「功能粒度可达」——一个具体问题，答案有对错，可写地面真相。
单臂成本低一个量级，可题库化、可矩阵化、可每波复测追趋势。

**它诊断的对象是文档指引系统，不是模型**——模型只是探头。
探头差异（模型/harness）本身作为变量 H4 记录，但主线结论关于文档。

## 二、题型五级（成本与深度递增）

| 级 | 题型 | 考什么 | 例 |
|---|------|--------|---|
| T1 | 名词探测 | 找不找得到功能存在 | 「守视是什么？」 |
| T2 | 定位探测 | 路由精度 | 「守视的代码在哪？」 |
| T3 | 评价探测 | 理解深度（需读代码+契约形成判断） | 「kfmv4 有一个守视，你觉得它如何？」 |
| T4 | 排障探测 | 工作流路由（会不会去 bugs.md/ledger） | 「守视好像不工作了，可能什么原因？」 |
| T5 | 任务探测 | 全流程合规（迷你冷启动） | 「给守视加个截图压缩功能」 |

首波用 T3（评价探测）为主——它强制 agent 走完「找到→读懂→形成判断」全链，
是单题信息量最大的题型；T1/T2 的答案被 T3 轨迹自然覆盖。

## 三、假设（预注册）

- **H1 新旧差异**：新功能的指引健康度（三维指标）系统性弱于老功能。
  判读：首波 5 题按功能年龄分组对比到达成本与可达率，方向一致且
  新旧组无重叠 → 成立。
- **H2 路由表有效性**：经 CLAUDE.md 路由表到达的臂，到达成本显著低于
  裸 grep 撞中的臂。判读：同题内按路径分桶比成本中位数。
- **H3 稀释病定量**：同一题目的到达成本随文档系统规模（文档数/行数）
  增长而上升。判读：每波同题复测，长期趋势（需 ≥3 波，本线慢变量）。
- **H4 探头差异**：模型/harness 影响路由行为（路径合规率），
  不影响主线结论的方向。判读：描述性记录，不做强裁决。

## 四、首波题库（5 题，新旧混考）

| 题 | 功能年龄 | 题型 | 选它的理由 |
|---|---------|------|-----------|

每题的地面真相（应达文档集/理解要点/期望路由）在 `truth/<topic>.md`，
判卷前刷新并记校准事件。

## 五、协议（逐字冻结项）

- 题目措辞逐字冻结在 truth 文件 `question` 字段——改措辞 = 新题。
- 环境钉版：每波记录主仓 commit 哈希 + 文档统计（文档数/总行数，供 H3）。
- 探头配置：只读白名单 `--tools read,grep,glob`（红线纪律：docprobe 永不放行
  bash/write）；角色卡统一 kfm-dev（避免人格变量）；无范式包。
- 重复测量：每题 × 每模型 ≥4 臂（模型随机性，单次是噪音）。
- 模型池：首波 3 模型跨强度档（弱/中/强各一），H4 用。

## 六、判卷（双轨）

1. **机械轨**（脚本）：轨迹解析——
   - 应达文档命中（可达率）：轨迹 read/grep 路径 ∩ 地面真相文档集
   - 路径合规（H2）：首次命中前是否读过 CLAUDE.md 且按路由表指向
   - 到达成本：首次命中前的工具调用数/token（session-runner 归档全量轨迹）
   可全自动，零判官偏差。
2. **盲判轨**（judge-llm，DS v4-flash 统一尺）：
   - 理解准确度 = 地面真相要点覆盖率（0-5）
   - 幻觉 = 断言对地面真相的违背数
   判卷输入只含题+回复，不含臂条件（盲判纪律同 paradigm）。

## 七、基建复用清单（撞墙再拆）

- session-runner.mjs（configId 解析/多轮/直写归档/只读白名单默认）
- exp-driver.mjs + specs/（矩阵×重复×自动判卷循环）
- arms.db（臂存储，occupancy 登记不适用本线——无范式包变量）
- audit-arms.py（轨迹统计）→ 需扩展「应达文档命中/路径合规」判定，
  新工具归 docprobe/tools/（本线首个自产工具时再立目录）

## 八、落成门远景（本线的终极形态）

新功能发版 → 针对该功能的抽测题自动入题库 → 全新 agent 找不到/理解错/
到达成本过高 → 功能不算完工，补文档。**抽测通过成为 definition-of-done
的一部分**——文档系统的自我修正回路（与错误码体系同构）。
